These prevent the most common failures.\n\n## 1. Bar charts: no duplicate categories\n\nFor bar charts without an aggregate, each (categorical_field, color_field) tuple must be unique. Duplicate categories cause stacked/overlapping bars that misrepresent the data. Avoid that, unless specifically requested by user.\n\n**Fix — aggregate transform** (preferred):\n```json\n{\n  \"transform\": [\n    {\"aggregate\": [{\"op\": \"sum\", \"field\": \"SALES\", \"as\": \"SALES\"}], \"groupby\": [\"REGION\", \"CATEGORY\"]}\n  ],\n  \"mark\": \"bar\",\n  \"encoding\": {\n    \"x\": {\"field\": \"SALES\", \"type\": \"quantitative\"},\n    \"y\": {\"field\": \"REGION\", \"type\": \"nominal\"},\n    \"color\": {\"field\": \"CATEGORY\", \"type\": \"nominal\"}\n  }\n}\n```\n\n**Fix — grouped bar chart** (when you want to show per-item bars side by side instead of stacking):\nUse `xOffset` (vertical bars) or `yOffset` (horizontal bars) to place bars next to each other. This is the **default** for multi-color bar charts.\n```json\n{\n  \"title\": \"Revenue by Region and Category\",\n  \"mark\": \"bar\",\n  \"encoding\": {\n    \"x\": {\"field\": \"SALES\", \"type\": \"quantitative\"},\n    \"y\": {\"field\": \"REGION\", \"type\": \"nominal\"},\n    \"yOffset\": {\"field\": \"CATEGORY\", \"type\": \"nominal\"},\n    \"color\": {\"field\": \"CATEGORY\", \"type\": \"nominal\", \"title\": \"Category\"}\n  }\n}\n```\n\n**Fix — stacked bar chart** (ONLY when the user explicitly asks for a \"stacked bar chart\"):\nAdd `\"stack\": \"zero\"` to the **quantitative** axis encoding and do NOT include `xOffset`/`yOffset`. Bar charts: custom x-axis domains cause bars extending off-screen\n\nBar marks always start from 0 on the quantitative axis. If you set a custom `scale.domain` that excludes 0 (e.g., `[0.95, 1.1]` for values near 1.0), bars will stretch from 0 (off-screen) to their value, appearing as extremely long bars extending to the left (horizontal) or bottom (vertical).\n\n**Fix — use `x2`/`y2` to anchor the bar baseline at the domain start:**\n```json\n{\n  \"mark\": \"bar\",\n  \"encoding\": {\n    \"x\": {\"field\": \"METRIC\", \"type\": \"quantitative\", \"scale\": {\"domain\": [0.95, 1.1]}},\n    \"x2\": {\"datum\": 0.95},\n    \"y\": {\"field\": \"CATEGORY\", \"type\": \"nominal\"}\n  }\n}\n```\n\n**Alternative — use tick or point marks** which don't have a baseline:\n```json\n{\n  \"mark\": {\"type\": \"tick\", \"thickness\": 3},\n  \"encoding\": {\n    \"x\": {\"field\": \"METRIC\", \"type\": \"quantitative\", \"scale\": {\"domain\": [0.95, 1.1]}},\n    \"y\": {\"field\": \"CATEGORY\", \"type\": \"nominal\"}\n  }\n}\n```\n\n**Rule**: Whenever you use a bar chart with a custom `scale.domain` that does not include 0, you MUST either set `x2`/`y2` to the domain start value, or use a non-bar mark type (tick, point, circle).\n\n## 4.
