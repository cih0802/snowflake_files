## 2. 단계별 작업 절차 (Step-by-Step)

### Step 1: Snowflake `SNAPSHOT` 스키마 생성 및 권한 설정
* **내용**: `GN_DW` 데이터베이스 내에 `SNAPSHOT` 스키마를 생성하고 dbt 및 분석 사용자 권한을 부여합니다.
* **실행 DDL**:
  ```sql
  CREATE SCHEMA IF NOT EXISTS GN_DW.SNAPSHOT
    COMMENT = 'dbt Snapshot 전용 이력 보존 스키마 (SCD Type 2 영구 보존 영역)';
  ```

### Step 2: dbt_project.yml 설정 및 소스 참조 구성
* **내용**: 
  * `10_dbt_pipeline/dbt_project.yml`에 `snapshot-paths: ["snapshots"]` 명시.
  * snapshots 전역 타겟 스키마(`+target_schema: SNAPSHOT`, `+target_database: GN_DW`) 구성.
  * `10_dbt_pipeline/models/silver/_sources.yml` 내 BRONZE 소스 정의(`bronze_crm.TM_CM_CMPGN_MNG` 등) 등록 상태 확인.

### Step 3: Tier 1 스냅샷 모델 5종 작성 (갱신율 50% 이상)
* **생성 대상 파일**:
  1. `10_dbt_pipeline/snapshots/snp_crm_tm_cm_brnd_mng.sql`
     * 대상: `{{ source('bronze_crm', 'tm_cm_brnd_mng') }}` · 고유키: `brnd_cd`
     * 전략: `check` (브랜드명·브랜드구분·사용여부)
  2. `10_dbt_pipeline/snapshots/snp_crm_tm_rm_bplc_mng.sql`
     * 대상: `{{ source('bronze_crm', 'tm_rm_bplc_mng') }}` · 고유키: `bplc_cd`
     * 전략: `check` (사업장명·국가·지역·사용여부)
  3. 🔴 `10_dbt_pipeline/snapshots/snp_crm_tm_cm_mber_dvlp_goal.sql`
     * 대상: `{{ source('bronze_crm', 'tm_cm_mber_dvlp_goal') }}`
     * 고유키: `dept_id || stdyy || stdr_mt || mber_dvlp_div_cd` 복합키 ⇒ **surrogate key 생성 필요**
     * 전략: `timestamp` (`updated_at='last_updt_dt'`)
     * ⚠️ 이 원천은 **단일 고유키 컬럼이 없다** — `dbt_utils.generate_surrogate_key` 로
       복합키를 만들어 `unique_key` 로 넘긴다(Step 3-A 선행 작업 참조).
  4. `10_dbt_pipeline/snapshots/snp_crm_tm_cm_cmpgn_mng.sql`
     * 대상: `{{ source('bronze_crm', 'tm_cm_cmpgn_mng') }}` · 고유키: `cmpgn_cd`
     * 전략: `timestamp` (`updated_at='last_updt_dt'`) — 실측 36,163건 전건 NOT NULL 확인 완료
  5. `10_dbt_pipeline/snapshots/snp_crm_tm_cm_dept_info.sql`
     * 대상: `{{ source('bronze_crm', 'tm_cm_dept_info') }}` · 고유키: `dept_id`
     * 전략: `check` (`dept_nm`, `upper_dept_id`, `acmslt_upper_dept_id`, `use_yn`, `stats_dept_lvl`)

### Step 3-A: 복합키 대상 선행 조치 (`TM_CM_MBER_DVLP_GOAL` 전용)
* **내용**:
  * `dbt snapshot` 은 `unique_key` 에 단일 값(또는 표현식)을 요구한다.
  * 개발목표 원천은 (부서 × 연도 × 월 × 개발구분) 4키 복합 그레인이므로 스냅샷 SELECT 절에서
    surrogate key 를 먼저 만든다:
    ```sql
    {{ dbt_utils.generate_surrogate_key(['dept_id', 'stdyy', 'stdr_mt', 'mber_dvlp_div_cd']) }} AS goal_sk
    ```
  * ⚠️ `packages.yml` 에 `dbt_utils` 가 없으면 `MD5(...)` 직접 조합으로 대체한다.
  * 🔴 **surrogate key 의 고유성을 먼저 실측 검증**한다(중복이 있으면 스냅샷이 잘못된 이력을 만든다):
    `SELECT COUNT(*), COUNT(DISTINCT dept_id||stdyy||stdr_mt||mber_dvlp_div_cd) FROM ...` 가 일치해야 한다.

### Step 4: dbt snapshot 초기 실행 및 적재 검증
* **내용**: 
  * 🔴 **실행 규칙 준수**: 세션 운영 규약에 따라 dbt 실행 명령은 에이전트가 명령문을 작성하여 제시하고, **사용자가 직접 실행**합니다.
    * 실행 명령: `dbt snapshot --project-dir 10_dbt_pipeline --select snp_crm_tm_cm_brnd_mng snp_crm_tm_rm_bplc_mng snp_crm_tm_cm_mber_dvlp_goal snp_crm_tm_cm_cmpgn_mng snp_crm_tm_cm_dept_info`
  * 생성된 `GN_DW.SNAPSHOT.SNP_*` 테이블의 행수 및 메타데이터 컬럼(`dbt_scd_id`, `dbt_updated_at`, `dbt_valid_from`, `dbt_valid_to`) 적재 상태 확인.

### Step 5: GOLD 마트 DDL 선행 변경 및 Point-in-Time 조인 배선
* **내용**:
  * 🔴 **GOLD DDL 보존 6단계 절차 엄격 준수**:
    1. `03_top-down_gold/06_DDL.sql` 내 `DIM_MEMBER_ACQUISITION` 테이블에 `ACQ_CAMPAIGN_NAME_AT_ACQ VARCHAR(300)` 신규 컬럼 DDL 및 주석 추가.
    2. Snowflake 물리 테이블에 `ALTER TABLE GN_DW.GOLD.DIM_MEMBER_ACQUISITION ADD COLUMN ACQ_CAMPAIGN_NAME_AT_ACQ VARCHAR(300) COMMENT '회원 획득 당시 캠페인명 (Snapshot 기반 시점 동결)';` 선행 실행.
    3. `INFORMATION_SCHEMA.COLUMNS`로 컬럼 추가 상태 확인.
    4. `10_dbt_pipeline/models/gold/dim/DIM_MEMBER_ACQUISITION.sql` 모델 로직 수정.
    5. dbt build 실행 (사용자 실행).
    6. 신규 컬럼 비-NULL 건수 및 데이터 정합성 검증.

  * 🛡️ **과거 회원 Cold Start 결손 방지 폴백(Fallback) 조인 로직 적용**:
    * **문제**: 오늘 생성된 스냅샷은 `dbt_valid_from = '2026-09-09'`이므로 단순 `BETWEEN` 조인 시 2021~2025년 가입자 150만 명이 전건 NULL이 됨.
    * **해결 로직**: 
      가입일자(`ACQ_DATE`) 기준 가장 적합한 스냅샷을 매칭하되, 스냅샷 최초 생성일 이전 가입자는 **최초 유효 스냅샷 레코드(`MIN(dbt_valid_from)`)로 폴백 매핑**하여 과거 회원 결손을 100% 방지.
      ```sql
      -- 안전한 Point-in-Time 매핑 CTE 예시
      WITH ranked_snp AS (
          SELECT
              cmpgn_cd,
              cmpgn_nm,
              dbt_valid_from,
              COALESCE(dbt_valid_to, '9999-12-31'::timestamp) AS dbt_valid_to,
              ROW_NUMBER() OVER (PARTITION BY cmpgn_cd ORDER BY dbt_valid_from ASC) AS rn_first
          FROM {{ ref('snp_crm_tm_cm_cmpgn_mng') }}
      )
      ...
      -- 조인 조건: 유효기간 내 매칭 OR 최초 스냅샷 레코드 폴백
      ```

### Step 6: Tier 2 스냅샷 모델 6종 배포 (갱신율 10~50%)
* **생성 대상 파일**:
  1. `snapshots/snp_crm_tm_ms_event.sql` (일반행사 마스터 · 47.6% · 고유키 `event_cd`)
  2. `snapshots/snp_crm_tm_ms_email_tmplat_mng.sql` (이메일 템플릿 · 37.2%)
  3. `snapshots/snp_crm_tm_ms_crmn.sql` (캠페인의전 마스터 · 26.7% · 고유키 `crmn_cd`)
  4. `snapshots/snp_crm_tc_cmmn_cd.sql` (공통코드 그룹 · 12.7% · 고유키 `cd_id`)
  5. `snapshots/snp_crm_tm_cm_spnsr_bsns_info.sql` (후원사업 마스터 · 12.0% · 고유키 `spnsr_bsns_id`)
  6. `snapshots/snp_crm_tc_cmmn_dtl_cd.sql` (공통코드 상세 · 11.9% · 복합키 `cd_id + dtl_cd_id`)
* ⚠️ 4·6 은 코드 체계 2종이며 **함께 배포**해야 라벨 디코딩 이력이 정합적으로 남는다.
* 🚫 **제외 확정 대상을 되살리지 말 것** — `TM_CM_MKTNG_CMPGN_MNG`(갱신 0.0%) ·
  `TM_CM_MKTNG_UTM`(0.0%) · `BDGT_ACMSLT_LEDGER`(연도키 버전 보존) · 대용량 트랜잭션 38종.
  근거 = `06_snapshot/01_스냅샷_아키텍처_및_네이밍룰.md` §3-3.

### Step 7: 스케줄링 및 운영 모니터링 가이드 수립
