# 03. 비용 제한: Per-user quota · Budget · RBAC

Cortex AI 비용을 통제하는 세 가지 계층을 정리한다.
서버리스 특성상 **Resource Monitor는 사용할 수 없다**는 점이 출발점이다.

> **개정 2026-08-12**: Per-user quota의 실제 API를 계정에서 실측해 전면 교체했다.
> 이전 판은 메서드명을 추정으로 기재해 **존재하지 않는 구문**을 담고 있었다(§5 정정표).
> 실행 가능한 구축 스크립트는 `05_AI비용가드_구축.sql` 이 정본이다.

## 계층 요약

| 계층 | 수단 | 성격 | 차단 여부 |
|------|------|------|-----------|
| 1. 사용자별 상한 | **Per-user quota** (Preview-Open) | 하드 | ⭕ 내장 Block (AI 도메인 한정) |
| 2. 그룹 예산 | Budget + Custom action | 준하드 | ⭕ 단, 저장 프로시저를 직접 작성해야 함 |
| 3. 접근 통제 | RBAC (역할/권한) | 하드 | ⭕ 사용 자체 차단 |

> Budget 단독은 **알림 전용**이다. 차단은 custom action으로 역할을 회수해야 성립한다.

## 1. Per-user quota — 사용자별 하드 차단 (권장)

`SNOWFLAKE.CORE.QUOTA` 클래스 인스턴스로 만드는 1급 객체다.
**Preview - Open** 상태로 모든 계정에서 사용할 수 있다.

### 1-1. 지원 도메인

| 도메인 | 대상 | Block |
|--------|------|-------|
| `AI FUNCTION` | AI_COMPLETE, AI_CLASSIFY 등 AI 함수 | ⭕ |
| `CORTEX CODE` | CoCo (CLI + Snowsight + Desktop 합산) | ⭕ |
| `SNOWFLAKE INTELLIGENCE` | CoWork | ⭕ |
| `CORTEX AGENT` | Cortex Agents | ⭕ |
| `WAREHOUSE` | 웨어하우스 컴퓨트 + QAS | ❌ 추적만 |

> ⚠️ **한 quota에 WAREHOUSE와 AI 도메인을 섞을 수 없다.** 측정단위가 다르다(credits vs AI credits).
> ⚠️ **Block은 AI 도메인 전용이다.** 웨어하우스 차단은 여전히 Resource Monitor의 몫이다.

### 1-2. 실제 메서드 (2026-08-12 계정 실측)

`GN_DW.INFORMATION_SCHEMA.CLASS_INSTANCE_PROCEDURES` 조회로 확인한 공개 메서드다.

| 목적 | 메서드 |
|------|--------|
| 도메인 등록/해제 | `ADD_SHARED_RESOURCE(DOMAIN [, TARGET])` · `REMOVE_SHARED_RESOURCE(...)` |
| **월 한도** | `SET_PER_USER_LIMIT(LIMIT FLOAT)` |
| **일 한도** | `SET_PER_USER_LIMIT(LIMIT FLOAT, 'DAILY')` |
| 한도 해제/조회 | `UNSET_PER_USER_LIMIT(CYCLE)` · `GET_PER_USER_LIMIT()` |
| **차단 활성화** | `SET_BLOCK_ENFORCEMENT_ENABLED(BOOLEAN [, SEND_EMAILS BOOLEAN])` |
| 태그 스코프 | `SET_USER_TAGS(TAG_PAIRS ARRAY, OPERATION_MODE VARCHAR)` |
| 사용자 제외 | `EXCLUDE_USERS(TARGET_TYPE VARCHAR, TARGETS ARRAY)` ⚠️ 아래 결함 참조 |
| 설정·스코프 확인 | `GET_CONFIG()` · `GET_QUOTA_SCOPE()` · `GET_USERS()` |
| 지출 조회 | `GET_SPENDING_DETAILS_BY_USERS(START, END)` · `GET_PER_USER_USAGE_PREVIEW(START, END)` |
| 차단 현황·이력 | `GET_ACTIVE_BLOCKS()` · `GET_ENFORCEMENT_HISTORY(START, END)` |
| 알림 | `SET_ADMIN_EMAILS(...)` · `ADD_NOTIFICATION_THRESHOLD(THRESHOLD, SPEND_STRATEGY, NOTIFY_USER [, CYCLE])` |
| 커스텀 액션 | `ADD_CUSTOM_ACTION(SPROC_REF, SPROC_ARGS, SPEND_STRATEGY, THRESHOLD)` · `GET_CUSTOM_ACTIONS()` |
| 사이클 시작 액션 | `SET_CYCLE_START_ACTION(SPROC_REF, SPROC_ARGS)` |
| 갱신 주기 | `SET_REFRESH_TIER(...)` · `GET_REFRESH_TIER()` (기본 `TIER_1H`) |

### 1-3. 최소 구축 순서

```sql
-- 1) 인스턴스 생성 (⚠️ only_compile 구문검증 미지원 — 실제 생성만 가능)
CREATE SNOWFLAKE.CORE.QUOTA GN_DW.OPS.AI_USER_QUOTA();

-- 2) 감시 도메인 등록
CALL GN_DW.OPS.AI_USER_QUOTA!ADD_SHARED_RESOURCE('AI FUNCTION');
CALL GN_DW.OPS.AI_USER_QUOTA!ADD_SHARED_RESOURCE('CORTEX CODE');
CALL GN_DW.OPS.AI_USER_QUOTA!ADD_SHARED_RESOURCE('SNOWFLAKE INTELLIGENCE');
CALL GN_DW.OPS.AI_USER_QUOTA!ADD_SHARED_RESOURCE('CORTEX AGENT');

-- 3) 한도 (⚠️ 설정 전까지 enforcement 는 전혀 발생하지 않는다)
CALL GN_DW.OPS.AI_USER_QUOTA!SET_PER_USER_LIMIT(100);          -- 월
CALL GN_DW.OPS.AI_USER_QUOTA!SET_PER_USER_LIMIT(10, 'DAILY');  -- 일(선택)

-- 4) 내장 차단 활성화
CALL GN_DW.OPS.AI_USER_QUOTA!SET_BLOCK_ENFORCEMENT_ENABLED(TRUE);

-- 5) 검증
CALL GN_DW.OPS.AI_USER_QUOTA!GET_CONFIG();
CALL GN_DW.OPS.AI_USER_QUOTA!GET_USERS();   -- 실제 적용 대상
```

`GET_CONFIG()` 반환 컬럼: `QUOTA_ID` · `PER_USER_LIMIT` · `REFRESH_TIER` · `ADMIN_EMAILS` ·
`ADMIN_LAST_SENT_AT` · `BLOCK_ENFORCEMENT_ENABLED` · `PER_USER_LIMIT_DAILY` ·
`PER_USER_BLOCK_NOTIFICATIONS_ENABLED`.
기본값은 한도 `NULL` · 차단 `FALSE` · `REFRESH_TIER = TIER_1H` · 사용자알림 `TRUE`.

### 1-4. 적용 대상 좁히기 (관리자 자기차단 방지)

quota의 **기본 스코프는 계정 전체 사용자**다. 그대로 한도를 걸면 관리자도 차단 대상이 된다.

> 🔴 **실측된 Preview 결함 (2026-08-12)**: `EXCLUDE_USERS('USER', ARRAY_CONSTRUCT('TRIALADMIN'))`이
> `INVALID_TARGET_TYPE`으로 실패한다. 오류 메시지가 허용값으로 `'USER'`를 안내하면서
> 정작 `'USER'`를 거부한다. 대소문자를 바꿔도 동일하다.
> ⇒ **태그 기반 스코프로 우회한다.**

```sql
-- 거버넌스 태그는 SECURITY 스키마에 둔다
CREATE TAG IF NOT EXISTS GN_DW.SECURITY.AI_COST_SCOPE
  ALLOWED_VALUES 'GOVERNED', 'EXEMPT';

-- GOVERNED 태그 보유자만 스코프에 포함
CALL GN_DW.OPS.AI_USER_QUOTA!SET_USER_TAGS(
  [[(SELECT SYSTEM$REFERENCE('TAG', 'GN_DW.SECURITY.AI_COST_SCOPE', 'SESSION', 'APPLYBUDGET')),
    'GOVERNED']],
  'UNION');

-- 한도 적용 대상 사용자에게만 부여. 관리자는 부여하지 않는다(= 제외)
ALTER USER analyst_kim SET TAG GN_DW.SECURITY.AI_COST_SCOPE = 'GOVERNED';
```

`OPERATION_MODE`는 `'UNION'`(태그 하나라도 일치) 또는 `'INTERSECTION'`(전부 일치)이다.
태그 해석은 평가 시점에 동적으로 이뤄지므로 태그를 바꾸면 재설정 없이 반영된다.

> ⚠️ **태그 스코프의 대가**: 태그를 부여하지 않은 사용자는 한도도 걸리지 않는다.
> 사용자를 추가할 때마다 `ALTER USER ... SET TAG`를 함께 수행해야 가드가 실제로 작동한다.
> SCIM의 `snowflakeTags` 속성으로 프로비저닝 시 자동 부여하는 것이 안전하다.

### 1-5. 한계 (공식문서 + 실측)

- **한도 미설정 시 enforcement 없음** — 객체만 만들어도 아무 일도 일어나지 않는다.
- **동일 quota 내 사용자별 차등 한도 불가.** 차등이 필요하면 quota를 여러 개 만든다.
- **전체 합산 한도 불가.** 각 사용자 한도가 독립 평가된다(합산은 Budget의 영역).
- **UTC 달력 월/일 고정.** 주간·커스텀 사이클 미지원. 회계월과 어긋난다.
- **초과(overshoot) 발생.** 차단은 요청시점 평가가 아니라 소비 후 수 분 내 평가다.
  100 크레딧 한도에서 100 도달 후 30을 더 쓰면 130에서 멈춘다.
  대용량 단일 AI 함수는 초과폭이 더 커질 수 있다.
- **사이클 경계 이중 소비.** UTC 자정 직전 사용자는 리셋 전 한도 + 리셋 후 한도를 연속 소비한다.
- **평가 지연.** 알림·커스텀액션은 약 6시간 주기 평가(계정 기본 `TIER_1H`)에 종속된다.
  Block만 별도 파이프라인으로 수 분 내 평가된다.
- 한도·스코프 변경은 즉시 반영되지 않는다.

## 2. Budget — 그룹 단위 예산 + 커스텀 액션

Per-user quota가 "개인별 상한"이라면 Budget은 "팀 합산 예산"이다.
`SNOWFLAKE.CORE.BUDGET` 인스턴스로 만든다.

### 2-1. 두 가지 형태

| 형태 | 스코프 지정 | 용도 |
|------|-------------|------|
| Resource budget | **객체**에 태그 부여 (`SET_RESOURCE_TAGS`) | 계정 전체의 특정 AI 객체 지출 |
| Shared resource budget | **사용자**에 태그 부여 (`SET_USER_TAGS`) | 같은 객체를 쓰는 팀별 독립 예산 |

> Shared resource budget에서 태그는 **객체가 아니라 사용자에게** 붙는다. 이 점이 혼동 지점이다.

### 2-2. 팀 예산 + 100% 도달 시 역할 회수

```sql
USE SCHEMA GN_DW.OPS;
CREATE SNOWFLAKE.CORE.BUDGET team_ai_budget();
CALL team_ai_budget!SET_SPENDING_LIMIT(500);              -- 팀 합산 월 500 크레딧
CALL team_ai_budget!ADD_SHARED_RESOURCE('SNOWFLAKE INTELLIGENCE');

CALL team_ai_budget!SET_USER_TAGS(
  [[(SELECT SYSTEM$REFERENCE('TAG', 'GN_DW.SECURITY.AI_COST_SCOPE', 'SESSION', 'APPLYBUDGET')),
    'GOVERNED']],
  'UNION');
```

차단은 저장 프로시저를 직접 작성해야 한다. Budget 자체에는 내장 Block이 없다.

```sql
-- 프로시저를 SNOWFLAKE 애플리케이션이 호출할 수 있게 권한 부여 (필수)
GRANT USAGE ON DATABASE GN_DW TO APPLICATION SNOWFLAKE;
GRANT USAGE ON SCHEMA GN_DW.OPS TO APPLICATION SNOWFLAKE;
GRANT USAGE ON PROCEDURE GN_DW.OPS.sp_revoke_ai_access(STRING) TO APPLICATION SNOWFLAKE;

CALL team_ai_budget!ADD_CUSTOM_ACTION(
  SYSTEM$REFERENCE('PROCEDURE', 'GN_DW.OPS.sp_revoke_ai_access(string)'),
  ARRAY_CONSTRUCT('GN_AI_USER'),
  'ACTUAL',
  100);
```

- `SPEND_STRATEGY`: `'ACTUAL'`(실지출) | `'PROJECTED'`(월말 추정)
- 임계치는 100%를 넘겨 설정할 수 있다(예외 기간 대응). Cortex Agents는 최대 1000%, CoWork은 500%.
- 다음 사이클에 접근을 자동 복원하려면 `SET_CYCLE_START_ACTION`에 복원 프로시저를 건다.
- 예산 초과 후 반영까지 최대 8시간(low latency budget 활성 시 2시간).

> ⚠️ 역할 회수로 차단할 때는 **대상 사용자가 다른 역할 경로로 같은 AI 객체에 접근하지 못하는지**
> 반드시 확인해야 한다. 경로가 남아 있으면 회수해도 차단되지 않는다.

## 3. RBAC — 접근 자체를 제한 (최후 방어선)

quota는 "얼마나"를 막고 RBAC는 "누가"를 막는다.

```sql
-- 현재 개방 상태 점검
SHOW GRANTS OF DATABASE ROLE SNOWFLAKE.CORTEX_USER;

CREATE ROLE IF NOT EXISTS GN_AI_USER;
GRANT DATABASE ROLE SNOWFLAKE.CORTEX_USER TO ROLE GN_AI_USER;
GRANT ROLE GN_AI_USER TO USER analyst_kim;

-- (선택) 전체 개방을 닫고 전용 역할로만 허용
REVOKE DATABASE ROLE SNOWFLAKE.CORTEX_USER FROM ROLE PUBLIC;
```

- `SNOWFLAKE.CORTEX_USER`는 기본적으로 `PUBLIC`에 부여되어 있어 전 사용자가 LLM 함수를 쓸 수 있다.
- 회수는 조직 전체에 영향을 준다. 사전 공지와 영향도 검토 후 적용할 것.
- Cortex Analyst / Agent / CoWork은 별도의 접근·객체 권한 체계를 가진다. 각 기능 문서를 함께 확인한다.

## 4. 본 계정 구축 현황 (2026-08-12)

| 오브젝트 | 위치 | 상태 |
|----------|------|------|
| `AI_USER_QUOTA` | `GN_DW.OPS` | 생성 · 4개 AI 도메인 감시 |
| `AI_COST_SCOPE` (TAG) | `GN_DW.SECURITY` | 생성 · quota 스코프로 연결 |
| `V_AI_SPEND_BY_USER` | `GN_DW.OPS` | 생성 · 관찰 가능 |

설정값: 월 한도 `NULL` · 일 한도 `NULL` · 차단 `FALSE` · `GET_USERS()` 0행.
⇒ **현재는 순수 관찰 상태이며 어떤 사용자도 차단되지 않는다.**

배치 원칙: `OPS` = 운영/비용 객체(quota·뷰), `SECURITY` = 거버넌스 정책 객체(태그).
차단 전환 절차와 한도 옵션은 `05_AI비용가드_구축.sql` §5·§6 주석 참조.

## 5. 이전 판에서 정정된 오류

| 오류 (이전 판) | 정정 (실측) |
|----------------|-------------|
| `CALL my_budget!SET_SPENDING_LIMIT(500)`를 quota 한도로 기재 | quota는 **`SET_PER_USER_LIMIT(...)`**. `SET_SPENDING_LIMIT`은 Budget 전용 |
| `SET_DAILY_SPENDING_LIMIT(10)` | **존재하지 않음.** `SET_PER_USER_LIMIT(10, 'DAILY')` |
| `SET_BLOCK_ENFORCEMENT(TRUE)` | **존재하지 않음.** `SET_BLOCK_ENFORCEMENT_ENABLED(TRUE)` |
| Per-user quota = "Preview, 사용 가능 여부 확인 필요" | **Preview-Open, 전 계정 사용 가능** |
| "Budget으로 Cortex 하드 차단 불가, 알림 전용" | Budget + **custom action**으로 역할 회수 차단은 가능(프로시저 자작 필요) |
| `CREATE OR REPLACE SNOWFLAKE.CORE.BUDGET` | 클래스 인스턴스는 `CREATE SNOWFLAKE.CORE.BUDGET name()` |
| `SET_EMAIL_NOTIFICATIONS('["a@b.com"]')` (JSON 배열) | `SET_EMAIL_NOTIFICATIONS(integration_name, 'a@b.com, c@d.com')` |
| "Cortex를 커스텀 Budget 리소스로 지정하는 범위가 불확실" | `ADD_SHARED_RESOURCE`로 AI 도메인 직접 지정이 정식 지원됨 |
| `ALTER USER ... SET RESOURCE_MONITOR_CREDIT_QUOTA` | 존재하지 않는 구문 (이전 판에서 이미 정정됨, 유지) |
