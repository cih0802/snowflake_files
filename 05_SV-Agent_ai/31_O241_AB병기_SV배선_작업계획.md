## 2. B안 정의 (제안 · 🟠 착수 전 사용자 확인)

### 2-1. 공91 B = 발송 매칭 선물금(원)

- 정의 = 서비스 발송 후 D+1~D+5 안에 들어온 선물금 합(공88·90 과 같은 D5 축 · DEC-33).
- 현재 `FACT_MESSAGE_DISPATCH.GIFT_PART_AMT` 는 **0 하드코딩**(`FACT_MESSAGE_DISPATCH.sql:133`) ⇒ 쓸 수 없다.
- 처방 = D5 매칭 CTE 에서 금액을 함께 낸다.
  - `followup` CTE(`:39-54`) GIFT 분기에 `a.GFTMNEY as AMT` 추가(다른 분기는 `NULL`).
  - `d5` CTE(`:62-`) 에 `SUM(IFF(f.KIND = 'GIFT', f.AMT, 0)) as D5_GIFT_AMT`.
  - 출력 컬럼 `D5_GIFT_PART_AMT`(공지성 제목 제외 `gn_is_notice_title` 동일 적용 · `:141` 패턴).
- 🔴 **중복 귀속 위험**: 한 선물금이 5일 창 안의 여러 발송(회원 × 발송일 쌍)에 동시에 매칭된다.
  - 건수·회원 플래그는 기존에도 같은 성질이지만, **금액은 합산하면 부풀려진다.**
  - 선택지 ㉠ 쌍별 귀속 그대로 + metric COMMENT 에 「발송 간 중복 귀속 · 기간 합 금지」 명시
  - 선택지 ㉡ 선물금 1건을 **가장 가까운 직전 발송 1건**에만 귀속(QUALIFY ROW_NUMBER)
  - 🟢 추천 = ㉡(금액 지표는 가산이 기대된다). 사용자 확인 대상.

### 2-2. 공98 B = UA식 세션 지속시간(초)

- 정의 = 세션 마지막 이벤트 시각 − 첫 이벤트 시각(UA 「평균 세션 시간」 근사).
- SILVER `BIGQUERY_SESSION.sql:45` 에 `SESSION_START_TS`(min) 만 있다 ⇒ `SESSION_END_TS`(max) 추가.
- GOLD `FACT_BIGQUERY_SESSION.sql:32` 에 `s.SESSION_END_TS` 투영.
- 한계(COMMENT 에 쓴다): 단일 이벤트 세션 = 0초 · 자정을 넘는 세션은 일자별 2행.
- SV metric 은 중첩 집계가 안 되므로 **GOLD 에 세션 단위 `SESSION_DURATION_SEC` 를 미리 계산**한다.
  - 자정 분할 행은 첫 일자 행에만 값 · 나머지 0 → `SUM / COUNT(DISTINCT 세션키)`.
  - SV metric 이름 = `AVG_SESSION_DURATION_SEC`.
