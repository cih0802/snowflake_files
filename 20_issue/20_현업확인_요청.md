## M. 코드 라벨 확정 요청 (2026-08-11 O59-C · DEC-35 0단계 파생)

> 정본 = `20_issue/31_코드군_매핑등재부.md`. 아래 3건만 확인되면 **행사·발송 도메인의 코드가 전부 한글 라벨로 바뀝니다.**
> 🔴 **추측으로 채우지 않습니다** — 코드에 잘못된 라벨을 붙이면 Agent 가 **확신을 갖고 틀린 용어**로 답합니다(NULL 보다 나쁩니다).

### M-1. 일반행사 참여상태 라벨이 **영문 단계 표기**입니다 🟡

일반행사 참여상태(`PART_STATUS`)의 코드군을 찾았고 **12종이 정확히 일치**했습니다(`MS304`).
그런데 사전에 등록된 라벨이 **영문**입니다:

| 코드 | 사전 라벨 | 코드 | 사전 라벨 |
|---|---|---|---|
| 110 | Success | 120 | Fail |
| 130 | 1_step_right | 140 | 1_step_fail |
| 150 | 2_step_right | 160 | 2_step_fail |
| 170 | 3_step_right | 180 | 3_step_fail |
| 190 | 4_step_right | 200 | 4_step_fail |
| 210 | 5_step_right | 220 | 5_step_fail |

🔴 **두 가지가 확인되어야 합니다.**
① 이 표기가 뜻하는 것이 **다단계 이벤트(퀴즈·미션형)의 단계 통과 여부**로 맞습니까?
   맞다면 일반행사의 「참여」는 **캠페인행사의 「참여」와 정의가 다릅니다** — 캠페인행사는 `신청/참여/불참/대기/취소`입니다.
   ⇒ 두 계통을 **한 표에 합쳐 「참여자수」로 보고하면 정의가 섞입니다.**
② 현업 화면·보고서에서 쓰는 **한글 표기**가 있습니까? (예: `110`=성공 · `130`=1단계 통과 · `140`=1단계 실패)
   없다면 영문 그대로 노출하겠습니다(창작하지 않습니다).

**판정**: 🟡 **[2026-08-11 운영서버 대조] ①은 확인, ②는 여전히 대기.**
운영 `TC_CMMN_DTL_CD` 실측 = `MS304` 12종이 **영문 그대로**(`110 Success`~`220 5_step_fail`)이고 전건 `USE_YN='Y'` 다
⇒ 우리 적재분과 **완전 일치**(사전 stale 아님). 결정 4대로 **영문 그대로 노출**한다. **한글 표기만 회신 부탁드립니다.**
🔴 부수 확인: `MS304`의 `200` = `4_step_fail` 인데 `MS303`(참여경로)의 `200` = `homepage` 다 —
**같은 값이 축마다 다른 뜻**이므로 코드 단독 필터는 위험하다. 그래서 `PART_STATUS_GROUP` 판별축을 신설했다.

### M-6. 「발송상태2」가 원천의 어느 컬럼입니까? 🟡 (2026-08-11 O59-P 신규)

정본 `05_회원_보고서필드 인벤토리.md` **§3-1 [회원] 서비스효과성분석보고(알림톡/이메일)** 는
**「발송상태1」과 「발송상태2」를 둘 다** 요구합니다. 저희는 두 자리를 만들어 뒀는데
**발송상태2 는 지금 전건 비어 있습니다**(`FACT_SERVICE_EVENT.SEND_STATUS2` · 38,470,780행 전건 NULL).

🔴 **저희가 임의로 채우지 않은 이유**: 원천에서 「상태」로 읽힐 컬럼이 채널마다 **개수가 다릅니다.**

| 채널 | 원천 테이블 | 상태성 컬럼 |
|---|---|---|
| 알림톡·문자(MSG_AT) | `TD_MS_MSG_AT_SNDNG_DTLS` | `TRNSMS_STAT_CD`(전송상태) + `TRNSMS_FAILR_CD_ID`(전송실패코드) = **2개** |
| SND | `SND_MEMBER_LIST` | `SND_YN` + `CALL_STATUS`(통화상태) = **2개** |
| 이메일 | `TD_MS_EMAIL_SNDNG_DTLS` | `SNDNG_RST_CD` = **1개** |
| 우편(PSTMTR) | `TD_MS_PSTMTR_SNDNG_DTL` | **0개**(컬럼 자체가 없음) |

현재 배선: **발송상태1 = 축A**(`TRNSMS_STAT_CD` 계열 · 코드군 `MS282` = 대기·발송중·발송완료·에러·예약취소).
남은 후보는 **축B**(`TRNSMS_FAILR_CD_ID` / `CALL_STATUS` · 코드군 `MS056`~`MS059`)뿐입니다.

⚠️ 그런데 축B 의 사전 라벨은 **「상태」가 아니라 「실패 사유」**입니다
(`TIMEOUT` · `POWER OFF` · `음영지역` · `블랙리스트에 의한 차단` · `잘못된 전화번호` …).
그래서 **「발송상태2 = 축B」라고 단정할 수 없습니다** — 맞다면 이름만 다른 같은 것이고,
아니라면 저희가 못 찾은 제3의 컬럼이 있거나 이 필드는 보고서에서 폐기된 것입니다.

🔴 **여쭙는 것 (택1로 답해 주시면 됩니다)**
① **발송상태2 = 전송실패코드/통화상태**(축B)입니까? → 그렇다면 이미 적재돼 있고 **이름만 맞추면 끝**입니다
   (`SEND_RESULT_CD`·`SEND_RESULT_NAME` 이 그 값입니다).
② 다른 컬럼입니까? → **원천 테이블·컬럼명**을 알려 주십시오.
③ 보고서에서 **더 쓰지 않는 필드**입니까? → 컬럼을 제거하겠습니다.

⇒ 회신까지 컬럼은 **전건 NULL 로 유지**합니다. 값을 추정해 채우면 「비어 있음」이 「값이 있음」으로 위장돼
   보고서가 조용히 틀립니다(저희 규약 P18·P24-B).
