### O63-B. 🔴🔴 O62 판정 2건이 실측으로 뒤집혔다

**㉠ 「두 컬럼의 NULL 은 같은 그 1행이다」 → 틀렸다.**
`DIM_MEMBER_CURRENT` 실측: `MEMBER_STATUS_NAME` NULL 은 1행(`MEMBER_DK='0000001'` · 상태코드 자체 결손)이지만
`ENROLL_PATH_NAME` NULL 은 **4행**이고 나머지 3행은 **회원상태가 정상**(`MBER_STAT_CD='12'` 후원중단)이다.
⇒ 두 컬럼의 빈 값은 **다른 사건**이다. 이것이 `R2-7-2`(한 문장을 여러 컬럼에 복사하지 않는다)의 **실증**이며,
한 문장으로 적었다면 Agent 가 「가입경로가 비면 상태도 없다」로 답할 수 있었다.
🔴 `DIM_MEMBER`(SCD2 전 버전)에서도 같은 구조가 재현된다 — 규모는 인덱스 O63 행.

**㉡ 「라이브 COMMENT 길이가 파일 문안과 다르다」 → 오판이었다.**
파일은 SQL 리터럴이라 `''` 이 값에서는 `'` 한 글자다. 언이스케이프하면 O62 시점에도 파일↔라이브가 **일치**했다.
⇒ 상황은 **드리프트가 아니라 「양쪽이 같이 폐기 규약을 발행 중」** 이었고, 조치도 달라진다
(드리프트면 라이브만 덮으면 되지만 이 경우는 **파일이 정본이라 파일부터 고쳐야** 한다).

🆕 **P223: 파일과 라이브를 비교할 때는 「저장 표현」이 아니라 「값」으로 비교한다.**
SQL 리터럴의 `''`, YAML 의 인용·이스케이프, JSON 의 `\uXXXX` 는 **저장 표현**이다.
길이·문자열을 그대로 대면 **차이가 없는데 있다고** 보고되고(이번 사례), 반대로 있는 차이를 놓친다.
⇒ 대조는 ①언이스케이프 후 ②**해시**로 한다(이번 판정 = SHA256 8/8 일치. 길이 일치는 보조 근거일 뿐이다).
