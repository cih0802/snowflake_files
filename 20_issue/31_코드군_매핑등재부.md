# 31. 코드군 매핑 등재부 (DEC-35 0단계)

> **이 문서가 1·2단계의 유일한 입력이다.** 여기 등재되지 않은 축은 라벨을 만들지 않는다.
> 🔴 **착수 조건 = 「추론 매핑 0건」.** 모든 행은 근거 등급을 갖는다. 등급 **D(미확정)** 인 행은
> 라벨을 만들지 않고 **NULL 유지 + 현업 확인**으로 간다(DEC-17-B · 라벨 창작 금지).
> ⚠️ 실측 수치는 이슈원장 **§O59 · §O59-C** 에 있다(R2-6 — 이 문서는 매핑 사실만 담는다).

---

## 0. 근거 등급 정의

| 등급 | 의미 | 무엇으로 확정했나 |
|---|---|---|
| **A 원천교차** | 코드의 **업무 의미**가 원천 내부 정합으로 확정됨 | 같은 BRONZE 테이블의 **동반 컬럼**과 1:1 대응 또는 원천 집계 카운트와 대조(**P175**) |
| **B 도메인일치** | 사전 코드군이 **배타적으로** 특정됨 | 실측 도메인 = 사전 그룹 도메인 **정확 일치**(또는 경쟁 후보를 초과값으로 배제) + 의미 정합 |
| **C 정황** | 코드군이 **유력**하나 배타적이지 않음 | 포함관계 성립 + 컬럼명·라벨 의미 정합. **경쟁 후보가 남아 있다** |
| **D 미확정** | 코드군을 특정할 수 없음 | 도메인이 너무 작아 다수 그룹에 포함되고 의미 판별자도 없음 ⇒ **현업 확인** |

🔴 **A 와 B 는 다른 축이다.** A = 「값의 뜻」 · B = 「어느 코드군인가」. 둘을 혼동하면
*"의미는 확정, 코드군은 정황"* 인 상태를 「확정」으로 잘못 적는다(§O59 ①의 경고).

## 1. 발송 결과 — 축 A (채널 상태) · `GOLD.FACT_SERVICE_EVENT.SEND_STATUS`

계보: `SILVER.CRM_SEND_MEMBER` 가 4원천을 `UNION ALL` 하며 **한 컬럼에 3체계를 합쳤다**.
판별자 = `FSE.SEND_TYPE`(= `SEND_CHANNEL`) — **기존 컬럼이며 신설 불요**.

| 채널 | BRONZE 원천 컬럼 | 실측 도메인 | 코드군 | 라벨(예정) | 등급 |
|---|---|---|---|---|---|
| **EMAIL** | `TD_MS_EMAIL_SNDNG_DTLS.SNDNG_RST_CD`(발신결과코드) | `1`·`0` | 🟠 미특정 | 🔴 **라벨 없음**(O59-N 결정 3 — 사전 문자열 부재) | **A**(의미) / **D**(코드군) |
| **MSG_AT** | `TD_MS_MSG_AT_SNDNG_DTLS.TRNSMS_STAT_CD`(전송상태코드) | `2`·`3`·`4` | **`MS282`** | `2`=발송완료 · `3`=에러 · `4`=예약취소 | **A**(의미) / **C**(코드군) |
| **SND** | `SND_MEMBER_LIST.SND_YN`(**COMMENT="발송 성공 여부"**) | `Y`·`N` | — (Y/N 플래그) | 🔴 **라벨 없음**(O59-N 결정 3 — 사전에 Y/N 그룹이 없다) | **A** |
| **PSTMTR** | 🔴 **원천 컬럼 없음** | 전건 NULL | — | **라벨 없음** | 구조적 부재(P21) |

**A 근거**
- MSG_AT: 같은 테이블의 `TRNSMS_FAILR_CD_ID` 와 교차하면 `2` ⟺ 전달코드(`7000`·`6600`·`4100`) **전건 1:1 · 오차 0** · `3` ⟺ 오류코드 · `4` ⟺ **결과코드 자체 없음**(발송 시도 전).
- EMAIL: 원천 집계 `SILVER.CRM_SEND_RESULT`(← `TD_MS_EMAIL_LQY_SNDNG`)의 `SUCCES_CNT`/`FAILR_CNT` 와 대조해 `1`=성공·`0`=실패 확정.
- SND: BRONZE COMMENT 가 **원천 자기서술**로 성공 여부임을 명시. ⚠️ `SND_REQ_MST` 의 `SEND_CNT`·`FAILR_CNT` 는 전건 0 이라 카운트 교차는 불가.

🟢 **[2026-08-11 O59-O 운영서버 대조] 등급 C 3건(`MS282`·`MS303`·`MS004`)은 전부 확정됐다 — 등급 C → B 승격 ·
롤백 미발동.** 운영 `TC_CMMN_DTL_CD` 라벨이 우리 추정과 전건 일치했다(정본 = 원장 §O59-O ⑤ · 문서20 §M-3 닫음).
아래 「C 인 이유」 서술은 **확정 이전의 경위 기록**으로 남긴다.

⚠️ **MSG_AT 코드군이 C 인 이유**: `MS282`(0대기·1발송중·2발송완료·3에러·4예약취소)가 분포·의미와 정합하지만
`{2,3,4}` 는 다수 그룹의 부분집합이라 **배타 특정이 안 된다**. 의미는 A 로 확정됐으므로 라벨은 만들 수 있고,
**코드군 ID 표기만 현업 확인 대기**로 둔다.

🟠 **EMAIL 코드군 D**: `{0,1}` 은 도메인이 2개뿐이라 후보가 과다하다.
🔴 **[2026-08-11 O59-N 사용자 결정 = 라벨을 만들지 않는다]** 종전 이 줄은 *"라벨은 A 근거로 만들고 코드군은 비워 둔다"* 였다 —
**철회한다.** 코드군이 특정되지 않으면 `CRM_CODE` 에서 가져올 **라벨 문자열 자체가 없다.**
「성공/실패」는 사전 라벨이 아니라 **원천 교차로 얻은 우리 해석**이므로 넣으면 **라벨 창작**이다(DEC-17-B).
⇒ `EMAIL {0,1}` · `SND {Y,N}` 은 **`*_NAME`·`*_GROUP` 둘 다 NULL** 로 두고 현업 확인(§M-4)한다.
라벨 정보가 들어오면 **조인으로** 채운다. 정본 = 문서30 **§23-J 결정 3**.

📌 **처방(DEC-35 §23-G)**: `SEND_STATUS`(raw 유지) + `SEND_STATUS_GROUP`(조인키) + `SEND_STATUS_NAME`(라벨).

## 3. 행사 참여 — `GOLD.FACT_EVENT_PARTICIPATION`

계보: `SILVER.CRM_EVENT_PARTICIPATION` = `TD_MS_EVENT_PRTCPNT_DTL`(일반행사) ∪ `TD_MS_CRMN_PRTCPNT`(캠페인행사).
판별자 = `DIM_EVENT.EVENT_KIND`(`EVENT`/`CRMN`) → 라벨축 `EVENT_KIND_NAME`.
🟢 **두 원천의 코드체계가 완전 분리된다**(겹침 0) — 판별자로 갈라 각자 코드군에 조인할 수 있다.

### 3-1. `PART_STATUS` (참여 상태)

| 원천 | 원천 컬럼 | 실측 도메인 | 코드군 | 등급 |
|---|---|---|---|---|
| **EVENT**(일반행사) | `PARTCPT_STAT_CD` | `110`·`120`·`130`·`140`·`150`·`160`·`170`·`180`·`190`·`200`·`210`·`220` (12종) | **`MS304`** = `110`Success·`120`Fail·`130`1_step_right·`140`1_step_fail·`150`2_step_right·`160`2_step_fail·`170`3_step_right·`180`3_step_fail·`190`4_step_right·`200`4_step_fail·`210`5_step_right·`220`5_step_fail | **B** — **12/12 정확 일치** |
| **CRMN**(캠페인행사) | `PARTCPT_STAT_CD` | `1`~`6` | **`MS006`** = `1`신청·`2`참여·`3`불참·`4`대기·`5`취소·`6`대기(결제) | **A + B** |

**A 근거(CRMN)** — 동반 컬럼 `RCPMNY_AMT`(수납액) 교차가 `MS006` 을 **배타 확정**한다:
`6`(대기(결제))은 금액 보유율 **94%·평균액 최고** · `4`(대기)는 금액 보유 **거의 0** · `2`(참여)·`5`(취소)는 금액 실재.
⇒ 경쟁 후보(`MS028` 수신거부·`MS004` 홈페이지·`CM013` 성별 등 40여 그룹)에는 **결제 개념이 없다.**

🔴 **업무 의미가 종전 이해와 다르다** — EVENT 계열의 참여상태는 「신청/참여/불참」이 아니라
**다단계 이벤트의 단계 통과 여부**(`n_step_right`/`n_step_fail`)다. 두 원천은 **참여의 정의가 다르다.**
⚠️ `MS304` 라벨이 **영문**이라 현업 용어가 아니다 ⇒ 한글 표기는 현업 확인(문서20).

### 3-2. `PART_PATH` (참여/신청 경로)

| 원천 | 원천 컬럼 | 실측 도메인 | 코드군 | 등급 |
|---|---|---|---|---|
| EVENT | `PARTCPT_PATH_CD` | `100`·`200`·`300`·`500`·`600`·`700` (6종 · `400` 미출현) | **`MS303`** = `100`webmail·`200`homepage·`300`출석·`400`포토·`500`텍스트·`600`독자의견·`700`독자이벤트 | **C** |
| CRMN | **`RQST_PATH_CD`**(컬럼명이 다르다) | `1`~`6` | **`MS004`** = `1`홈페이지·`2`상담센터·`3`초대·`4`이메일·`5`모바일웹·`6`APP | **C** |

⚠️ **C 인 이유**: EVENT 도메인이 `MS303`·`MS302` **둘 다에 포함**된다. 배타 근거는 3-3 이 준다(아래).
CRMN `1`~`6` 은 `MS004`·`MS264` 등 다수에 포함되며 컬럼명(`RQST_PATH_CD`=신청경로)과 `MS004` 의 의미 정합이 유일한 근거다.

### 3-3. `PART_CHANNEL` (참여 채널) — **EVENT 전용**(CRMN 은 원천 컬럼 없음 → NULL)

| 원천 컬럼 | 실측 도메인 | 코드군 | 등급 |
|---|---|---|---|
| `PARTCPT_CHNNL_CD` | `100`·`200`·`300`·`400`·`500`·`600`·`700`·`800` (8종) | **`MS302`** = `100`PC·`200`mobile web·`300`APP·`400`회지(온라인)·`500`회지(오프라인)·`600`SNS·`700`문자·`800`행사 | **B** — **8/8 정확 일치** |

🟢 **이 축이 3-2 의 모호성을 줄인다** — `800` 을 가진 축은 `MS302` 뿐이므로 `PART_CHANNEL`→`MS302` 가 확정되고,
`PART_PATH` 에는 `MS303` 이 남는다. 의미도 정합한다(`CHNNL`=채널=기기/매체 · `PATH`=경로=참여형태).
⚠️ 다만 두 축이 같은 그룹을 쓸 가능성이 논리적으로 배제되지는 않아 3-2 는 **C 로 유지**한다.

## 5. 🟠 D(미확정) — 라벨을 만들지 않는다

| 축 | 실측 | 왜 미확정인가 | 처방 |
|---|---|---|---|
| **`DIM_SERVICE.SUBTYPE`** (원천 `CRM_SEND_REQUEST.SNDNG_TY_CD`) | 🔴 **채널별 다체계**(신규 발견) — EMAIL `0`·`1`·`2` / MSG_AT `0`·`1` / PSTMTR `1`·`2`·`3` / SND NULL | 채널별 도메인이 2~3종뿐이라 후보가 과다. 사전 후보 `MM020`(EA/BOX/SET/KG)·`MS282`(발송상태) 는 **의미 무관** | **NULL 유지** + 채널별 다체계 사실을 COMMENT 에 명시. 현업 확인(문서20) |
| `FSE.SEND_STATUS` **코드군 ID**(EMAIL) | `{0,1}` | 도메인 2종 → 배타 불가 | 라벨은 A 근거로 생성 · **코드군 컬럼은 NULL** |

🔴 **`SUBTYPE` 은 `SEND_STATUS` 와 **같은 구조적 결함**이다** — 채널별 다체계가 한 컬럼에 합쳐졌다.
O58-C 는 이를 「라벨 미배선」으로만 적었고 **채널별 체계 차이를 몰랐다**. ⇒ DEC-35 §23-G 처방을 이 축에도 적용한다.

## 7. 집계 — 1·2단계 착수 판정

| 항목 | 수 |
|---|---|
| 등재 축 | **10** (축A 4채널 · 축B 2 · 참여 3 · 행사구분 1 — 원천 분기 기준 14행) |
| 등급 **A**(의미 확정) | 5 |
| 등급 **B**(코드군 배타 확정) | 6 |
| 등급 **C**(정황) | 3 — `MS282`·`MS303`·`MS004` |
| 등급 **D**(미확정) | 2 — `SUBTYPE` · EMAIL 코드군 |
| 🔴 **추론 매핑** | **0** |

🟢 **착수 조건 충족** — 추론 매핑 0건. C 등급은 **라벨은 만들되 코드군 ID 를 「정황」으로 표기**하고,
D 등급은 **라벨을 만들지 않는다**.

⛔ **현업 확인 이관 4건**(문서20): ① `MS304` 영문 라벨의 한글 표기(§M-1) ② `SUBTYPE` 채널별 코드군(§M-2)
③ C 등급 3건의 코드군 ID 확정(§M-3) ④ 🆕 **`EMAIL {0,1}`·`SND {Y,N}` 의 라벨**(§M-4 · O59-N 결정 3 파생).

> 🔴 **[2026-08-11 O59-N] 1·2단계 실행 결정 반영** (정본 = 문서30 **§23-J**)
> · 범위 = **등재 축 전량 + 축B 신설**
> · **C 등급 3건은 `*_GROUP` 에 값을 채운다** — 단 **롤백 조건부**다: 문서20 §M-3 회신이 다르면
>   해당 `*_GROUP` 값과 라벨을 되돌린다(손댈 곳 = SILVER 조인 `CD_ID` 리터럴 · GOLD 적재 · COMMENT).
> · **D 등급 + Y/N 플래그는 라벨을 만들지 않는다**(`*_NAME`·`*_GROUP` 둘 다 NULL).
> · `MS304` 는 **사전 영문 라벨 그대로** 적재하고 COMMENT 에 한글화 대기를 명시한다.
> · 🟢 축B 는 `MS056`~`MS059` **코드값 중복 0**(실측)이라 **코드군을 조인 결과에서 얻는다** — 리터럴 지정이 아니다.
