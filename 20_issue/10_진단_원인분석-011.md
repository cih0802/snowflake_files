### 18-D. 🟢 GA 데이터검토 종결 — 가산성 전수 + 정본지표 대조

사용자 지시에 따라 **설계·산식은 손대지 않고 검토만** 했다. 조치는 COMMENT 가드로 한정했다(§18-F).

**① measure 가산성 전수 (분모 = SILVER.GA4_EVENT 538,565행 / 세션 77,172)**

| measure | 산식 | 원천 참값 | 팩트 SUM | 배수 | 판정 |
|---|---|---:|---:|---:|---|
| `EVENT_CNT` | `COUNT(*)` | 538,565 | 538,565 | **1.0000** | 🟢 가산 |
| `VISITS` | `COUNT_IF(session_start)` | 78,098 | 78,098 | **1.0000** | 🟢 가산 |
| `VIEW_CNT` | `COUNT_IF(page_view)` | 135,896 | 135,896 | **1.0000** | 🟢 가산 |
| `SESSION_CNT` | `COUNT(DISTINCT user‖session)` | 77,172 | 243,156 | **3.1508** | 🔴 비가산·표기없음 |
| `ENGAGED_SESSIONS` | `COUNT(DISTINCT …)` | 37,505 | 161,117 | **4.2959** | 🔴 비가산·표기없음 |
| `TOTAL_USERS`·`ACTIVE_USERS`·율·평균 | — | — | — | — | 🟢 이미 비가산 표기 있음 |

🟢 **전수 스캔의 음성 결과도 결론이다(P44)** — 가산 3종은 **정확히 1.0000** 이므로 *"GA measure 전반이 부풀려져 있다"* 는 우려는 실측으로 닫혔다. 결함은 `COUNT(DISTINCT)` 2종에 국한된다.

**② 🔴 `PAGE_PATH` 가 정본 #105 를 충족하지 않는다 (거짓 주석)**

- 산식은 `SPLIT_PART(PAGE_LOCATION,'?',1)` — **쿼리문자열을 버린다**. GOLD 실측 `?` 포함 행 **0건**.
- 그런데 COMMENT 는 2계층에서 *"페이지경로+쿼리 (#105)"* 라고 적혀 있었다. 정본 #105 의 지표명이 **「페이지경로+쿼리문자열」** 이므로 이름만으로 충족한 것처럼 보였다.
- 🔴 파급: **정본 #122 결연아동코드**는 정의가 *"「페이지 경로+쿼리 문자열」에서 `childnum=` 뒤 13자리"* 다 → **쿼리 제거가 정본 지표의 파생 원천을 파괴**했다.

**③ 🔴 `PAGE_LOCATION` 은 `MAX()` 대표값이다 (URL 전체 아님)**

| 대상 | SILVER distinct | GOLD distinct | 소실 |
|---|---:|---:|---:|
| `PAGE_LOCATION` | 75,474 | **8,408** | 67,066 (**88.9%**) |
| `childnum=` 값 (#122) | 594 | **352** | 242 (40.7%) |
| `memnum=` 값 (#111) | 1,589 | **680** | 909 (57.2%) |

⚠️ 따라서 URL 파생 지표를 배선할 때 **원천은 GOLD 팩트가 아니라 SILVER 여야 한다.**

**④ 🔴 `DIM_MEMBER_IDENTITY` 의 정본 지표 2종이 전건 NULL 이고 사유 주석이 틀렸다**

| 컬럼 | 정본 | 모델 주석(종전) | 실제 원천 |
|---|---|---|---|
| `CHILD_CODE` | #122 | *"결연(SPONSOR_RELATION) 대기"* | 🔴 거짓 — 정본 DDL(`06_DDL.sql:164`)은 *"URL 파싱"* 이라 적었고 원천은 `SILVER.GA4_EVENT.PAGE_LOCATION` 의 `childnum=` **6,827행·594종**으로 실재 |
| `MEMNUM` | #111 | (없음) | `PAGE_LOCATION` 의 `memnum=` **17,795행·1,589종** |

**⑤ 🟢 URL `memnum` 은 미사용 identity 원천이다 — 결선 여력 +77.1%**

`IDENTITY_MEMBER_XREF` 는 `GA4_IDENTITY.GA_MEMBER_ID`(= GA4 이벤트의 `user_id`) ↔ `CRM_MEMBER.MEMBER_DK` 만 쓴다. URL 의 `memnum` 은 **어디에서도 쓰이지 않는다.**

| 측정 (분모 = GA pseudo 68,423) | 값 |
|---|---:|
| 현재 매칭 pseudo | 1,823 (2.66%) |
| URL `memnum` 보유 pseudo | 1,792 |
| 그중 `CRM_MEMBER` 에 실재 | 1,637 |
| **신규 매칭 여력**(현재 미매칭) | **1,406** |
| 기존 매칭과 **충돌** | **4** |

→ 결선 1,823 → **3,229 (+77.1%)** · 충돌 0.2%. **phase-2 최우선 후보**로 기록한다(G-1/G-5 커버리지 문제의 직접 완화책).

**⑥ 🔴 `FACT_GA_BEHAVIOR.CAMPAIGN_SK` 는 상수 0 하드코딩이다**

모델이 `0 as CAMPAIGN_SK` 로 고정한다. 결과: `WIDE_GA_BEHAVIOR` 의 `CAMPAIGN_BK`·`CAMPAIGN_NAME`·`CAMPAIGN_BRAND` 가 **실측 distinct 1 = 전건 `(미매핑)`/NULL** — 소비 계층에 死축 3컬럼이 노출돼 있었다. 한편 GA 캠페인은 `SILVER.GA4_EVENT.UTM_CAMPAIGN` 에 **244종·채움 88.0%** 로 실재한다. **§17-B `FEP.EVENT_BK` 와 완전히 동일한 P51 위반**이다.

| `PAGE_REFERRER` 귀속처 | `DIM_GA_PAGE` 역할수행 (`REFERRER_PAGE_SK`) | **`DIM_GA_REFERRER` 신설** grain=(REF_HOST,REF_PATH) 1,678행 + `IS_INTERNAL` | referrer host **206종** vs 자사 host **11종** · path 정확일치 **857/1,678 = 51.1%** · host 기준 내부 1,253(74.7%) · 외부 **425종(25.3%)**: `youtube.com`·`www.google.com`·`pay.naver.com`·`bing.com`·`chatgpt.com` 등 195 host |

**왜 오판정이었나**: *"쿼리 제거 시 1,678종이고 `PAGE_PATH` 1,953종과 자릿수가 같다"* 는 **크기 유사성**을 conform 근거로 삼았다. 그러나 conform 판정의 기준은 크기가 아니라 **도메인 동일성**이다 — referrer 의 도메인은 *"인터넷의 모든 URL"* 이고 페이지축의 도메인은 *"자사 11개 host 의 페이지"* 다. 겹치는 부분(51.1%)은 `IS_INTERNAL=TRUE` 로 표시해 `REF_PATH` 로 대조하면 되고, 나머지는 의미상 **유입 출처축**(organic/social)이므로 애초에 페이지축이 아니다.

→ 🆕 **P56 (차원 conform 판정은 카디널리티 유사성이 아니라 도메인 동일성으로 한다)**: 두 컬럼의 distinct 수가 비슷하다는 사실은 같은 차원이라는 근거가 **전혀 아니다**. `PAGE_REFERRER`(1,678종)와 `PAGE_PATH`(1,953종)는 자릿수가 같았지만 값 집합의 **정의역이 달랐다**(외부 25.3%). → conform 여부는 **① 값 집합의 교집합 비율**과 **② 정의역(누가 발급하는 값인가)** 으로 판정한다. 크기 비교는 판정 근거가 아니라 정황일 뿐이다.


### 18-I. 신규 교훈

- **P52 (차원이 GOLD 에 존재하는 것과 팩트에서 도달 가능한 것은 다르다 — 중복축 판정은 「존재」가 아니라 「도달」로 한다)**: `DIM_AD_CREATIVE` 는 8,716행이 적재돼 있지만 유일한 참조 FK 가 100% 센티넬이라 **어떤 팩트에서도 조회할 수 없다.** §18-D ① 의 중복축 판정 규칙(*"같은 역할 컬럼이 GOLD 에 이미 있는가"*)을 존재 기준으로 적용하면, **도달 불가 차원을 근거로 원천 컬럼을 DROP** 하게 된다. → 중복축 판정 시 대체 컬럼이 **어느 팩트에서 몇 % 비센티넬로 도달되는지**까지 확인한다. 도달 불가면 그것은 대체재가 아니라 **또 하나의 결손**이다.
- **P53 (`ALL_NULL` 집계에는 「빈 테이블」이 섞인다 — 컬럼 결함과 원천 미입고를 분리하라)**: 미주입 106 중 8건은 0행 테이블(`FACT_TARGET_BIZ`)의 컬럼이었다. 컬럼 단위로만 세면 **원천 입고 이슈가 배선 결함으로 보고**된다. → 미주입 판정 결과는 **테이블 행수와 조인해 0행 테이블을 분리 표기**한다. **역방향도 같다** — 0행 테이블은 모든 FK 의 센티넬율이 0% 로 나오므로 **「센티넬 0% = 도달 가능」 판정의 근거로 쓸 수 없다**(§18-G ⑩). 도달가능 근거로 쓸 팩트는 **행수 > 0 을 먼저 확인**한다.
- **P54 (정본 지표명이 산식을 보증하지 않는다 — 지표 충족 여부는 산식을 읽어 판정한다)**: `PAGE_PATH` 는 COMMENT 에 *"페이지경로+쿼리 (#105)"* 라 적혀 있었고 정본 #105 의 지표명도 「페이지경로+쿼리문자열」이라 **이름이 완전히 일치**했다. 그런데 산식은 쿼리문자열을 잘라낸다. 게다가 그 쿼리문자열은 **다른 정본 지표(#122)의 유일한 파생 원천**이었다. → 지표번호를 COMMENT 에 붙일 때는 **정본 값정의와 산식을 대조**하고, **그 컬럼에서 파생되는 다른 지표가 있는지 정본을 역검색**한다(P38 의 지표 버전).
- **P55 (`MAX()` 대표값은 grain 이 좁을 때만 안전하다 — 은폐량을 세어 COMMENT 에 적어라)**: `PAGE_LOCATION` 은 `MAX()` 로 노출돼 URL **75,474종 → 8,408종(88.9% 소실)** 이 됐고 COMMENT 는 *"URL 전체"* 라고 적혀 있었다. 같은 `MAX()` 패턴인 `DEFAULT_CHANNEL_GROUP`(다중 9/146)은 안전하다. **차이는 grain 대비 은폐량뿐**이다. → 대표값 노출을 결정할 때는 **`SUM(distinct)-COUNT(grain)` 으로 은폐 종수를 세고**, 그 수치를 COMMENT 에 남긴다. 은폐량이 크면 grain 에 포함하거나 노출하지 않는다.
