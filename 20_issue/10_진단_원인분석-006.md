## 12. [2026-08-03 O24 — FME 개발구분 도메인 부분적재] 진단 결론 · 신규 교훈

### 12-A. 트리거와 판정 — "항의는 옳았고, 원인은 우리 추정과 달랐다"

현업 항의: *"회원 상태가 개발·중단·미납·활동·증액·감액 등 다양한데 GOLD 엔 `dev`·`stop` 둘만 있다."*

열거된 6개는 **한 축이 아니라 3축**이다. 이 분해를 먼저 하지 않으면 조치 범위를 잘못 잡는다.

| 현업 표현 | 축 | 실제 위치 | 항의 시점 상태 |
|---|---|---|---|
| 개발 | 사건 | `FME` 개발원천 | 있음(단 5종이 뭉개진 상태) |
| 증액 · 감액 | 사건 | 동일 — `DVLP_DIV_CD` 2·3 | **라벨 소실**(행은 존재) |
| 중단 | 사건 | `FME` 중단원천 + 개발원천 코드5 | 있음(단 **양쪽 중복**) |
| 활동 · 미납 | **상태** | `DIM_MEMBER.MEMBER_STATUS_NAME`(MM010) | **이미 한글 라벨 완비** |

즉 활동·미납은 애초에 FME 소관이 아니었고 이미 라벨까지 갖춰져 있었다. 현업은 `EVENT_TYPE` **한 컬럼만** 보고 "2종뿐"이라 판단했다.

### 12-B. 실제 결함 — 의미혼입(O16 계열), 미적재가 아니다

SILVER `CRM_MEMBER_DEV` 는 `DVLP_DIV_CD` 를 **정상 보존**한다. GOLD `FACT_MEMBER_EVENT.sql:21·30` 이 이를 **무시하고 전건 `'DEV'`·`DEV_CNT=1` 로 하드코딩**했다. 정본 컬럼정의서 167행이 이 컬럼에 코드그룹 **MM015** 를 지정하고, `SILVER.CRM_CODE` 에 5종 라벨이 `USE_YN='Y'` 로 **이미 완비**돼 있었다 — 즉 **원천도 코드사전도 있었고 GOLD 배선만 없었다.**

```
DVLP_DIV_CD  라벨        행수         SPNSR_AMT 합계
  1          신규      1,788,612      +330.3억
  2          증액        367,295      +142.5억
  3          감액        292,285      −124.4억   ← 이탈성
  4          재후원      135,971       +23.9억
  5          후원중단  1,010,680      −215.2억   ← 이탈성
                     ─────────
                     3,594,843  = 종전 DEV_CNT 전량
```

### 12-C. 🔴 부수 발견이 원 항의보다 심각 — `DEV_CNT` 56.86% 과대계상

정본 공#121 *"개발구분 = 신규, 증액, 재후원"* → 개발 = 코드 1·2·4 = **2,291,878**. 종전 값 **3,594,843** 은 **감액·후원중단까지 개발실적으로 계상**한 것이다. 두 코드는 금액 합계가 음수인 이탈성 사건이므로 방향이 반대다.

**독립 확증**: `FACT_TARGET_DEV.DEV_TYPE`(#121 conform) 실측값이 `1`·`2`·`4` **3종뿐**이다. 목표 팩트는 처음부터 정본 정의를 지키고 있었고, 실적 팩트만 어긋나 있었다 — **목표와 실적의 분모가 다른 상태**로 개발달성률이 산출될 수 있었다.

### 12-D. ❌ 폐기한 조치안 — IRSD(증감) 팩트 편입

세션 초기 계획은 `TM_MM_FDRM_MBER_IRSD`(324,947행)를 `RDCAMT_YN`(감액여부)으로 증액·감액 분해해 편입하는 것이었다. **정본 대조(PROC-2)에서 폐기**했다.

- 정본 `테이블정의 20260629.csv:36` 비고: *"UPDATE 내역은 RDCAMT_YN이 Y로 바뀌나, **안 바뀌는 경우도 있음**, 그 외에 날짜로 구분이 불가함"* → **현업이 직접 불신을 명시**한 컬럼이다.
- 실측 확증: 명백 오분류 **752키**(감액인데 N 201 · 증액인데 Y 551) + 증액·감액 동시 존재로 **판정불가 50,295키(16.5%)**.
- 게다가 IRSD 키의 **99.62%가 이미 `DVLP_AMT` 코드 2·3에 존재하는 부분집합**이다.

→ 권위 원천은 `DVLP_DIV_CD`(MM015) 하나다. 조언대로 `DVLP_AMT`·`SPNSR_DSCNTC` **두 테이블만으로 전부 해결**됐다.

⚠️ **파생 부채**: `FACT_MEMBER_MONTHLY.sql:101` 의 `AMT_INCREASE_CUM_CNT`·`AMT_DECREASE_CUM_CNT`(W4/DEC-22)가 바로 이 불신 컬럼 기반이다. 별도 트랙으로 재산출 검토 필요.

### 12-E. 🟠 잔여 미결 — 후원중단이 두 원천에 중복 존재

`DVLP_DIV_CD='5'` 924,044키 중 **923,931(99.99%)** 이 중단원천에 **동일 회원·동일 일자**로 존재한다. 조치에서는 코드5 행을 `DEV_CNT=0`·`STOP_CNT=0` 으로 두어 measure 이중계상을 막았으나, `DVLP_DIV_NM='후원중단'` 을 행수로 세면 `EVENT_TYPE='STOP'` 과 중복된다. **두 원천이 동일 사건의 이중 기록인지, 서로 다른 중단 단위(후원사업별 vs 회원별)인지**가 미확정 — 확인 전 합산 금지를 DDL·WIDE COMMENT 에 명시했다.

### 12-F. 컬럼 명명 — BRONZE 코드체계 유지 원칙

현업은 아직 BRONZE 를 직접 조회하며, 분석용 DW 로 전환하는 과정이라 **새 개념이 나오면 혼동**된다. 따라서 **정본 지표가 명명한 것 외에는 BRONZE 이름·코드값을 그대로 노출**한다.

- ❌ `MEMBER_STATUS` — `DIM_MEMBER`(#132 MM010) 및 WIDE 5개 테이블과 **충돌**, 코드체계도 다르다
- ❌ 영문 mnemonic(`NEW`/`INCREASE`/…) — BRONZE 에 없는 신개념
- ✅ `DVLP_DIV_CD` / `DVLP_DIV_NM` — **정본 컬럼정의서 504행이 이미 쓰는 현업 용어쌍**
- ✅ `SPNSR_AMT` 원금액 보존 — 정본 공#38 감액(건)·#151 증액(건)이 **금액÷10,000**(CONF-2)이므로 행수로 세면 정의 파괴

`EVENT_TYPE` 은 도메인을 넓히지 않고 **"원천 계통축"(DEV=개발원천 / STOP=중단원천)으로 재정의**했다. 기존 `'DEV'`/`'STOP'` 을 전제한 소비처(FMM 롤업·WIDE·SV)를 깨지 않기 위한 선택이며, 상태축은 신설 2컬럼이 담당한다.

### 12-G. 신규 교훈 (P-시리즈)

- **P27 (차원값 도메인 부분적재는 어떤 자동검증에도 걸리지 않는다)**: `EVENT_TYPE` 이 5종 중 2종만 가져도 **행수 검증·fan-out 검증·참조무결성 검증·not_null 을 전부 통과**한다. 누락된 값은 "틀린 행"이 아니라 **"없는 행"**이라서다. P15("설계 완료 ≠ 값 존재")는 *컬럼이 비어 있는* 경우였고, 이번은 **컬럼에 값이 있으나 도메인이 부분적재된** 새 변형이다 — 더 위험하다. 비어 있으면 눈에 띄지만, 부분적재는 **그럴듯한 값이 들어 있어** 아무도 의심하지 않는다. → **코드성 컬럼은 원천 코드사전(`CRM_CODE`)의 `USE_YN='Y'` 값 집합과 적재 결과를 대조하고, `accepted_values` 로 도메인을 고정**한다. 현업 항의가 유일한 탐지 경로여서는 안 된다.
- **P28 (지표 정의 위반은 conform 상대와 대조하면 드러난다)**: `DEV_CNT` 56.86% 과대계상은 정본 문구(공#121)로도 잡히지만, **같은 개념을 공유하는 다른 팩트**(`FACT_TARGET_DEV.DEV_TYPE` = `1`·`2`·`4`)와 대조하면 **문서를 읽지 않고도** 드러난다. conform 차원·축을 공유하는 팩트가 둘 이상 있으면 **도메인 집합이 일치하는지 정례 대조**할 것. 목표와 실적의 분모가 다르면 달성률이 조용히 틀린다.

### 12-G-2. SV/Agent 영향 점검 — "영향 없음"으로 넘기지 않았다

순서9-II 가 광고 팩트 변경을 "SV/Agent 영향 없음"으로 판정했다가 순서9-J 에서 오판으로 뒤집힌 이력이 있어, 이번에는 **실제 참조를 grep 으로 확인**했다. 영향이 있었다.

- 🔴 **`SV_MEMBER_EVENT.EVENT_TYPE` COMMENT 가 "상태전이 유형(개발/중단/**증액**/미납중단 등)"** — 실제값은 `DEV`/`STOP` 2종. Analyst 가 `EVENT_TYPE='증액'` 을 생성하면 **0행 = 무증상 오답**(AD-4 와 동일 유형, 에러·경고 없음). → COMMENT 를 "원천 계통축"으로 교정.
- 🟢 **`DVLP_DIV_NM`·`DVLP_DIV_CD` 차원 신설** + 증액·감액 **금액·회원수 metric 4종 신설**. 임시 SV(`ZZ_TMP_SV_ME_O24`)로 문법·값 검증 후 DROP — 실측 일치(증액 +14,251,550,042원·214,394명 / 감액 −12,443,707,772원·170,879명).
- 🟢 **`TOTAL_DEV_CNT` 값이 바뀐다**(과대계상 교정분) → metric COMMENT 에 교정 사실과 이전 값을 명시해 과거 리포트 대조 시 혼란을 막았다.
- 🟢 **Agent instruction 은 변경 불요** — 상태축 필터·중단 합산금지·(건) 단위 규칙을 **SV `AI_SQL_GENERATION`** 에 넣었다. P11(생성 SQL 제어는 SV 계층 소유)에 따른 것이며, Agent 프롬프트에 병렬 규칙을 두면 P24(위임 규칙과 병렬 규칙 공존 → 비결정적 무시)를 위반한다.

### 13-B. O25 진단 — 결손은 어떤 자동검증에도 걸리지 않았다

- 🔴 **계보 계약 위반**: `04_컬럼계보매핑.md:105` 가 `FME.STOP_REASON`(정본 공#162) 변환규칙을 *"사유코드→라벨"* 로 명시했으나 실적재는 **raw 코드**(1·14·16…)였다. SILVER `CRM_MEMBER_DISCONTINUE.DSCNTC_RSN_NM` 라벨은 **채움률 100%(1,038,262/1,038,262)** 로 이미 존재했고 **GOLD 가 전파만 안 한 것** — O24 와 동일 유형.

### 13-C. O26 진단 — 정본을 지키려던 코드가 정본을 위반했다

🔴 **위반 1: 존재하지 않는 범주를 창작했다.** `DIM_MEMBER.GENDER_NAME` 이 하드코딩 `CASE UPPER(SEX) WHEN 'F' THEN '여성' WHEN 'M' THEN '남성' ELSE '미상' END` 로 **3종**을 만들었으나, 정본 지표 **공#130 성별 정의는 "남 / 여 / 기업 / 단체 / 기타" 5종**이다. 정본에 없는 **'미상'을 창작**하고 **법인·단체를 '미상'으로 오라벨**했다. P21(개념 부재를 결측으로 오판) 유형.

### 13-D. 명명 규칙 전환 — §12-F 의 확장·구체화

§12-F("정본 지표가 명명한 것 외에는 BRONZE 이름·코드값을 그대로")를 **코드/라벨 2계층으로 분리**해 규칙화했다. 결정 정본 = 문서30 **DEC-25**.

| 계층 | 규칙 | 근거 |
|---|---|---|
| **코드** | BRONZE 원천명 그대로 | BRONZE 가 **이미 수식어 접두 관례**를 쓴다(`ACT_`/`ACMSLT_`/`REGIST_DEPT_CD` · `EMAIL_`/`MOBLPHON_`/`ETC_CTTPC_STAT_CD` · `TSTM_`/`ETC_TSTM_DIV_CD`) → **신개념 도입이 아니라 원천 관례의 일관 적용** |
| **라벨** | 분석 용어명 유지 · 값은 `CRM_CODE` 조인 | 하드코딩 `CASE` 폐기 → **사전 변경이 자동 반영**된다 |
| **동명이의** | 원천 테이블 변별 토큰을 접두 | G5 실측 2건 한정 |

- 개명 실행: GOLD `GENDER→SEX` · `MEMBER_STATUS→MBER_STAT_CD` · `MEMBER_TYPE→MBER_DIV_CD` · `ENROLL_PATH→JOIN_PATH_CD`. 라벨 6개(`GENDER_NAME`·`MEMBER_STATUS_NAME`·`MEMBER_TYPE_NAME`·`ENROLL_PATH_NAME`·`REGION`·`AGE_BAND`)는 **분석 용어라 유지**.
- 동명이의 분리: `PRCS_STAT_CD` → **`MBRFEE_PRCS_STAT_CD`**(회비) / **`PSTMTR_PRCS_STAT_CD`**(발송). `SEX` 는 개명하지 않고 **SILVER 를 CM013 raw 로 되돌려 체계를 일치**시켜 해소했다 — 동명이의 2건의 해법이 서로 다르다는 점이 중요하다(**이름을 바꿀 것인가, 값을 바로잡을 것인가**는 어느 쪽이 원천 충실한지로 결정).
- ⚠️ **가드는 오조인을 막지 못한다.** `accepted_values` 는 값 도메인만 고정하며, 같은 이름의 다른 체계를 **조인**하는 실수는 잡히지 않는다. 동명이의는 가드가 아니라 **개명으로만** 해소된다.
