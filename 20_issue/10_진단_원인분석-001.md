## 2. 핵심 교훈 (근본원인 예방)
- 사전의 **"추정"·"(LLM생성)"은 실측 전 사실 아님** → 단정 금지(P5).
- `_NO`/`_ID` 유사 키는 grain부터 의심 → distinct 비교(P2).
- PK 있어도 measure는 실물 중복 별도 확인(P4).
- **정의서 타입 ≠ 실측 타입**: UNION/캐스팅 전 `INFORMATION_SCHEMA.COLUMNS` 실타입 확인.
  - 예: `SNDNG_STDR_DE`·`SEND_DATE` 문서상 TEXT였으나 실측 DATE → `::TIMESTAMP_NTZ` 필요.
- **다계열 UNION 키는 판별자를 PK에 포함**(예 `SEND_CHANNEL`) → 미래 키 충돌 방지.

## 3. 설계 노트 (개선 후보·비긴급)
- **월 팩트 conform 갭**: `FACT_MEMBER_MONTHLY`·`ERP_BUDGET`는 `MONTH_KEY`(YYYYMM) grain인데 **DIM_MONTH 부재**, `DIM_DATE`는 일 grain → 월 팩트가 날짜차원에 단일키 조인 불가. **월 차원 신설 또는 degenerate 명시** 검토.
- **`DW_BATCH_ID` 전 SILVER NULL**: `NULL AS DW_BATCH_ID` 하드코딩(dbt `invocation_id` 미주입). 감사메타 보완 필요(GOLD는 `gold_meta` 매크로로 정상 주입). *내부 처리·현업 판정 대상 아님.*
 - **🔴 FROZEN(삭제 금지) — D1 후속**: 스캐폴드 팩트 6종(FGA·FSE·FMM·FME·FEP·FTD)은 `incremental + append + pre-hook TRUNCATE + full_refresh:false`(순서9 G-1/G-2 개정 — `table`은 CTAS가 06_DDL FK/타입 드롭해 폐기). 매 run TRUNCATE 후 전량 재적재 → 잔존행 0·멱등이나 **대량시 재적재 비용 발생**. **마감 전 볼륨·비용 재평가 후 진성 `incremental`(+merge, unique_key에 활성 SK) 재전환 여부 결정 필수.** (의사결정 상세: 문서30 D1)

### 5-D. [2026-07-15] identity 활성화 진단 (ID-활성)
- **enablement 전제 무효화**: `DIM_MEMBER_IDENTITY`의 `enabled=false` 사유("GA4_IDENTITY 비활성")는 SILVER `GA4_IDENTITY`(1,348행)·`IDENTITY_MEMBER_XREF`(1,348행)가 이미 적재돼 **무효** → 활성화 정당.

### 6-A. 🔴 기저 FACT grain 비유일 (FME·FSE·FEP) — PK 미선언으로 회피

### 6-B. ⚠️ 비율 metric의 전기간 무필터 왜곡 (납부율 100.36%)

- **처리**: SV comment + Agent custom instruction에 **"납부율은 연/월 기간 스코프 필수, 전기간 총율은 참고치"** 강제.
- **교훈(신규 P10)**: **분모가 중복 누적되는 비율 metric은 기간/그룹 스코프 없이는 의미 없음** → 기본 응답에서 무필터 단일값 금지. (미납회원 감소율 등 DISTINCT 기반도 월 그룹 전제.)

- **해소**: 공식 클로즈 **`AI_SQL_GENERATION '<지침>'`**(CREATE SEMANTIC VIEW, 2026-01 도입 = `module_custom_instructions.sql_generation`)을 5개 SV 전부에 부여. **지표 성격별 기본스코프 차등**: SV_BUDGET=**최신 연도 전체**(편성/집행은 연간합계가 자연스러움) · 플로우/비율 SV 4종(MEMBER_MONTHLY·MEMBER_EVENT·SERVICE·EVENT_PARTICIPATION)=**최신 1개월**.
- **[2026-07-23 개정1]** 러프한 질문엔 단일값보다 추이가 유용 → 5개 SV "최신 12개월 월별 추이"로 통일(VERSION$6).
- **[2026-07-23 개정2 = AI/DB 전문가 검토 반영]** §7-F 참조. "무조건 월별"의 경직성·CURRENT_DATE 오류를 교정한 **최종 설계**(VERSION$7):
  · **적용 조건 명확화**: "기간·그룹이 **모두** 없을 때만" 기본스코프 발동(그룹 지정 질문=예: 세세목별·특정 프로젝트는 대상 아님).
  · **총계+월별 동시 제공**: `GROUP BY ROLLUP((연,월))`로 12개 월별 행 + 총계 행을 한 쿼리로 반환 → 비율(집행율·납부율)도 총계 레벨에서 SUM기반 정확. Agent는 상단 총계요약→월별표→되묻기.
  · **단일값 우선**: 사용자가 "합계/총액만" 요청 시 단일값 답변.
  · **기준월 = 데이터 MAX(연월)**(CURRENT_DATE 아님): 실측 데이터 최신월이 FMM 2029-11·FBD 2026-12로 오늘(2026-07)보다 미래 → CURRENT_DATE 윈도우는 최신데이터 누락. 검증: FMM `MAX(month_key)` 기준, 발송 `MAX(cal_year*100+cal_month)` 기준으로 직전 12개월 ROLLUP 생성 확인.
- **검증**(Cortex Analyst 생성SQL): 예산 → `WHERE cal_year=(SELECT MAX(cal_year))` · 회원월 "납부율은?" → `ORDER BY month_key DESC LIMIT 1`. ✅ 트라이얼에서도 `cortex analyst query` CLI로 **생성SQL 검증 가능**(6-C DATA_AGENT_RUN 차단과 무관 — Analyst text-to-SQL은 열려 있음).
- **교훈(P11)**: **기본 필터·데이터포맷 등 "생성 SQL 제어"는 Agent instruction이 아니라 SV의 `AI_SQL_GENERATION`에 넣어야 반영된다.** Agent orchestration은 라우팅·답변톤 담당. → 6-B(P10 기간스코프 강제)의 **실행 수단이 이 계층**임을 확정.

### 7-B. 🛠️ SV 부분재배포: `CREATE OR ALTER` = GRANT 보존 (`CREATE OR REPLACE`는 소실)
- `CREATE OR REPLACE SEMANTIC VIEW`는 GRANT 전부 삭제(OWNERSHIP만 잔존) → 재부여 필요(05_SV_DDL.sql §6 경고, SV_MEMBER_MONTHLY 재배포 시 실측).
- **`CREATE OR ALTER SEMANTIC VIEW`는 기존 GRANT 보존**(SHOW GRANTS `created_on` 원본 timestamp 유지 실측). AI_SQL_GENERATION 추가처럼 **정의만 바꿀 땐 CREATE OR ALTER 권장** → 재grant 불필요. (`ALTER SEMANTIC VIEW … SET`은 COMMENT만 변경 가능.)

### 7-C. 🛠️ Agent COMMIT 후 재편집: `ADD LIVE VERSION FROM LAST` 필요
- `ALTER AGENT … COMMIT` 후 live 버전이 소진돼 다음 `MODIFY LIVE VERSION`이 **'Live version is not found'** 실패.
- **해소**: 재편집 전 `ALTER AGENT … ADD LIVE VERSION FROM LAST` → `MODIFY LIVE VERSION SET SPECIFICATION` → `COMMIT`. COMMIT이 새 VERSION을 default로 자동승격(`SET DEFAULT_VERSION=LAST`는 **미지원 — 문법오류**).

### 7-D. PoC 비즈니스로직 이식 (미납비중·총미납금액·평균납입회비)
- 4달전 PoC(`GN_DW_POC…SV_PAYMENT_ANALYSIS`)의 `UNPAID_RATIO`·`TOTAL_UNPAID`·`AVG_PAID`를 **현재 적재분(청구·납입 실적재)만으로** SV_MEMBER_MONTHLY에 파생 metric 3종 추가. 유지율/LTV/캠페인/광고/회원여정 등 PoC 리치 로직은 데이터 미적재로 제외(Phase-2).
- 미납비중 = 100−납부율 → 전기간 무필터 **−0.36%**(납부율 100.36%, 6-B와 동일 재청구·이월 왜곡) → 7-A 기간스코프(최신 1개월)로 완화.

### 7-E. Agent 답변 한글표기 규칙

### 7-F. AI/DB 전문가 검토 대응 (2026-07-23) · Data Mart는 Phase-2 백로그
- **AI 설계 검토(수용)**: "무조건 월별"은 문맥추론 저하·UX 경직 → 7-A 개정2로 **총계요약 우선 + 월별 추이 + 되묻기 + 단일값 우선**으로 유연화. "특정 프로젝트 예산"은 그룹 지정 질문이라 애초 기본스코프 대상 아님(적용조건 명확화로 해소).
- **DB 아키텍처 검토**:
  · (부분수용) "단일 SUM에 12개월 GROUP BY 강제 = 낭비" → 이미 12개월로 범위 제한 후의 월그룹은 풀스캔 대비 미미하고, ROLLUP 총계행으로 단일값도 동시 확보하므로 낭비 아님. "합계만" 요청 시 단일값 경로도 확보.

(설계결정 원장: 문서30에 후속 반영 대상.)
- **미해결 관찰**: `AI_SQL_GENERATION`은 자연어 지침이라 Analyst가 항상 동일 SQL을 생성하진 않음(예: budget=서브쿼리 MAX, service=산술 MAX). 결과 동치이나 결정론 아님 → VQR(ai_verified_queries)로 대표 패턴 고정이 더 강한 통제(Phase-2 후보).

### 7-G. 🔧 Agent instruction 컴팩트화 (VERSION$8)

- **원인(설계)**: **커버리지(재현율) 최적화가 정밀도를 침식**. 폴백 체인에서 "임의 substring 일치"를 "의미 패턴(파생)"보다 위에 둔 순서 오류. 커버리지 99%는 *매칭률*이며 정확도 지표가 아님에도 성과처럼 읽힐 위험.
- **해소**: 파생 의미 표지(`율|률|구성비|증감|대비|비중|달성|1인당|%`)가 있는 필드는 **③④를 건너뛰고 ⑤ SV 패턴으로 직행**(`DERIVED_MARK` 게이트). `후원기간대`는 `PERIOD_BAND1/2`(#74·75) 별칭 추가. 비율 폴백을 끝문자→포함검사로 보정. **재감사 결과 오매핑 0건**, SV파생 38→53·지표사전~ 34→19.
- **투명성 보강**: 장표 §0-1에 **매핑근거별 신뢰도 표**(정확일치 / 규칙기반 / 부분일치=검증필요 / 미매칭) + "커버리지≠정확도·부분일치 단독인용 금지·원천 변경 시 자동갱신 안 됨" 경고 명시.
- **교훈(P13)**: **문자열 기반 매핑 산출물은 "커버리지"와 함께 "근거별 신뢰도"를 반드시 병기**한다. 폴백 체인은 *의미 규칙 > 부분일치* 순으로 두고, 부분일치 결과는 검증대상으로 표시한다.
