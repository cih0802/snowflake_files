## §20. 연령대 × 캠페인 교차 불가 → 사건시점 속성 전파 (O35 · 2026-08-04)

> 본 절의 수치는 전부 **본 세션 BRONZE·SILVER 직접 실측**이다(작업조건 #3 · PROC-3).
> 방향(대안 A 채택)은 선행 세션에서 사용자 승인 완료 — 재론 대상이 아니고 **실행 기록**이다.

### §20-A. 문제 — Agent 가 자기 설명의 근거를 계산할 수 없었다

O34-B 에서 「10대 미만 최다」의 원인을 편지쓰기대회 계열 캠페인으로 실증하고 그 서술을 SV COMMENT 에
넣었다. 그런데 **Agent 는 그 근거를 스스로 산출하지 못한다** — 두 축이 다른 SV 에 갈라져 있다.

| SV | grain | 연령대 | 캠페인 |
|---|---|---|---|
| `SV_MEMBER_MONTHLY` | 월 × 회원 | 있음(`_AT_PLEDGE`) | 🔴 없음(`FMM.CAMPAIGN_SK` 센티넬 단일값) |
| `SV_MEMBER_EVENT` | 일 × 회원 × 사건 | 🔴 없음 | 있음(개발 사건 전용) |

`SEMANTIC_VIEW()` 는 **단일 뷰 대상 테이블 함수**라 Agent 는 SV 를 각각 호출해 문장으로 합칠 뿐
**행 단위 조인을 못 한다**. 즉 SV 계층에서 해결되지 않는다.

### §20-B. 원천 실측 (BRONZE → SILVER)

| 측정 | 결과 |
|---|---|
| `BRONZE_CRM.TM_MM_FDRM_MBER_DVLP_AMT` 행수 | 3,594,843 |
| `.AGE` 채움 · distinct | 3,594,843(100%) · 12종 = CM014 **12/12 일치** |
| `.AREA_CD` 채움 · distinct | 3,594,837 · 19종 = CM018 18종 + 라벨 없는 센티넬 `'0'`(20,624행) · NULL 6행 |
| SILVER `CRM_MEMBER_DEV` | BRONZE 를 1:1 승계(행수·채움 동일) + **`AREA_NM`(CM018 라벨) 이미 보유** |
| 🔴 **스냅샷 재현 가능성** | 복수 개발사건 회원 1,040,895명 중 **`AGE` 변동 102,685명 · `AREA_CD` 변동 50,039명** → 사건행별 값과 「최근 약정」 스냅샷은 **실제로 다르다** |
| 중단원천 `TM_MM_FDRM_MBER_SPNSR_DSCNTC` | 전 **9컬럼** — 연령·지역 컬럼 **구조적 부재** → NULL(0 금지, P21) |

🔴 위 「변동 회원」 측정이 이 작업의 **정당화 근거**다. 만약 회원당 값이 불변이었다면 차원 스냅샷으로
충분했고 전파는 중복 축을 만드는 일이었을 것이다. 실측이 그 반대를 보였다.

### §20-D-3. SV 확장 배포

`SV_MEMBER_EVENT` 에 차원 4개 추가(`AGE_BAND_AT_EVENT`·`AGE_CD_AT_EVENT`·`REGION_AT_EVENT`·
`AREA_CD_AT_EVENT`) + SV COMMENT · `AI_SQL_GENERATION` 규칙 (7) 신설. 정본 `05_SV_DDL.sql` 먼저 수정 후
그 블록만 실행했다. ⚠️ `CREATE OR REPLACE` 가 GRANT 를 파괴하므로 **§7 GRANT 3줄을 같은 세션에 재실행**
(ANALYST·VIEWER·SERVICE) — 05 파일 §7 경고의 지시대로다.

### §20-D-4. Agent 스펙 배포 (재구축 순서 ⑥ 완료)

`09_2_AGENT_버전업.sql` 경로로 정본 yaml 을 stage 에서 직접 읽어 새 버전 발행.

| 단계 | 결과 |
|---|---|
| stage 정본 확인 | `AGENT_MEMBER/agent_spec.yaml`·`AGENT_OVERALL/agent_spec.yaml` 존재 — 본 세션 수정분이 `versions/live` 에 즉시 반영됨(문서 서술대로) |
| live 선소진 | 두 Agent 모두 `committed`(멱등 블록) → `VERSION$2` 로 껍데기 스냅샷 보존 |
| `ADD VERSION FROM` | 두 Agent 모두 **`VERSION$3` · `is_default=true`** · 이전 버전 보존(롤백 가능) |
| 스펙 실물 확인 | `AGENT_MEMBER` = 도구 4개(`analyst_*`) + 교정된 instruction 전문 반영 |
| GRANT 보존 | `SHOW GRANTS` = OWNERSHIP + **USAGE 3종(ANALYST·VIEWER·SERVICE) 잔존** — 이 경로가 파괴하지 않는다는 서술이 실측으로 확인됐다 |

⚠️ 성공 메시지가 `Version nullsuccessfully created` 로 나오는 것은 **표시 버그**이며 실제 버전은 정상
생성된다(정본 09_2 주석의 사전 경고와 일치 — 놀라지 말 것).

🔴 **NL 스모크는 실행하지 못했다**: `SNOWFLAKE.CORTEX.DATA_AGENT_RUN` 이 **트라이얼 계정에서 차단**된다
(`Access denied for trial accounts`). 따라서 *"10대 미만 개발건이 왜 많아? 캠페인별로 보여줘"* 를 Agent 가
실제로 도구 호출까지 수행해 답하는지는 **Snowsight UI·CoWork 에서 사람이 확인해야 한다**(PRV-3 잔여).
SQL 계층(`SEMANTIC_VIEW()` 직접 호출)은 §20-D-2 에서 검증 완료이므로, 미검증 구간은 **Agent 의 도구
선택·instruction 준수** 뿐이다.

### §20-E. 자기검토

| # | 항목 | 내용 |
|---|---|---|
| ① | ⚠️ **구문 오류 1회** | `ALTER TABLE … ADD COLUMN IF NOT EXISTS a, ADD COLUMN IF NOT EXISTS b` 는 **문법 오류**다. Snowflake 는 `ADD COLUMN IF NOT EXISTS` 를 한 번 쓰고 컬럼을 콤마로 나열한다. 재시도로 해소 |
| ② | 🔴 **문서 공백 발견** | 이슈원장이 지목하는 **§19-J(P60)가 문서10 에 없었다** — O33·O34·O35 진단 전문이 이슈원장에만 있었다. 즉 *"상세 = 문서10 §19"* 라는 안내가 **닫힌 링크**였다. 본 세션에서 §19-J 를 회수 신설했다. 교훈: 문서 간 상호참조는 **참조 대상의 실존을 확인**해야 한다(§19-H 와 같은 계열 — "가리킨 곳에 있다"고 가정하지 말 것) |
| ③ | ⚠️ **컬럼명 대안을 배제한 근거** | `AGE_AT_EVENT` 는 값이 나이가 아니라 CM014 코드라 `AGE_CD_AT_EVENT` 가 더 정확했을 수 있다. 그럼에도 원천명(`AGE`)·기존 GOLD 축(`DIM_MEMBER.AGE`)과의 **일관성**을 택하고 오독 위험은 COMMENT 3중 경고(연속형 아님·평균 금지·코드 열거)로 막았다. O26 명명 규칙(코드=BRONZE 원천명)의 적용이다. 🟢 단 **SV 차원명은 `AGE_CD_AT_EVENT`** 로 뒀다 — SV 는 Agent 가 읽는 계층이라 오독 비용이 더 크고, 차원명은 물리 컬럼명과 달라도 되기 때문이다 |
| ④ | 🔴 **가장 중요한 발견 — 조치가 소비 끝단에서 무력화될 상태였다** | §20-F 참조. 팩트·SV 까지 다 고쳐도 **Agent instruction 이 "지역/연령대는 미적재"라고 지시**하고 있었다 |
| ⑤ | ⬜ **미검증 잔여 1건** | Agent 스펙 배포는 완료했으나(§20-D-4) **NL 스모크는 트라이얼 계정 제약으로 불가**하다 — `DATA_AGENT_RUN` 이 차단된다. Snowsight UI·CoWork 에서 사람이 확인해야 한다(PRV-3). SQL 계층은 검증 완료이므로 남은 위험은 **Agent 의 도구 선택·instruction 준수**뿐이다 |
| ⑥ | ⚠️ **`_AT_PLEDGE` 쪽 미조치** | `SV_MEMBER_MONTHLY` 의 `MEMBER_AGE_BAND_AT_PLEDGE` COMMENT 는 *"교차 확인은 SV_MEMBER_EVENT 에서"* 라고만 안내한다. 이제 그 SV 에 실제로 축이 생겼으니 서술은 참이 됐다 — 다만 *"불가"* 계열 표현이 남아 있는지는 재확인하지 않았다(다음 세션 점검 대상) |

### §20-F. 🔴 파생 발견 — 소비 끝단(Agent instruction)이 조치를 무력화할 상태였다

P59(소비 계층 역추적)를 SV 에서 멈추지 않고 **Agent 스펙까지** 밀고 갔더니 정본
`cortex_project/agents/AGENT_MEMBER/agent_spec.yaml` 이 다음과 같이 지시하고 있었다:

> *"미적재분(**캠페인**/조직/후원사업/**사유별** … **지역/연령대** 등)은 창작 금지 → '데이터 적재 후(Phase-2)
> 제공 예정' 안내"*

**이 4축은 전부 활성이다** — 캠페인·중단사유·중단경로는 O33(2026-08-04), 연령대·지역은 O35(본 세션).
즉 팩트·SV 를 고쳐도 **Agent 는 "그건 아직 없습니다"라고 답하도록 지시받은 상태**였다. 데이터가 맞고
SV 가 맞는데도 답이 틀리는 경로이며, 어떤 데이터 품질 테스트로도 잡히지 않는다(P19·O33 계열).

추가로 같은 파일의 `analyst_member_event` **도구 description 이 O24 이전 상태**였다 —
차원을 *"전이유형(개발/중단)"* 으로만 적어 O24 가 교정한 「상태축은 `DVLP_DIV_NM`」 규칙이 빠져 있고,
증액/감액 measure·캠페인·중단사유 축도 누락이었다. 도구 description 은 오케스트레이터의 도구 선택
근거이므로, 누락된 축은 **도구가 선택되지 않아** 사실상 비활성이 된다.

✅ 조치(정본 yaml): ① 활성/미적재 목록 교정 ② 연령대·지역이 약정시점 축임을 명시(현재값 산출 불가)
③ *"10대 미만 왜 많은가"* 는 추측 금지·`연령대 × 캠페인` 교차를 실제 실행 후 설명하도록 지시
④ `analyst_member_event` description 을 O24·O33·O35 축으로 전면 갱신 ⑤ `orchestration` 에
「연령대·지역 분해는 `analyst_member_event`」 라우팅 규칙 추가 ⑥ `sample_questions` 4건 교체.

⚠️ **배포 상태 주의**: 실측 결과 라이브 `AGENT_MEMBER`·`AGENT_OVERALL` 의 스펙은
`{"models":{"orchestration":"auto"}}` — **껍데기(VERSION$1)뿐이고 도구·instruction 이 하나도 없다**.
재구축 순서 ⑥(`09_2_AGENT_버전업.sql`)이 아직 실행되지 않았기 때문이다(§19-I 최소경로의 마지막 단계).
