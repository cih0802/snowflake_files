### 18-C. 🔴 B군 — `DIM_SERVICE.SEND_TYPE_L/M/S`: DROP 판정 철회 · 차원 재설계 결정 대기

⚠️ **본 절은 당일 자기검토로 초판을 철회한 것이다.** 초판은 *"grain 함수종속 불성립 → 3컬럼 DROP"* 으로 결정했다. **DROP 은 오답이다** — 이 3컬럼은 **정본 지표 #133·#134·#135(발송구분 대/중/소)** 이고 `WIDE_SERVICE_EVENT` 가 이미 그 지표번호로 노출한다. DROP 하면 정본 지표 3개가 소멸한다. 진단 정본 = 문서10 **§14-B**.

### 18-D. 판정 순서 규칙 (P37 — §17-C 규칙의 선행 단계 신설)

§17-C 의 사용자 확정 규칙(①같은 역할 컬럼 有→DROP ②BRONZE 근거 有→채움 ③둘 다 아니면 DROP)에 **grain 판정을 ② 앞에 삽입**한다.

```
① 같은 테이블에 같은 역할 컬럼이 있는가        → 있으면 DROP
②-NEW 대상 grain 에 함수종속하는가             → 아니면 DROP (원천이 있어도)
③ BRONZE/SILVER 근거가 있는가                  → 있으면 채움 (커버리지 병기)
④ 대표값 규칙이 필요한가 · 그 규칙이 확정됐는가 → 미확정이면 보류(게이트 우회 금지)
⑤ 위 어디에도 안 걸리면 DROP
```

**근거**: 본 세션 B군이 ②에서 걸렸다. ②가 없으면 "원천이 실재하므로 채움"(P14 논리)으로 잘못 진행된다. 반대로 `AGE_BAND` 는 ②를 통과하고 ④도 **불요**(원천이 이미 구간화)여서 즉시 ③ 이다.

`99_NEXT_SESSION.md` §3 과 문서10 §14-H·§14-I 는 **결론(두 체계 혼입 · 96.6% 소실 · 단위 오류)은 전부 옳았다.** 틀린 것은 **조치안의 세부 지정**이었고, 그대로 실행하면 다음이 발생했다:

- 조치안 ③을 문면대로 하면 → **정상 코드를 고치고 진짜 원인(원천 입력)을 방치**(결정 4로 교체)
- §3 대상 지정대로 하면 → **소비 계층(WIDE)에 경고가 안 닿음**(결정 1·2로 확장)

📌 **일반 규칙으로 승격**: 인수인계 문서의 조치안은 **결론과 별개로 재검증한다.** 결론은 실측에 근거하지만 **조치안은 그 시점의 추론**이며, 특히 *"어느 컬럼을 쓰라"* 는 지정은 §18-D ①(같은 역할 컬럼 확인)·`INFORMATION_SCHEMA` 실재 확인을 통과해야 한다. 미이행 시 P38(결손 창작)의 변형인 **"조치 창작"** 이 된다.

### 19-C. 구현 시 준수 사항

- 🟢 **GOLD 팩트 테이블 COMMENT 는 영구적이다** — `gold.fact` 는 `incremental + append + pre-hook TRUNCATE` 이고 **COMMENT 를 세팅하는 `post_hook` 이 없다**. `TRUNCATE` 는 COMMENT 를 지우지 않는다(본 세션 검증). 따라서 `ALTER … COMMENT` 만으로 충분하며 재빌드 불요.
- 🔴 **WIDE 뷰는 반대다** — `post_hook` 이 소유주이므로 **모델 파일 수정이 필수**다. 물리 ALTER 는 보조 수단.
- ⚠️ **`post_hook` 문자열에 이중인용부호를 넣지 말 것** — Jinja 문자열 이스케이프가 얽힌다. 본 세션은 `\"…\"` 를 **`「…」`** 로 교체해 회피했고 `dbt compile` 로 검증했다.
- 🔴 **완료 판정은 `INFORMATION_SCHEMA` 스캔**(P33) — 본 세션 결과 FEP 17/17 · WIDE_EP 16/16 · `DURATION_SEC` 3/3. 거짓 경고문 스캔(`온라인`) 잔존 1건은 **교정문이 구 문구를 인용해 설명하는 의도적 이력 서술**이다(§13-F-2 ④ 선례).
- 🔴 **정본 DDL 동기화 필수**(P33 ②) — GOLD 테이블 COMMENT 의 소유 산출물은 `06_DDL.sql` 이다. 물리만 고치면 다음 `CREATE OR REPLACE TABLE` 실행 시 되돌아간다.
