### 30-G. 🔴🔴 [2026-08-29 O118] 이 오류가 **SV 로 이미 발행되고 있다** + 항목단위 재현

> 🔴🔴 **정직 표기**: 「재작성」 판정은 **§30-F(O115)가 이미 확정**했다.

**㉡ 🔴🔴 신규 사실 — `SV_BUDGET` 이 라이브에 있고 과대값을 발행 중이다.**
O117 시점 전제(「이 계정에 SV 0」)가 무너졌다 — **2026-08-29 05:59 에 SV 10종 배포**
(실측 = `05_SV-Agent_ai/04_SV_설계.md` §0.9-A). `SV_BUDGET` base = `GOLD.FACT_BUDGET`(월) ·
`TOTAL_EXEC_BUDGET = SUM(fbd.EXEC_BUDGET_ERP)` · `SEMANTIC_VIEW()` 실측 **99,006,005,048**

🔴 **단계가 올라갔다** = 「돌리면 틀릴 것」 → 「조회하면 틀린다」 → **「의미 계층의 확정 metric 이다」.**
🟢 다만 **Agent 는 0** 이라 오답이 사용자에게 나가는 경로는 **미개통**
⇒ 🔴 **Agent 배포 전에 이 결정을 닫는 것이 정답 순서다.**

🔴 **차단조항이 지목한 객체가 틀렸다** — 종전 처방은 *"`05_6` 을 `FACT_BUDGET_YEARLY` 에 붙이지 마라"* 였고
라이브 base 는 `FACT_BUDGET` 이라 **문자적으로는 준수**됐다. 그러나 §30-F ③ 이 이미 적었듯
**두 팩트가 같은 값으로 같이 틀린다**(차이 0) ⇒ **결함은 그대로 상속됐다.**
⇒ 🟢 **판정식 신설** = **차단조항이 객체명으로 쓰여 있으면 그 결함값이 다른 객체에도 있는지 대조하라.**
「그 테이블을 안 썼다」 ≠ 「그 결함을 피했다」. 🔴 근거는 옳았고 **처방 문구가 좁았다.**

**㉢ O118 이 한 것 / 안 한 것.** 🟢 한 것 = 표기만 = `05_6_SV_DDL_BUDGET.sql` 헤더 **「보류」 선언** ·

### 31-B. 🔴 결정해야 하는 것 (현업·설계 소관)

㉠ **캠페인 1건이 후원사업 여러 개를 동시에 가리키는 것이 업무상 정상인가.**
  정상이면 다중값은 데이터 오류가 아니라 **관계 카디널리티(1:N)**이고, 비정상이면 원천 정정 사안이다.
㉡ 정상이라면 **그 N 을 분석에 노출할 것인가.** 노출하면 브릿지가 필요하고, 노출하지 않으면 관계 테스트를 단일값으로 한정해야 한다.
🔴 **㉠ 없이 ㉡ 를 정할 수 없다** — 이것이 이 절이 대기 상태인 이유이고, 에이전트가 대신 정할 수 없는 지점이다.
