# 32_컬럼개명표 — DEC-46 Phase 1 계보 라벨링 · 개명표

> 🔴 **결정문 정본은 여기가 아니다** = `20_issue/30_설계_의사결정_조각/30_설계_의사결정-012.md` **§32 (`DEC-46`)**.
> 이 문서는 그 결정의 **작업표**다 — 3분류 규약(P/L/X)의 정의·근거·구현 준수 사항은 §32 를 읽는다.
> 🔴 **분리 사유** = 26 계보 169컬럼의 라벨과 근거 좌표가 §32 조각을 **300줄 상한 밖으로 밀어냈다**
> (실측 319줄 · 2026-08-30 O123 · 사용자 결정으로 분리).

## 0. 판정 규칙 요약 (정본 = `DEC-46` 32-A)

| 분류 | 판정 기준 | 컬럼명 규칙 |
|---|---|---|
| **P** | 그 컬럼에 **로직이 0** 이다 — 원천 컬럼을 그대로 투영한다 | **원천명 유지·복원** |
| **L** | **join · union all · 계산 · 키 승격 · 타입 캐스트** 중 하나라도 있다 | **의미명 유지** |
| **X** | 서로 다른 원천·코드체계가 **같은 이름**을 쓴다 | **변별 접두 유지** |

🔴 **판정은 줄 단위가 아니라 계보 단위로 한다** — 텍스트 파싱은 `select *` 경유 · 여러 줄 `CASE` ·
상류 `UNION`/`JOIN` 이후의 bare 참조를 구조적으로 못 본다(`DEC-46` 32-A).

### 0-A. 사용자 확정 판정 원칙 (2026-08-30 O123 · 🔴 재논의 대상 아님)

| # | 쟁점 | 결정 | 파급 |
|---|---|---|---|
| ㉠ | `TRY_TO_NUMBER`·`CAST` 등 **타입 캐스트**를 로직으로 볼 것인가 | 🟢 **본다 ⇒ 분류 L** | 캐스트만 거친 컬럼은 **개명 0건** · P 분모가 그만큼 줄어든다 |
| ㉡ | `NULLIF`/`TRIM` 만 거친 컬럼 | 🟢 **로직이 아니다 ⇒ 분류 P** | 근거 = 코드베이스 자신의 관례(아래 1-A 참조) |
| ㉢ | 형제 모델이 서로 다른 어휘를 쓰게 되는 경우 | 🟢 **규약 우선 — 불일치 수용** | 계보가 다르면 이름이 달라지는 것을 정당한 결과로 본다 |
| ㉣ | `UNION ALL` 언피벗의 **위치 별칭** | 🟢 **분류 L**(`DEC-46` 32-C) | `ERP_BUDGET` 4건 개명 0건 |
| 🆕 ㉤ | `union all` 을 곧바로 L 근거로 볼 것인가 | 🟢 **정밀화 — 「그 `union all` 로 원천명이 유일하지 않게 되면」 L**(2026-08-31 O127) | 🔴 **정본 = `DEC-46` §32-G ㉠** · 기존 판정 12건 **불변** |
| 🆕 ㉥ | 문서화된 **쌍 계약**의 한쪽이 L 인 경우 | 🟢 **쌍 전체를 L 로 본다**(2026-08-31 O127) | 🔴 **정본 = `DEC-46` §32-G ㉡** · 8-C 가 이 조문으로 닫혔다 |

### 2-A. ERP 라벨링에서 나온 판정상 발견 3건

- 🔴 **계보 단위 판정이 실제로 갈렸다.** 겉모습이 같은 `BDGT`→`BUDGET` 약어확장인데

  이는 「의도적 의미명 부여」가 아니라 **일관성 없는 약어확장**임을 보여준다.
- ⚠️ **0-A ㉢ 의 귀결을 명시한다** — 개명 후 같은 ERP 원장에서 온 두 모델이
  `*_BUDGET_AMT`(월 · L) 와 `*_BDGT_TOT_AMT`(연 · P) 로 **서로 다른 어휘**를 쓴다.
  🔴 이것은 결함이 아니라 **사용자가 승인한 규약 우선의 결과**다 — 다음 세션이 「불일치」로 오판해 되돌리지 마라.

### 3-D. 🔴🔴 최대 발견 — `_SRC` 접미 7종은 **분류 X** 이고 `kind_hint` 는 이것을 `P?` 로 오표시한다

`AGENCY_AD_DIGITAL.sql` **5-8행**이 `_SRC` 의 존재 이유를 명시한다:
*"`_SRC` 컬럼 = 대행사가 계산해 넘긴 원천 파생값. DW 가 재계산하지 않고 원본 그대로 적재한다.
목적은 '대조'다 — SV 는 base measure 로 별도 재계산하고, 현업이 양쪽을 비교한다."*
⇒ 🔴 **`_SRC` 는 약어도 오염도 아니라 「대행사 산정값 ↔ DW 재계산값」을 가르는 변별 접미**다
(`DEC-25` 15-A 「동명이의 = 변별 토큰」의 **접미 버전** · `DEC-9` 가 전량 보존을 규정).
🔴 **원천명을 복원하면**(`CTR_SRC`→`CTR` 등) DW 재계산 measure 와 **실제 동명이의 충돌**이 생긴다
— 즉 개명이 규약을 지키는 것이 아니라 **규약이 막으려던 상태를 만든다.**
🔴 `kind_hint` 는 이 7종을 전부 **`P?(원천명 복원 후보)`** 로 표시한다 ⇒ **힌트를 따르면 7건을 잘못 개명한다.**
🟢 참고 = `AGENCY_AD_BROADCAST.AD_VIEW_RT_SRC`·`CPC_SRC` 는 **L(UNION ALL)이면서 동시에 X(접미)**다.
  분류가 겹치지만 **두 분류의 판정이 모두 「유지」**라 실무 영향은 없다 — 겹침을 결함으로 읽지 마라.

### 8-A. 판정식 정밀화 제안 — 「`UNION ALL` 이면 L」은 너무 거칠다

32-A 는 `union all` 을 곧바로 L 근거로 쓴다. 실측하니 두 경우가 갈린다:
· **원천명이 유일하지 않은 경우** = 분기마다 **다른** 원천 컬럼을 한 출력에 모은다
  (`ERP_BUDGET.YB` ← `YEAR_BDGT_AMT_1..12` · `CRM_EVENT.STRT_DE` ← `STRT_DATE`/`CRMN_STRT_DE`)
  ⇒ **복원할 이름이 하나로 정해지지 않는다** ⇒ 🟢 **L 이 옳다**(32-C 그대로).
· **원천명이 유일한 경우** = 전 분기가 **같은** 원천 컬럼명을 쓴다 ⇒ **복원이 잘 정의된다.**
🟢 **코드베이스의 관례가 후자를 P 로 다룬다** — `CRM_MEMBER` 의 `MBER_DIV_CD`·`SEX`·`HMPG_ID`·`REGIST_DEPT_CD` 는
전부 두 분기가 같은 원천명을 쓰며 **원천명을 유지**한다(부재 목록에 없다).
⇒ 🔴 **제안 = 32-A 의 L 조건을 「`union all` 이 있다」에서 「그 `union all` 로 원천명이 유일하지 않게 된다」로 정밀화한다.**

### 8-B. `CRM_MEMBER.JOIN_DT` ← `FRST_REGIST_DT`

2-way `UNION ALL`(FDRM ∪ ONCE)이고 **양 분기가 같은 원천명 `FRST_REGIST_DT`** 를 쓴다(31·64행) · 로직 0.
⇒ 8-A 를 적용하면 **P · 개명 → `FRST_REGIST_DT`**. 적용하지 않으면 L · 유지.
⚠️ 개명 시 부수효과 = `FRST_REGIST_DT`(최초등록일)와 `JOIN_DT`(가입일)는 **업무 의미가 같지 않을 수 있다**
— 원천 컬럼명이 더 정확한지 현업 판단이 필요할 수 있다.

### 8-C. `CRM_MEMBER_STATUS_HIST.EFFECTIVE_FROM` ← `FRST_REGIST_DT`

로직 0 · 순수 투영(10행)이라 축만 보면 P 다. 🔴 **그러나 이 컬럼은 SCD2 구간의 한쪽 끝**이고
짝인 `EFFECTIVE_TO` 는 `LEAD()` 계산이라 **L 이다**(11행) ⇒ 한쪽만 복원하면
`FRST_REGIST_DT` + `EFFECTIVE_TO` 라는 **읽을 수 없는 쌍**이 된다.
⚠️ `07_메타.md` **§4-1** 이 *"`EFFECTIVE_FROM`~`TO` 로 시점조인"* 을 문서화된 계약으로 쓴다 ⇒ 소비처 계약 파괴.
⇒ 🟢 **제안 = 「쌍 규약」 예외를 명문화하고 L 로 유지한다** — 짝의 다른 쪽이 L 이면 그 쌍 전체를 L 로 본다.
🟢 **같은 원천 컬럼(`FRST_REGIST_DT`)이 두 모델에서 다른 이름으로 나간다**(`JOIN_DT` · `EFFECTIVE_FROM`)
— 0-A ㉢ 「규약 우선 · 불일치 수용」의 또 다른 실물이다.
