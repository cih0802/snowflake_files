### 8-H. GA4 디바이스 분류 정합 + DIM_DEVICE 공용참조 근거 검토 (2026-07-27)
**(1) 🟢 GA4 `platform`×`device.category` 조합 — 메달리온 반영 확인**
- GA4 공식 기준(=`platform` 단독으로 PC/모바일웹 구분 불가, `WEB`은 둘 다 포함)은 **이미 SILVER에 정확히 구현**돼 있었음. BRONZE는 최상위 `platform`(WEB/ANDROID/IOS)·`device.category`(mobile/desktop/tablet) 모두 보유, SILVER `GA4_EVENT`·`GA4_DEVICE`가 두 필드를 조합해 `DEVICE_TYPE` 파생 + 원값(`PLATFORM`·`DEVICE_CATEGORY`) 보존.
- **APP 부재 원인 = 데이터**(로직 아님): `SILVER.GA4_EVENT` 265,312행이 **2026-05-01 1일 샤드**뿐이고 `platform`=**WEB 단일** → APP 생성 입력 자체가 없음. **G-5**(GA4 전기간 입고) 해소 시 자동 생성.
- **🔴→🟢 교정한 잠재결함**: 기존 `ELSE 'PC'` fallback이 **미분류를 전부 PC로 흡수**(platform·category NULL, 신규 category 등) → GOLD의 `(unknown)` 센티넬을 무력화하고 **PC 과대계상** 위험. GA4 정식 기준대로 `WEB × desktop = PC`를 명시하고 나머지는 `'(unknown)'`으로 격리.
  - 수정: `GA4_DEVICE.sql`·`GA4_EVENT.sql`. 부수 조치로 `DIM_DEVICE.sql`에서 `'(unknown)'` 제외(센티넬 SK=0과 **중복 행 방지**).
  - **회귀 검증**: 현 적재 실측 신·구 분류 100% 동일(WEB/mobile→M 222,756 · WEB/desktop→PC 37,694 · WEB/tablet→M 4,862).

**(2) ✅ 검토 결론: AGENCY 기기(공14)의 `DIM_DEVICE` 공용참조는 **타당**. 단 구현 근거가 사실과 다름**
- **설계 근거(타당)**: `03_테이블 설계.md` D13 `DIM_DEVICE`(PC/M/APP) + FAD grain `PERF_DATE × CAMPAIGN_SK × AD_CREATIVE_SK × DEVICE_SK` → FGA·FAD 공용 **conformed dimension**. 킴볼 정석이며, 광고 성과와 GA 행동을 동일 기기축으로 비교하려면 공용이 **필수**.
- **⚠️ 실측이 반박한 코드 주석**: `FACT_AD_PERFORMANCE.sql:6` — *"DEVICE_SK=0: AGENCY device 도메인 ≠ GA4 기반 DIM_DEVICE → 별도 매핑 필요"*. **사실과 다름**:

#### (2) 🔴 신규 결함군 — "GOLD 설계O·값 미주입"

기존 진단이 놓친 **제3의 결손 유형**이다. 종래 분류는 ①원천 부재 ②GOLD 미설계 뿐이었으나,
실제로는 **③설계·DDL 은 완료됐고 SQL 배선만 빠진 상태**가 76건 존재했다.

- **위험성**: DDL·문서상 컬럼이 존재하므로 **커버리지 점검을 통과**한다. 그러나 조회하면 전건 NULL/센티넬.
  즉 `11_BRONZE적재 컬럼대조.md` 가 "공백 없음"으로 판정한 것과 **모순 없이 공존**한다(역방향 vs 순방향, §8-I(5)).
- **해소 난이도가 가장 낮은 군**: DDL 변경 없이 SELECT 배선만으로 해소 가능 → **최우선 조치군**으로 지정.

AGENCY 9건은 **전량 BRONZE 실존이 확인**되어, dbt 주석의 "원천 부재" 단정이 오류임이 재확증됐다:

#### (3) 🔴→🟢 감사 도구 자체의 오탐 결함 — 전역 이름매칭의 함정

초기 구현(전역 컬럼명 매칭)은 **노출됨 153건**을 보고했으나, 검증 결과 **대부분 오탐**이었다.

| 오탐 사례 | 초기 판정 | 실제 | 원인 |
|---|---|---|---|
| `AGENCY.DEVICE` | 노출됨 | **하드코딩(전건 unknown)** | GOLD SQL 토큰에 `DEVICE` 출현 |
| `AGENCY.YEAR`·`MONTH`·`DAY` | 노출됨 | **대체노출**(DATE 파생) | `DIM_DATE.YEAR/MONTH/DAY` 와 동명이의 |
| `GA4.device` | 하드코딩 | **정상 노출** | `AGENCY.DEVICE` 와 컬럼명 충돌 |
| `AD_COST` | 하드코딩 | **모델별 상이** | FAD 실적재 / FBD 하드코딩 |

- **핵심 위험**: 미탐(false negative)은 "더 확인해야 함"으로 끝나지만, **오탐(false positive)은 실제 결손을 '정상'으로 은폐**한다.
  즉 감사 도구의 오탐은 감사를 **하지 않은 것보다 나쁘다**.
- **교정 설계 3종**:
  1. 계보 매핑 키에 **BRONZE 테이블 포함** → 원천 간 컬럼명 충돌 제거 (`AGENCY.DEVICE` ≠ `GA4.device`)
  2. 계보 매핑 값에 **GOLD 모델 포함** → 동명 컬럼의 모델별 하드코딩/실적재 구분 (`AD_COST`)
  3. 일반명(`YEAR`·`DATE`·`TEAM` 등)은 **`판정보류(동명이의)`** 로 격리 → 근거 불충분을 '노출됨'으로 반올림하지 않음
- 교정 후: 노출됨 153 → **18**, 신규 판정 `대체노출(파생)` 14 · `판정보류` 9 분리.

| ID | 패턴 | 내용 |
|---|---|---|
| **P15** | **"설계 완료 ≠ 값 존재" — 하드코딩 정적 스캔을 정례화** | DDL·문서에 컬럼이 있어도 SQL이 `0`/`CAST(NULL)`이면 값은 없다. 이 상태는 **문서 점검·커버리지 점검을 모두 통과**하므로 사람 리뷰로는 반복 누락된다. 모델 SQL 정적 스캔을 감사에 상설 포함할 것 |

#### (5) 역방향 충족 ≠ 순방향 노출 (P13 확장)

`11_BRONZE적재 컬럼대조.md`(CRM 전용·역방향)는 "BRONZE에 GOLD 필요 데이터 공백 없음"으로 결론했고 이는 **여전히 유효**하다.
본 감사(전 원천·순방향)는 "BRONZE 데이터가 GOLD에 노출되는가"를 물어 **미노출 612·⚠️값미주입 1**(순서9-II 보정 후)을 찾았다.
두 결론은 **모순이 아니라 질문이 다르다**. 문서 간 관계를 11번 문서 상단에 명시했다.
