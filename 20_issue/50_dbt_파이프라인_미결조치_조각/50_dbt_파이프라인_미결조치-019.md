### 🟠 [2026-08-25 O99] `SV_MEMBER_EVENT` 만 해소 — `SV_MEMBER_COHORT`·`SV_MEMBER_FEE`·
`SV_MEMBER_SPONSOR_BIZ` 는 동일 설계부채(캠페인 마스터 실시간 조인) 잔존

> 경위: O98 후속으로 `SV_MEMBER_EVENT`(base=`FACT_MEMBER_EVENT`)의 회원 개발이력
> 비정규화 9속성을 `campaign.*`(`DIM_CAMPAIGN` 실시간 조인) → `fme.*_AT_EVENT`
> (SILVER `CRM_MEMBER_DEV` 적재 시점 동결값)로 전환 완료. 그런데 같은 9속성 계열을
> 노출하는 **다른 SV 3종은 손대지 않았고, 애초에 `FACT_MEMBER_EVENT` 를 base 로 쓰지
> 않아 이번 조치의 범위 밖이었다.**

**① 잔존 위치 3종 (실측)**

| SV(설계문서) | base | 잔존 참조 | 경유 경로 |
|---|---|---|---|
| `05_3_SV_DDL_MEMBER_COHORT.sql` | `FACT_MEMBER_COHORT` | `acq_campaign.CAMPAIGN_TYPE`·`PARENT_CAMPAIGN_NAME`·`PROMO_METHOD_NAME`·`CAMPAIGN_INFLOW_PATH`·`DOMESTIC_OVERSEAS`·`BIZ_CASE_TYPE`·`MARKETING_CAMPAIGN` | `GOLD.DIM_MEMBER_ACQUISITION` → `DIM_CAMPAIGN` |
| `05_9_SV_DDL_MEMBER_FEE.sql` | `FACT_MEMBER_FEE` | `fee.ACQ_MARKETING_CAMPAIGN` | `GOLD.DIM_MEMBER_ACQUISITION` → `DIM_CAMPAIGN` |
| `05_10_SV_DDL_MEMBER_SPONSOR_BIZ.sql` | `FACT_MEMBER_SPONSOR_BIZ` | `campaign.CAMPAIGN_TYPE` | `GOLD.DIM_CAMPAIGN` 직접 |

**② 위험이 동일한 이유** — 세 SV 모두 캠페인 마스터(`DIM_CAMPAIGN`/`DIM_MEMBER_ACQUISITION`)를
**실시간 조인**해 값을 낸다. `TM_CM_CMPGN_MNG` 값이 나중에 정정되면 이 세 SV 는 **과거
회원 획득·회비·후원사업 사건의 캠페인 속성값도 조용히 따라 바뀐다** — O98 이전 `SV_MEMBER_EVENT`
와 동일한 결함 유형이다.

**③ O98 과 다른 점 — 왜 이번에 같이 안 고쳤나** — `SV_MEMBER_EVENT` 는 `FACT_MEMBER_EVENT`
자신이 이미 SILVER `CRM_MEMBER_DEV` 를 원천으로 삼아 `_AT_EVENT` 스냅샷 컬럼을 가질 수 있는
grain(사건 1건)이었다. `FACT_MEMBER_COHORT`·`FACT_MEMBER_FEE`·`FACT_MEMBER_SPONSOR_BIZ` 는
grain 이 다르고(획득 1건·회비 납입 1건·후원사업 결합 1건) **각 grain 에서 스냅샷 값을 어느
시점으로 동결할지(획득 시점? 회비 발생 시점?)가 별도 결정 사안**이라 이번 조치에 자동으로
포함되지 않는다.

**④ 조치 필요 (결정 대기)** — 아래 결정 없이는 착수 불가:
1. `DIM_MEMBER_ACQUISITION` 이 캠페인 속성을 **획득 시점 스냅샷**으로 가질지, 계속
   `DIM_CAMPAIGN` 실시간 조인으로 둘지 현업 확인.
2. 위 ①에서 결정되면 `DIM_MEMBER_ACQUISITION.sql`(dbt)에 스냅샷 컬럼 추가 →
   `05_3`·`05_9` 두 SV 를 `acq_campaign.*`/`fee.*` 대신 해당 컬럼으로 전환.
3. `FACT_MEMBER_SPONSOR_BIZ` 는 결합 시점 스냅샷이 필요한지 별도 확인 후 `05_10` 전환.
4. 세 SV 모두 O98/O99 와 동일하게 **친화명(synonyms) 유지 + 배포 후 `SEMANTIC_VIEW()` 스모크
   검증** 절차를 따를 것.

   `SV_MEMBER_SPONSOR_BIZ` 는 `CREATE OR ALTER` 재배포. 둘 다 owner `GN_DW_ADMIN` 보존 확인.
