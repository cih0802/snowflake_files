## R0. 셸 명령 안전 규칙 (모든 bash 호출 전 적용)

무한 대기의 최대 원인은 **미완결 셸 구문**이다.
예: `cd /workspace && for d in 05_SV-Agent_ai 02_GN_DW_building 10_dbt_pipeline`
→ `; do ... ; done` 이 없어 bash가 stdin에서 다음 줄을 계속 기다린다(`>` 연속 프롬프트).
실패가 아니라 **입력 대기 상태로 영구 정지**한다.

* **R0-1 구문 완결 필수**
  `for` → `; do ... ; done`, `if` → `fi`, `case` → `esac`, heredoc → 종료 구분자까지
  **하나의 명령 문자열 안에서 반드시 닫는다.**
  전송 직전 점검: 따옴표 짝, 괄호 짝, 백틱 짝, 파이프 뒤 피연산자 존재.
* **R0-2 루프 회피 (우선 선택)**
  여러 디렉터리·파일을 다룰 때 셸 루프를 쓰지 않고 루프 없는 단일 명령으로 대체한다.
  * 나열: `ls -d d1 d2 d3`
  * 탐색: `find -L /workspace/ -maxdepth 2 -name '*.yml'`
  * 검색: `grep -rn pat d1 d2 d3`
  * 대량 반복이 꼭 필요하면 셸 루프 대신 스크립트 파일을 작성해 1회 실행한다.
* **R0-3 stdin 차단**: 입력을 읽을 가능성이 있는 명령에 `</dev/null` 을 붙인다.
* **R0-4 타임아웃 강제**: `timeout 60 <cmd>` 로 감싸거나 `timeout_ms` 를 명시한다.
  60초 초과 예상 작업은 background 실행 후 폴링으로 처리한다.
* **R0-5 비대화형 강제**: `--no-pager`, `-y`, `-n`, `--quiet` 로 프롬프트·페이저를 차단한다.
  `git rebase -i`, `git add -i` 등 대화형 플래그 금지.
* **R0-6 정지 시 복구 절차** (타임아웃·무응답 시)
  1. **같은 명령 문자열을 재시도하지 않는다.**
  2. 구문 완결성을 먼저 재점검한다(R0-1).
  3. `echo ok` 또는 `ls -d <경로1>` 같은 최소 명령으로 환경 생존을 확인한다.
  4. 대상 경로를 하나씩 분해해 재실행한다.
* **R0-7 워크스페이스 파서 제약**
  dbt 명령에는 파이프·리다이렉트·`&&`·`;`·서브셸을 쓸 수 없다.
  단순 명령 1개만 사용하고 경로는 `--project-dir` 로 전달한다. `cd X && dbt ...` 금지.

## R4. 작업 흐름 제어 및 사후 처리

* **R4-1 dbt 정지점**: dbt 명령은 **에이전트가 실행하지 않는다 — 사용자가 직접 실행한다.**
  대상 = `dbt parse` · `dbt compile` · `dbt build`(및 `run`/`test` 등 모델을 만지는 명령 전부).
  해당 순서에 도달하면 **즉시 작업을 중단**하고, 실행할 명령을 그대로 제시한 뒤 사용자 입력을 기다린다. 선행 실행 금지.
  🆕 **2026-08-20 사용자 지시로 `parse`·`compile` 까지 확대**(이전에는 `build` 만 정지점이었다).
* **R4-2 이슈 갱신**: 큰 작업 종료 시 `20_issue/` 를 갱신한다. 후속 업데이트 필요 항목은 마커로 표기한다.
* **R4-3 응답 형식**: 작업 완료·대기 시 응답은 단답형으로 짧고 간결하게 출력한다.
* 🆕 **R4-4 세션 착수 브리핑과 조건부 STOP (2026-08-18 O85 신설 · 사용자 결정으로 착수표 ⑮ 확정)**
  · 🔎 **경위·실사고 근거 = `91_사고사례집.md` §C12**(`R2-8` 무변경 이관 · `O106`)
  * **R4-4-1 브리핑은 무조건 출력한다.** 어떤 지시가 와도 **Step 2 를 읽고 브리핑을 먼저 낸다.**
    브리핑은 **Step 2 독해의 산출물**이므로, 생략은 「출력을 아꼈다」가 아니라 **미독의 증거**다.
  * **R4-4-2 지시 동봉 여부로 그 다음 행동을 가른다.**
    · **지시 없음** ⇒ 브리핑 후 **STOP**, 사용자 지시를 기다린다.
    · **지시 동봉** ⇒ 브리핑 후 **되묻지 않고 즉시 수행한다.** 확인 질문은 **작업과 병행**해서 낸다
      (진행을 막는 질문은 어느 가정으로도 안전하지 않을 때만 한다).
  * **R4-4-3 🔴 파괴 가능 작업은 이 완화의 예외다 — 지시가 동봉돼도 별도 승인을 받는다.**
    대상 = 파일 discard · `rm` 계열 · `ALTER WORKSPACE … ABORT` · `--rebalance`·`--rollover`·
    `retire_rows.py` 처럼 **다중 파일을 재작성하는 유지 연산** · 라이브 객체 `DROP`/`REPLACE`.
    ⇒ **이 예외가 `R4-4-2` 보다 강하다.** 되돌릴 수 없는 것에는 완화를 적용하지 않는다.
  * **R4-4-4 🟠 롤백 조건을 함께 정한다(사용자 지시).** 이 완화로 **에러·재작업이 눈에 띄게 늘면
    `R4-4-2` 의 「지시 동봉」 분기를 철회**하고 무조건 STOP 으로 되돌린 뒤 방식을 다시 정한다.
    ⇒ 판단 근거를 남기기 위해 **이 분기로 진행한 세션은 이력 항목에 그 사실과 확정위반 건수를 적는다.**
    🔴 **근거 없이 「괜찮다」고 유지하지 마라** — 롤백 판단도 실측으로 한다(`R2` 축).
