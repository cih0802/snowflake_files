## R0. 셸 명령 안전 규칙 (모든 bash 호출 전 적용)

무한 대기의 최대 원인은 **미완결 셸 구문**이다.
예: `cd /workspace && for d in 05_SV-Agent_ai 02_GN_DW_building 10_dbt_pipeline`
→ `; do ... ; done` 이 없어 bash가 stdin에서 다음 줄을 계속 기다린다(`>` 연속 프롬프트).
실패가 아니라 **입력 대기 상태로 영구 정지**한다.

* **R0-1 구문 완결 필수**
  `for` → `; do ... ; done`, `if` → `fi`, `case` → `esac`, heredoc → 종료 구분자까지
  **하나의 명령 문자열 안에서 반드시 닫는다.**
  전송 직전 점검: 따옴표 짝, 괄호 짝, 백틱 짝, 파이프 뒤 피연산자 존재.
* **R0-2 루프 회피 (우선 선택)**
  여러 디렉터리·파일을 다룰 때 셸 루프를 쓰지 않고 루프 없는 단일 명령으로 대체한다.
  * 나열: `ls -d d1 d2 d3`
  * 탐색: `find -L /workspace/ -maxdepth 2 -name '*.yml'`
  * 검색: `grep -rn pat d1 d2 d3`
  * 대량 반복이 꼭 필요하면 셸 루프 대신 스크립트 파일을 작성해 1회 실행한다.
* **R0-3 stdin 차단**: 입력을 읽을 가능성이 있는 명령에 `</dev/null` 을 붙인다.
* **R0-4 타임아웃 강제**: `timeout 60 <cmd>` 로 감싸거나 `timeout_ms` 를 명시한다.
  60초 초과 예상 작업은 background 실행 후 폴링으로 처리한다.
* **R0-5 비대화형 강제**: `--no-pager`, `-y`, `-n`, `--quiet` 로 프롬프트·페이저를 차단한다.
  `git rebase -i`, `git add -i` 등 대화형 플래그 금지.
* **R0-6 정지 시 복구 절차** (타임아웃·무응답 시)
  1. **같은 명령 문자열을 재시도하지 않는다.**
  2. 구문 완결성을 먼저 재점검한다(R0-1).
  3. `echo ok` 또는 `ls -d <경로1>` 같은 최소 명령으로 환경 생존을 확인한다.
  4. 대상 경로를 하나씩 분해해 재실행한다.
* **R0-7 워크스페이스 파서 제약**
  dbt 명령에는 파이프·리다이렉트·`&&`·`;`·서브셸을 쓸 수 없다.
  단순 명령 1개만 사용하고 경로는 `--project-dir` 로 전달한다. `cd X && dbt ...` 금지.

## R1. 사전 준비 및 정보 파악

* **R1-1** 작업 시작 전 반드시 `20_issue/` 를 먼저 읽고 미해결·pending 항목을 파악한다.
* **R1-2** 지시가 `20_issue/` 와 충돌하면 `20_issue/` 를 우선하거나 사용자에게 문의한다. 임의 판단 금지.
* **R1-3 문서 전량 읽기 (파일 종류 무관)**
  `.md`, `.sql`, `.yml`, `.py`, `.csv` 등 **모든 파일**에 적용한다. 특정 문서에 한정되지 않는다.
  * **R1-3-1 전량 확보 필수**: 파일은 처음부터 끝까지 읽는다. 중간에 끊긴 상태에서 나머지 내용을 추론·단정하지 않는다.
  * **R1-3-2 분할 읽기로 이어 읽기**: `read` 툴은 1회 호출당 **최대 2000줄**, **1줄당 2000자**까지만 반환한다.
    이 한도로 잘리면 `offset`/`limit` 을 옮겨 **끝까지 반복 호출**해 전량 확보한다.
    이는 시간 제약(R0-4 `timeout 60`)과 **무관한 별개 문제**다. 시간을 이유로 읽기를 중단하지 않는다.
  * **R1-3-3 줄 수 선확인**: 대용량 파일은 `timeout 60 wc -l <경로>` 로 총 줄 수를 먼저 확인하고,
    필요한 호출 횟수를 계산해 전량 읽었는지 자가 검증한다.
  * **R1-3-4 bash 로 문서 읽기 금지**: `cat`/`head`/`tail` 은 출력 절단으로 내용이 손실된다.
    내용 파악은 반드시 `read` 툴을 쓴다. bash 는 줄 수·크기 확인 용도로만 쓴다.
  * **R1-3-5 부분 읽기 명시**: 사용자가 특정 구간만 요청한 경우에만 부분 읽기를 허용하고, 그 사실을 응답에 명시한다.
  * **R1-3-6 이력 파일 예외 (2026-08-11 O59-J 신설)**
    전량 독해 의무는 **정본**에만 적용한다. 정본 = 본 지침 · `20_issue/00_INDEX_이슈원장.md`(인덱스) ·
    `10_진단_원인분석.md` · `30_설계_의사결정.md` · `31_코드군_매핑등재부.md` · `40_…` · `50_dbt_…md` · `99_NEXT_SESSION.md`.
    **append-only 이력 파일**(`20_issue/01_세션이력.md`)은 **필요한 세션 구간만** 읽는다.
    * 🔴 **왜 예외가 필요한가**: 이력이 정본과 한 파일에 섞여 있어 원장이 **4,686줄/612KB** 까지 커졌고,
      `read` 1회 한도(2,000줄·1줄 2,000자·출력 10만자)를 넘겨 **R1-3 이 여러 세션 연속 미충족**이었다.
      예외를 명문화하지 않으면 다음 세션도 같은 곳에서 막히거나, **읽지 않고 읽은 척하게 된다.**
    * ⚠️ **예외의 한계**: 이력에서 **판정·수치를 근거로 인용하려면 그 세션 항목 전체를 읽는다.**
      부분 인용은 P170(분모 미확인 반박)·P154 오판의 실제 경로였다.
    * 🔴 **이력이 다시 커지면 정본이 아니라 이력을 쪼갠다.** 정본 파일이 1회 read 한도를 넘기면
      그것은 **정본에 이력이 섞였다는 신호**다 ⇒ 분리 대상이다(성격 혼합이 원인이고 크기는 증상이다).
  * **R1-3-7 읽기 반환 실패 = 미독 (2026-08-13 O69 신설 · R1-3-1 의 집행 장치)**
    `read` 호출이 **본문을 돌려주지 않은 경우**는 「읽었다」가 아니라 **「읽지 못했다」**로 취급한다.
    실패 형태 = ㉠ `edited out to manage context size` 로 대체됨 ㉡ `Output too large` 로 파일 경로만 반환됨
    ㉢ 미리보기(preview)·꼬리만 반환됨. **호출한 사실은 확보한 사실이 아니다.**
    * 🔴 **왜 필요한가 (O69 실사례)**: `read` **11회 중 10회**가 컨텍스트 관리로 삭제 반환됐는데
      그 상태로 「지침 로드 OK · 전량 독해 4건」이라 보고했다. 그 결과 브리핑의 근거가 정본이 아니라
      **사용자가 붙여넣은 대화 로그**였고, 착수표 범위(`⓪~⑩`)를 `⓪~⑨` 로 틀리게 적었다.
      R1-3-6 이 경고한 **「읽지 않고 읽은 척」** 이 실제로 났고, 그 실패가 **조용했다**(에러가 아니다).
    * **판정 절차**: 매 호출 직후 **본문이 실제로 왔는지**를 확인한다. 오지 않았으면
      `limit` 을 절반 이하로 줄여(권장 **60~100줄**) 같은 구간을 재호출한다. 이는 R0-6 의
      「같은 명령 재시도 금지」와 다르다 — **분할 크기를 바꾼 다른 호출**이다.
    * **복구 실패 시**: 그 파일을 **미독으로 명시**하고, 그 파일 소관 사실·수치·판정을
      **인용하지 않는다**(참조형 언급만 허용). 미독 사실을 응답과 인수인계에 **함께** 적는다.
    * 🔴 **대체 근거 금지**: 사용자가 붙여넣은 로그·이전 응답·기억은 정본의 대체물이 아니다.
      정본을 못 읽었으면 **그 수치를 다시 쓰지 말고 재측정하거나 판단을 보류**한다.
    * 🆕 **R1-3-7-a 미반환 좌표 기록 의무 (2026-08-13 O70-B 신설 · 이 조문의 집행 장치)**
      반환 실패가 난 **파일·`offset` 좌표와 총 건수**를 응답과 인수인계에 **숫자로 적는다**.
      🔴 **왜 필요한가**: O70 은 `read` **39회 중 19회**가 삭제 반환이었는데 복구 절차를 **0회** 실행하고,
      원장에는 *"미반환 2회는 재호출해 확보했다"* 라고 **거짓으로 적었다**(문서50 §O70-B A1·A2).
      건수를 적지 않으면 「몇 번 실패했는지」가 사라지므로 **미실행이 조용해진다** — R1-3-7 이 막으려던 것과 같은 구조다.
      * 판정식 = **재호출 건수 ≥ 미반환 건수**. 충족하지 못하면 「전량 확보」라고 쓰지 않고
        **「도착 실증 · 복구 절차 미실행」**으로 구분해 적는다(둘은 다른 상태다).
      * 도착을 다른 방법으로 실증했다면(편집 앵커 전건 일치 · 그 구간 고유 발견) **그 근거를 명시**한다.
        🔴 실증은 **면제 사유가 아니라 완화 사유**다. 재호출을 대신하지 않는다.
* **R1-4 ID 발급 게이트 (2026-08-12 O62 신설 · P220 의 집행 장치)**
  `DEC`·`P`·`O`·`Q` 등 **ID 를 새로 부여하기 전에** 아래를 실행한다. 기억·인접 문맥은 근거가 아니다.
  ```
  python3 scripts/id_collision_gate.py            # 착수·종료 게이트 (중복 시 exit 1)
  python3 scripts/id_collision_gate.py --next DEC # 그 계열의 다음 발급 번호
  ```
  * **R1-4-1 차단 강도 = blocking.** 동일 문서가 같은 ID 를 두 번 정의하면 실패(exit 1)다.
    승격 근거 = 선례 관례 「**위반 0 을 먼저 실측한 뒤 올린다**」(`AGENCY_AD_PERFORMANCE.AD_DATE`
    warn→error 승격 · 문서50). 2026-08-12 실측 = 중복 **0건** 확인 후 blocking 으로 넣었다.
  * **R1-4-2 「다음 발급」은 정의·참조 두 최대값 중 큰 값 +1 이다.** 한쪽만 보면 양방향으로 틀린다
    (정의 기준은 과소 — `O61` 이 이력 항목을 안 남겨 59 로 보였다 / 참조 기준은 과대 — 본문 수치 혼입).
  * **R1-4-3 세션 라벨은 이 게이트로 보증되지 않는다.** 한 세션이 작업 단위별로 여러 이력 항목을
    쓰는 것이 정상이라 중복 검사 대상이 아니고, 진짜 사고(**같은 날 다른 세션이 같은 라벨을 집음**)는
    한 워크스페이스 스냅샷으로 탐지할 수 없다. ⇒ **라벨은 선점으로 막는다**: 착수 시 `--next O` 로
    확인한 라벨을 원장에 **한 줄로 먼저 등재**(선착순 확정)한 뒤 작업한다. 스캔만으로는 경합이 남는다.
* **R1-5 문서 작성 시 한 줄 2000자 가드 (2026-08-13 신설 · R1-3 의 쓰기 측 대칭 규칙)**
  `.md`, `.sql`, `.yml`, `.py`, `.csv` 등 **생성·수정하는 모든 파일**에 적용한다.
  * **R1-5-1 한 줄 2000자 초과 금지.** 목표는 1줄 **1000자 이내**(안전 마진), 절대 상한 2000자다.
  * **R1-5-2 왜 필요한가**: `read` 툴은 **1줄당 2000자에서 절단**한다(R1-3-2). 2000자를 넘는 줄을 쓰면
    그 줄은 **다음 세션에서 전량 확보가 불가능**해지고, `offset`/`limit` 재호출로도 복구되지 않는다
    (줄 단위 절단이라 이어 읽기가 듣지 않는다). ⇒ **쓰는 쪽에서 R1-3 을 구조적으로 깨는 행위**다.
    R1-3-6 의 교훈과 같은 축이다: 크기는 증상이고 **원인은 한 덩어리로 몰아쓴 형태**다.
  * **R1-5-3 분할 기준**: 긴 문장은 문단·항목·절 단위로 개행하고, 표는 **행마다** 개행한다.
    긴 SQL·코드는 절(`SELECT`/`FROM`/`WHERE`/`JOIN`)·컬럼·인자 단위로 개행한다. 한 줄 몰아쓰기 금지.
    긴 나열은 쉼표 나열 대신 불릿 또는 표 행으로 분해한다.
  * **R1-5-4 쓰기 후 검증 필수 (blocking)**: 파일 생성·수정 직후 아래를 실행한다.
    ```
    timeout 60 awk 'length($0)>2000 {print FILENAME": "FNR": "length($0)}' <경로> </dev/null
    ```
    **출력이 비어야 통과**다. 초과 줄이 나오면 그 자리에서 개행 분할하고 재검증한다.
    초과 줄을 남긴 채 완료 보고하지 않는다(R3-3 「마커만 남기기 금지」와 동일 취지).

## R2. 데이터 작업 및 검증 (실측 중심)

* **R2-1 사전 검증 우선**: 정본(yml 등)만으로 검증 가능한 항목은 **산출물 생산 전에** 검증한다.
  `dbt build` 를 단순 검증기로 사용하지 않는다.
* **R2-2 사후 검증 한정**: 물리적 반영 확인처럼 산출물 실체가 필요한 검증만 생산 이후에 수행한다.
* **R2-3 원본 실측**: COMMENT나 문서를 근거로 단정하지 않는다. `BRONZE` 스키마 원본을 직접 스캔한 결과만 근거로 삼는다.
* **R2-4 완료 판정 기준**: 완료 기준은 문서 작성이나 DDL 실행 여부가 아니라 **실제 스캔 결과**(INFORMATION_SCHEMA 스캔, P33)다.
* **R2-5 파일 상태 검증**: 파일 생성·수정 후 반드시 `cortex ws ls` 로 스테이지 실체를 확인한다(§9 P102).
  `/workspace` 마운트의 `ls` 성공은 스테이지 반영을 의미하지 않는다.
  같은 시점에 **R1-5-4 한 줄 2000자 검증**도 함께 실행한다(존재 확인 + 가독 확인은 한 쌍이다).
* **R2-6 메타데이터 분리**: 코드 COMMENT에는 코드값만 기록한다. 실측 수치는 문서10과 이슈 원장에만 기록한다.
* **R2-7 NULL 규약 (2026-08-12 O62 신설 · 사용자 결정)**
  * **R2-7-1 데이터는 NULL 이면 NULL 로 둔다.** 값이 없는 자리를 `'미상'`·`'알 수 없음'` 같은 문자열로
    **창작하지 않는다.** 창작한 라벨은 「값을 모른다」로 읽히지만 실제로는 원인이 서로 다른 여러 사건
    (원천 미보유 · 개념 부재 · 조인 실패 · 센티넬)을 **한 값으로 뭉개** 분석을 조용히 망친다.
  * **R2-7-2 NULL 의 「이유」는 그 컬럼의 COMMENT 에 컬럼별로 쓴다.** 데이터에 쓰지 말고 메타데이터에 쓴다.
    이유는 컬럼마다 다르므로 **한 문장을 여러 컬럼에 복사하지 않는다.**
    실측 예(`DIM_MEMBER_CURRENT` · 2026-08-12):
    · `MEMBER_STATUS_NAME`·`ENROLL_PATH_NAME` = 일시회원(`ONCE`) 175,722행은 **원천에 개념 자체가 없어**
      센티넬 `(해당없음)` 이고, 그와 별개로 정기회원 중 코드 결손 **1행**만 진짜 NULL 이다.
    · `REGION`·`AGE_BAND` = `ONCE` 는 **개념은 있고 원천 행이 없어** NULL 이다(`(해당없음)` 이 아니다).
    ⇒ 두 경우는 뜻이 다르므로 COMMENT 문안도 달라야 한다.
  * **R2-7-3 표기 축을 혼동하지 않는다.** `(미매핑)` = 차원 마스터 **조인 실패**(`SK=0` 시드 멤버) ·
    `(해당없음)` = **개념 부재** · `NULL` = 값 없음. 세 축은 서로 대체물이 아니다.
  * **R2-7-4 COMMENT 는 주장 발행이다(P212).** 값 목록·미매핑 처리 방식을 쓰기 전에 **라이브를 실측**한다.
    🔴 이 규칙이 없어서 실제로 무슨 일이 있었나: `06_DDL.sql` 이 *"미매핑은 `'미상'`"* 을 4곳에 선언했지만
    라이브 실측은 `'미상'` **0건**·`(미매핑)` **0건**이었고, **같은 파일 198행은 정반대**로
    *"`'미상'` 으로 창작하지 않는다"* 를 적고 있었다. Agent 는 이 COMMENT 를 답변 근거로 쓴다.
* **R2-8 정본 이관 무결성 (2026-08-13 O70-B 신설 · P107 의 집행 장치)**
  절·표·판정을 **다른 문서로 옮기고 원본을 삭제·축소**할 때 아래를 **삭제 전에** 실행한다.
  🔴 **왜 필요한가**: O70 이 `99_NEXT_SESSION.md` §0-G·§0-H 를 문서50 으로 옮기며 **원문을 삭제**했는데
  삭제 전 중복 실재를 **기계로 확인하지 않았다**(문서50 §O70-B A3). O62 는 같은 작업에서
  `grep` 매칭 110행으로 확인한 **선례가 있었다** ⇒ 선례가 있는데 지켜지지 않은 것은 조문이 없었기 때문이다.
  * **R2-8-1 삭제 전 토큰 대조**: 원본 구간의 **수치·ID·좌표 토큰**을 추출해 목적지에 실재하는지 대조한다.
    한 건이라도 부재면 **삭제하지 않는다**. 대조 결과(대상 토큰 수 · 실재 수)를 원장에 적는다.
  * **R2-8-2 「무변경 이관」은 기계 대조로만 주장한다.** 문장을 재작성하거나 항목을 가필했으면
    **「이관 + 가필」로 적는다.** O70 은 §O69 에 없던 항목을 신설하고도 「판정·수치 무변경」이라 적었다(A4).
  * **R2-8-3 되돌릴 수 없음을 전제로 판단한다.** 원본이 삭제되면 그 문장은 **워크스페이스에서 사라진다**
    (이력 항목은 요약이라 대체물이 아니다) ⇒ 확신이 없으면 **원본을 남기고 포인터만 추가**한다.

## R3. 단계 종료 게이트 (로드맵 각 단계 완료 시 필수)

아래 6개를 즉시 자문하고 **모두 통과해야만** 다음 단계로 넘어간다.
하나라도 미통과면 그 자리에서 조치하고 재검한다.

3. 알아낸 수정을 마커만 남기고 미이행했는가? → 마커만 남기기 금지, 즉시 이행(P105).
4. 생성한 게이트를 **대상이 존재하는 상태**에서 실행했는가?(P106)
5. 새로 발견한 사항을 `20_issue/` 에 등재했는가?
6. 이 단계에서 만든·고친 파일에 **2000자 초과 줄이 남아 있는가?** → R1-5-4 검증 실행, 출력이 비어야 통과.
