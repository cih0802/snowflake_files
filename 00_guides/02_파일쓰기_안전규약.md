# R1-7 파일 쓰기 안전 규약 (쓰기 절차 스펙)

> 🔴 **이 문서는 `00_작업지침_세션운영규칙.md` 에서 `R1-7` 전체를 무변경 이관한 것이다**
> (2026-08-18 O85 · `R2-8` 토큰 대조 통과 · 조문 번호·본문 **한 글자도 바꾸지 않았다**).
> **왜 분리했나**: 지침이 다시 **33,539B / 여유 7,421B** 까지 커져 `doc_type_gate` 축3 경고가 났고,
> `R1-7` 은 그중 **9,409B(28%)** 로 단일 최대 계열이었다.
> 🟢 **이관해도 세션 시작 시 가용성이 줄지 않는다** — `init_ihcho` **Step 0.7** 이 이 9개 조문을
> **요약 형태로 전부 재수록**하고 있어서, 매 세션 첫 행동에서 이미 노출된다.
> ⇒ 지침에는 포인터 + 조문 제목 목록만 남기고 상세는 여기로 옮겼다.
> **파일을 쓰기 전에, 그리고 쓰기 사고를 조사할 때 이 문서를 읽는다.**
> ⚠️ 조문 번호는 `R1-7-*` 그대로다 — 다른 문서의 `R1-7-N` 인용이 **전건 유효**하다(`O59-K` 리네임 금지).
> 🔴 **이 문서는 갱신형이다** — 새 조문은 **번호 순서 말미**에 덧붙인다(`R1-7-8` · `clause_order_gate`).

---

* **R1-7 파일 쓰기 안전 규약 (2026-08-18 O82-B 신설 · `C5`·`C6`·`C7` 의 조문화)**
  🔴 **왜 필요한가**: 이 워크스페이스에서 원장이 **4회** 깨졌고 전부 같은 뿌리였다 —
  `A13`(인덱스 꼬리 10줄 소실) · `A15`(O76 행 덮어쓰기 + O76-B 행 중복) ·
  `O82` 편집 2건 소실(O76-C 재작성) · `doc_line_length_gate` 분모 14파일 소실(파일 단위 discard).
  네 건 모두 **기존 게이트를 전부 통과**했다 ⇒ 규율이 없으면 조용히 재발한다.
  * **R1-7-1 전체 재작성(`write`) 금지 · 부분 치환(`edit`) 기본.**
    정본·원장 파일을 `open().read()` → 수정 → `write()` 로 갱신하지 않는다.
    🔴 근거 = **`C5`** — 이 워크스페이스의 파일 읽기는 **조용히 부분 반환**할 수 있다.
    짧게 읽힌 버퍼를 그대로 쓰면 **꼬리가 잘린다**(`A13` 이 실제로 이렇게 났다).
    `write` 툴은 **신규 파일**에만 쓴다. 기존 파일은 `edit` 로 필요한 구간만 바꾼다.
  * **R1-7-2 쓰기 전 해시 안정성 확인 (blocking).**
    같은 파일을 **2회 이상** 읽어 **크기·SHA256 이 동일**해야 착수한다. 다르면 **중단**한다.
    다름 = 부분 반환 중이거나 **타 세션이 지금 쓰고 있다**는 뜻이다.
  * **R1-7-3 「손상」 판정 전에 재읽기 (2026-08-18 O82-B 실패 경로).**
    UTF-8 절단·줄 수 급감을 보면 **손상으로 단정하기 전에 2~3회 재읽어 해시를 대조**한다.
    🔴 O82 는 타 세션이 인덱스를 **재작성하는 중에 읽어** 찢어진 버퍼(torn read)를 받고
    **「꼬리 10줄 영구 소실」로 오판**했다. 실제로는 파일이 온전했고, 그 오판으로
    **사용자에게 불필요한 복원 작업을 요청**했다. 재읽기 3회면 막을 수 있었다.
  * **R1-7-4 쓰기 후 행 키 게이트 (blocking).**
    원장 표를 건드렸으면 아래를 실행한다. 제목·길이·크기 게이트는 **행 소실을 못 잡는다**.
    ```
    timeout 60 python3 scripts/index_row_gate.py
    ```
    🔴 **FAIL 을 `--update-golden` 으로 덮지 마라** — 사고를 기준선으로 만드는 행위다.
    소실 행을 `edit` 로 되살린 뒤 재실행한다.
    ⚠️ **의도적 삭제와 사고를 이 게이트는 구별할 수 없다**(2026-08-18 O82-C 실측 · 첫 삭제 시 발견).
    ⇒ 갱신형 원장에서 낡은 행을 정리할 때는 **행을 지우지 말고 「행 키를 보존하고 내용을 대체」**한다
    (`| 같은 첫 셀 | ~~낡은 값~~ | … | ✅ 대체됨 + 사유 |`). 원장은 append·갱신형이고 좌표가 인용되므로
    행 키 보존이 게이트 편의가 아니라 **인용 안정성** 문제다. 진짜로 지워야 하면 **원장에 사유를 먼저 적고**
    골든을 갱신한다 — 사유 없이 골든을 갱신하면 다음 세션이 그 유실을 정상으로 읽는다.
  * **R1-7-5 타 세션 토큰 보존 단정.**
    이 원장은 **다른 세션이 동시 편집한다**(`C7`). 쓰기 전 착수 시점의 **최신 라벨·절 제목**을
    목록화하고 쓰기 후 **전건 잔존**을 확인한다.
    🔴 **토큰 1개로 단정하지 마라** — O76-C 는 문자열 `O82` **하나**만 검사해 「보존 5/5」로
    통과시켰고, `O82` 를 포함하지 않는 편집 **2건이 그 단정을 통과해 사라졌다**.
    ⇒ 단정 대상은 **행 키 집합**이어야 한다(R1-7-4 가 그 자동화다).
  * **R1-7-6 파일 단위 discard 는 파괴적이다 — 사용자에게 먼저 알린다.**
    Snowsight 의 파일 change discard 는 「내 변경 취소」가 아니라 **그 파일의 미커밋 변경 전부 취소**다.
    🔴 `USER$` 워크스페이스는 **`head` == `live`** 여서(2026-08-18 `LIST` md5 동일 실측)
    **redo 경로가 없다.** Time Travel 도 적용되지 않고, 파일별 버전 이력은 **Git 연동 워크스페이스에만** 있다.
    ⇒ discard 를 제안·수행하기 전에 **되돌릴 수 없음과 타 세션 작업까지 지워짐**을 명시한다.
    ⚠️ `ALTER WORKSPACE … ABORT` 는 **워크스페이스 전체**의 미커밋 변경을 날린다 — 사용자 명시 승인 없이 금지.
  * 🆕 **R1-7-7 `rm -rf` 는 discard 와 같은 등급의 파괴 명령이다 (2026-08-18 O83-E 신설)**
    🔴 **왜 필요한가**: `R1-7-6` 이 discard 만 경고했기 때문에 `rm -rf` 를 **조문에 없다는 이유로**
    무의식적으로 안전하다고 가정했다. 그 결과 `rm -rf 20_issue/01_세션이력` 한 번에 **허브 파일이
    스테이지에서 함께 삭제**됐다(스테이지의 「폴더」는 **경로 접두**이고 그 접두가 `01_세션이력.md` 를
    포함한다). 스냅샷 대조로 복원해 손실은 0 이었지만, **조문의 빈틈을 근거로 삼은 것**이 실패의 뿌리다.
    * 🔴 **삭제 전에 「그 경로 접두로 무엇이 걸리는가」를 먼저 나열한다** — `os.listdir` 로 실측한다.
      `rm -rf <경로>` 는 그 경로**로 시작하는 모든 스테이지 객체**를 지운다고 가정하라.
    * 🔴 **디렉터리 통삭제 대신 파일 개별 삭제**를 기본으로 한다.
    * ⚠️ **삭제 직후 `ls` 는 낡은 뷰를 돌려준다**(`OPS-3`) — `os.listdir` + `cortex ws ls` **두 축**으로 확인한다.
    * 🟢 **일반화**: 조문에 없다는 것은 **안전하다는 근거가 아니다.** 파괴 가능성이 있는 명령은
      조문 유무와 무관하게 **영향 범위를 먼저 실측**한다.
  * 🆕 **R1-7-8 `edit` 앵커는 「직전 줄까지」 포함하고, 편집 직후 제목 게이트를 돌린다 (2026-08-18 O83-H 신설)**
    🔴 **왜 필요한가**: 이 워크스페이스에서 `edit` 의 `old_string` 을 좁게(치환 대상 첫 줄만) 잡아
    **절·조문 제목줄을 덮어써 지운 사고가 한 세션에 4회** 발생했다(`R1-6-13` 2회 · 좌표 환산표 · `R1-6-17`).
    전부 즉시 복원했지만 **탐지가 「눈으로 보기」에 의존**했고, 표 행에서는 **꼬리가 붙어 행이 중복**되기도 했다.
    🔴 **`doc_heading_gate` 가 바로 이 축을 잡는데, 나는 작업 끝에만 돌렸다** —
    게이트가 없어서가 아니라 **늦게 써서** 놓쳤다. 게이트는 **가까이 둘 때만** 값을 한다.
    * **앵커에 「바꾸려는 줄 + 그 직전 줄(또는 소속 제목줄)」을 함께 넣는다.** 첫 줄만 넣지 않는다.
    * **긴 표 행을 바꿀 때는 행 전체를 앵커로 넣는다** — 접두만 넣으면 **꼬리가 남아 붙는다**(실측 사고).
      행이 너무 길어 앵커로 넣기 어려우면 `edit` 대신 **python 으로 그 줄 인덱스를 지정해 치환**한다.
    * 🔴 **문서 편집 직후**(작업 끝이 아니라 **그 자리에서**) 아래를 돌린다.
      ```
      timeout 180 python3 scripts/doc_heading_gate.py     # 제목 유실
      timeout 120 python3 scripts/index_row_gate.py       # 표 행 유실·중복
      ```
    * 🟢 **일반화**: **게이트를 언제 돌리는지가 게이트의 성능이다.** 끝에 한 번 돌리면
      「어느 편집이 깼는지」를 잃고 복구 비용이 커진다.
    🔴 **이 조문은 5번째 재발 직후에 확정됐다** — 바로 이 `R1-7-8` 을 삽입하면서
    `R1-7-7` 제목줄을 또 덮어썼다(즉시 복원). **조문을 쓰는 행위 자체가 그 조문의 반례였다.**
    🟢 **[O83-H 후속] 이 조문의 「위치」도 그 사고의 잔재였다** — 복원 과정에서 `R1-7-8` 이 `R1-7-7` **앞**에 놓여 번호와 문서 순서가 어긋났다(같은 유형이 규약 `R1-6-18`↔`R1-6-17` 에도 있었다 · 둘 다 O83-H 에서 정렬). ⇒ **조문은 번호 순서 말미에 덧붙인다** — 중간 삽입은 그 자체가 앵커 사고의 신호다.
  * 🆕 **R1-7-9 백틱·`$`·`!` 를 포함한 본문은 셸을 경유시키지 않는다 (2026-08-18 O83-H 신설)**
    🔴 **왜 필요한가**: 이력 §O83-H E 절을 `bash -c "python3 -c '...'"` 로 기록했을 때
    본문의 **백틱 구간이 bash 명령치환으로 해석되어 23줄에서 전부 삭제**된 채 파일에 써졌다.
    조문 번호(`R1-6-17` 등)와 코드 식별자가 **통째로 사라져 문장이 무의미해졌다**(즉시 되돌림 · 손실 0).
    🔴 이 워크스페이스의 문서는 **백틱이 매 줄에 있다** ⇒ 이 경로는 상시 위험이다.
    * **본문을 쓸 때는 `write` 도구로 파일에 쓰거나, 스크립트 파일을 만들어 실행한다.**
      `bash -c` 안의 인라인 python 문자열에 문서 본문을 넣지 않는다.
    * ⚠️ 작은따옴표로 감싸도 **바깥이 큰따옴표면 백틱은 여전히 해석된다** — 중첩 인용은 방어가 아니다.
    * 🔴 **쓴 뒤에 그 구간을 되읽어 백틱·식별자가 살아 있는지 확인한다**(`R1-7-3` 과 같은 축:
      성공 메시지는 「줄 수가 맞다」만 증명하고 **내용이 온전한지는 증명하지 않는다**).
    🟢 **일반화**: `R1-7-8` 은 **앵커**(어디를 바꾸나)를 다뤘고 이 조문은 **전달 경로**(어떻게 넣나)를
    다룬다. 같은 편집 사고가 두 축에서 따로 났다 — **경로에도 게이트가 필요하다.**

  * 🆕 **R1-7-10 스냅샷은 `scripts/snapshot_util.py` 만 경유한다 (2026-08-28 O110 신설)**
    🔴 **왜**: `_archive/` 스냅샷은 이 워크스페이스의 **유일한 되돌리기 수단**이다
    (`R1-7-6` — `USER$` 는 `head == live` 라 redo 경로가 없다). 그런데 종전 구현들은
    ㉠ 세션 라벨을 **소스에 하드코딩**하고 ㉡ `shutil.copyfile`/`write_text` 로
    **기존 스냅샷을 경고 없이 덮었다**. 실증 = O108 이 `00_INDEX` 를 3회 republish 해
    **최초 상태가 이미 없다** · O109 의 재균형 스냅샷이 `…O83B-prerebalance` 로 남아
    **「누가 만들었나」가 거짓**이 됐다.
    * **라벨은 인자로 받는다** — 해소 순서 = `--label` → 환경변수 `SESSION_LABEL` →
      `UNLABELED`(경고만 내고 **중단하지 않는다** · 스냅샷을 못 남기는 것이 더 나쁘다).
      🔴 `add_argument('--label', default='O1NN')` 처럼 **지난 세션 라벨을 기본값으로 두지 마라.**
    * **절대 덮지 않는다** — 바이트 동일이면 재사용(`reused`) · 다르면 `.2`·`.3` 접미 ·
      접미가 소진되면 **예외로 중단**한다(조용한 소실보다 실패가 낫다).
    * 파일은 `snapshot(path, op, label=…)`, 메모리 내용은 `snapshot_content(name, op, data, …)`.
    * 🔴 **`archive=` 를 넘겨라** — 호출부 모듈의 `ARCHIVE` 를 명시하지 않으면 테스트가
      패치한 임시 경로를 벗어나 **실 `_archive/` 에 잔재를 만든다**(O109 실사고).
    🔴 **전수 조사 의무**(`R1-6-17 ㉡`): 스냅샷을 쓰는 도구는 **전부** 이 경로를 쓴다 —
    O109 는 `split_doc` 만 배선하고 나머지 **4종을 손대지 않은 채 「고쳤다」고 보고**했다.
    🟢 이 조문은 **음성 테스트가 집행**한다 = `scripts/test_snapshot_util.py` 축7·축8
    (헬퍼 import + 우회 경로 0 + 라벨 기본값 하드코딩 0 을 도구별로 단정).
