# BRONZE 기준년월 보유 테이블·컬럼 인벤토리 (yyyyMM 준수 실측)

> 판정 대상 = **BRONZE 계층에서 「연·월」 의미를 갖는 컬럼**이 `yyyyMM` 6자리 규격을 따르는가.
> 근거는 카탈로그 COMMENT 가 아니라 **라이브 값 전건 집계**다(`R2-3`).

## 6. 정제 지침 (SILVER 적재 시)

| 대상 | 처리 |
| :--- | :--- |
| AGENCY `YEAR` | `REGEXP_REPLACE(YEAR,'[^0-9]','')` 로 `년` 제거 후 4자리 검증 |
| AGENCY `MONTH`/`BRDC_MT` | `LPAD(REGEXP_REPLACE(TRIM(col),'[^0-9]',''),2,'0')` — 선행공백·`월`·미패딩 동시 해소 |
| AGENCY NULL 행 | `VIDEO_AD_CMPGN_DTLS` 1,987행은 연·월 모두 NULL ⇒ 대체 키(`BRDC_DATE`)로 파생하거나 제외 정책을 명시 |
| `TD_MS_CRMN_PRTCPNT.RQST_DATE` | `NULLIF(RQST_DATE,'0')` 선행 적용 후 `TRY_TO_DATE(...,'YYYYMMDD')` |
| 8자리 TEXT 일자 | `TRY_TO_DATE` 사용(`TO_DATE` 금지) — 센티넬·이상치가 적재 실패로 번지지 않게 한다 |
| `EXPENSE_RESOLUTION.WRITE_DATE` | 구분자 포함 10자리 ⇒ `TRY_TO_DATE(col,'YYYY-MM-DD')` |
| 센티넬 `99991231`/`19000101` | NULL 로 변환하지 말고 **의미를 COMMENT 에 명시**(`R2-7`) · 지표 집계에서 제외 조건을 명시 |

## 7. 본 조사의 한계 (비판적 자기점검)

🔴 **이 절을 지우지 마라 — 수치를 인용할 때 함께 읽어야 하는 조건이다.**

1. **1차 판정은 방법이 틀렸다.** 최초 스캔은 `INFORMATION_SCHEMA` 의 **컬럼명·COMMENT 키워드 필터**(`%YM%`·`%MONTH%`·`기준년월`)로 대상을 뽑았고, 그 결과 분리형 연/월 컬럼(`STDYY`+`STDR_MT`)·TEXT 일자 컬럼·이상치(`'0'`)를 **누락**했다. 사용자 지적으로 재조사했다. ⇒ COMMENT 기반 대상 선정은 `R2-3` 위반이며, 대상 선정 단계부터 실측이어야 한다.
2. **「임의 컬럼에 숨은 `yyyyMM` 값」 탐색은 표본 조사다.** TEXT/NUMBER 컬럼 전건에 대해 `^[12][0-9]{3}(0[1-9]|1[0-2])$` 매칭을 돌렸으나, 컬럼당 **`LIMIT 1000` 표본**이었다. 적중 14건은 전부 6자리 숫자 ID·파일크기(`CHILD_CD`·`FILE_SIZE`·`RELATNSP_KEY` 등)의 **우연 일치**로 확인돼 판정에서 배제했다. ⇒ 「연·월 의미를 가진 미명명 컬럼이 없다」는 **전수로 증명되지 않았다**. 필요하면 전건 스캔을 재실행해야 한다(§0 기준 1,176컬럼).
3. **§2·§3·§4 의 건수는 전건 집계다**(표본 아님) — `GROUP BY` / `COUNT` 를 대상 테이블 전체에 실행한 값이다.
4. **의미 판정은 COMMENT 에 의존한다.** 어떤 컬럼이 「기준년월」인지의 **의미**는 한글 COMMENT 를 근거로 삼았다. COMMENT 가 비어 있거나 틀린 컬럼(`BRONZE_CRM` 일부 · 예 `TD_MS_MSG_AT_SNDNG_DTLS` 는 COMMENT 가 실제 컬럼과 어긋남)은 의미를 확정하지 못했다.
5. **미측정 항목**: `VIDEO_AD_CMPGN_DTLS.BRDC_DATE` NULL 건수 · AGENCY `YEAR`↔`DATE` 연도 일치 여부 · 센티넬 건수(최대값만 확인) · `TD_MS_EMAIL_LQY_SNDNG` 두 컬럼의 원천 사용 여부.
6. **범위 한정**: BRONZE 만 본다. SILVER/GOLD 의 파생 결과가 이 규격을 지키는지는 **본 문서가 보증하지 않는다**.
