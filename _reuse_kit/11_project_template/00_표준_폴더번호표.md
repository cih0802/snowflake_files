# 표준 폴더 번호표

## 0. 원칙

- **10단위 번호 = 프로젝트 생명주기 단계.** 빈 번호(예: 쓰지 않는 40)는 비워 둔다 — 당겨 채우지 않는다(참조가 깨진다).
- **하위 폴더는 상위 번호의 1의 자리**를 쓴다(`30_build/31_env_rbac/` · `32_dbt/` …).
- **`00`·`01` 은 단계 밖.** `00` = 일하는 규칙, `01` = 프로젝트가 지금 어디까지 왔는가(전 단계 공통 관리).
- **번호 없는 `_` 접두** = 보조(보관 · 키트). 도구 폴더 `scripts/` 는 관례상 번호 없이 둔다(`kit_paths.SCRIPTS_DIR`).
- **배포 경로로 쓰이는 폴더는 처음부터 최종 위치에 둔다.** (원 프로젝트 교훈 = dbt 를 `10_dbt_pipeline` 으로 배포한 뒤
  번호 체계와 어긋나도 옮길 수 없었다 · `CREATE DBT PROJECT … FROM '<workspace 경로>'`.)
- **프로젝트 종료 = `01_project_control/` 하나를 `_archive/` 로 옮긴다.** (원 프로젝트는 세션 운영물 5종이 루트에 흩어져
  종료 때 5,477파일 이동 · 참조 1,628행 재분류가 필요했다 — `_archive/O276_project_closure/`.)

## 4. 조립 순서 (새 프로젝트)

1. 빈 루트에 `00_guides/` ← 키트 `01_agent_rules/*` · `04_methodology/*` · `02_skill_init/*.md`.
2. `scripts/` ← 키트 `03_session_tools/*` · `07_ops_tools/*` · `02_skill_init/*.py`.
3. `01_project_control/` · `_archive/` ← 이 폴더(`11_project_template/`)의 같은 이름 폴더(이 문서는 복사하지 않아도 된다).
4. `.snowflake/cortex/skills/init_ihcho/` ← 키트 `02_skill_init/init_ihcho/`.
5. (반출 전 키트에서) `python3 apply_names.py --set DB=… --set ACCOUNT=… --apply` → `kit_paths.py --check` → `build_init_ihcho_skill.py --check` → `session_brief.py --write`.
6. 단계 폴더(10~80)는 필요할 때 만든다 — 빈 폴더를 미리 만들지 않아도 도구는 동작한다.
