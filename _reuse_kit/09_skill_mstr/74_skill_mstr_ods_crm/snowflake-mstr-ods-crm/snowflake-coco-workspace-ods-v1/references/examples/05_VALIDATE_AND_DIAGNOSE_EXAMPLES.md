# 검증 및 수치 차이 진단 요청 예시

## 수치 차이 원인만 진단

```text
$mstr-ods-crm-schema

현재 Streamlit의 수치 차이 원인만 진단해주세요. 아직 코드는 수정하지 마세요.

- 화면명: [화면명]
- 조회기간: [시작일~종료일]
- 조회조건: [법인, 부서, 구분 등]
- 차이가 나는 지표: [지표명]
- 비교 기준값: [기존 화면 또는 엑셀 값]
- 현재 Streamlit 값: [값]
- 참고자료: [파일명 또는 없음]

조회조건 → 원천 대상 → 상태 선택 → 날짜 기준 → JOIN → 중복 제거 → 집계 → 화면 표시 순서로 처음 차이가 발생하는 단계를 찾아주세요.

숫자를 강제로 맞추지 말고 다음만 보고해주세요.
1. 확인된 원인
2. 영향을 받는 기간과 지표
3. 원천 적재 / 현재 ODS 재계산 / 업무기준 / JOIN·집계 / 화면 표시 중 판정
4. 수정이 필요한 최소 범위
5. 제가 결정할 내용 최대 3개
```

## 화면과 다운로드 검증

```text
$mstr-ods-crm-schema

현재 화면의 표와 다운로드 파일이 같은 조건과 같은 계산 결과를 사용하는지 검증해주세요.

기간, 필터, 정렬, NULL 처리, 고유 회원 수, 전체 합계, 비율 계산을 비교해주세요.
Python에서 다시 계산되는 값이 있으면 위치를 알려주세요.
현재는 수정하지 말고 차이와 영향만 보고해주세요.
```

## JOIN 중복 검증

```text
$mstr-ods-crm-schema

후속 행동 데이터를 연결한 뒤 발송 수와 회원 수가 증가하는 문제가 있는지 검증해주세요.

각 단계의 전체 행 수, 고유 발송 수, 고유 수신자 수, 고유 회원 수를 보여주세요.
오픈·클릭·서신·선물금·중단 데이터를 한 단계씩 추가하면서 처음 증가하는 JOIN을 찾아주세요.
원시 이벤트끼리 곱집계가 발생했는지도 확인해주세요.
```
