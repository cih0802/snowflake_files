### [L-1, L-2] 발송 효과성 및 중단 분석

* **담당 전문 주체**: `[비즈니스 로직]`
* **현업 의사결정 및 확인 필요 사항**:
  * 발송 후 반응(중단·증액)을 측정할 마케팅·캠페인성 발송과 단순 행정처리 통보성 발송의 구분 기준 확정.
  * 반응 귀속 기간(예: D+5) 설정 및 채널별 차등 적용 여부 확정.
  * 중단 보고서의 후원사업 축을 '실제 해지(중단)한 사업(가)'으로 볼 것인지 '최초 유입(개발)시킨 사업(나)'으로 볼 것인지 실적 귀속 기준 확정.
* **DB 실측 근거**:
  * **중단 이력**(`BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_DSCNTC`): 2025년 기준 115,129건의 중단 발생.
  * **알림톡 발송 이력**(`BRONZE_CRM.TD_MS_MSG_AT_SNDNG_DTLS`): 중단 회원의 직전 발송을 대조한 결과, 중단 당일(D+0) 발송 비중이 상당수 존재하며 상위 제목은 `[굿네이버스] 회원정보 변경 안내`, `후원금 납부 결과 안내` 등 행정·결과 통보성 메시지임.
  * **후원약정 사업**(`BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_BSNS`): 중단 플래그(`SPNSR_DSCNTC_YN='Y'`) 사업(가)과 개발 당시 획득 사업(`TM_MM_FDRM_MBER_DVLP_AMT` 최초행, 나)이 서로 다른 약정이 다수 존재함.
  * **판단 근거**: 마케팅성 발송과 행정통보성 발송을 구분하지 않으면 중단 직전 통보 메시지가 중단을 유발한 것으로 왜곡 집계되며, 후원사업 귀속 축에 따라 부서별 중단 실적이 완전히 달라짐.
* 🔴🔴 **[2026-09-08 O144-D 라이브 실측] 회신 전까지 「중단 축」은 DW 에서 빈 값으로 차단돼 있다 — 현업이 반드시 알아야 하는 파급이다.**
  * `GOLD.FACT_MEMBER_EVENT` 를 `EVENT_TYPE` 으로 분해해 캠페인축(`CAMPAIGN_SK`)·사업축(`SPONSORSHIP_SK`)의 채움률을 센 결과:
    * **`STOP` 행 1,038,262건** — `CAMPAIGN_SK` **전건 `0`** · `SPONSORSHIP_SK` **전건 `0`** (둘 다 0 센티넬).
    * **`DEV` 행 3,594,843건** — `CAMPAIGN_SK` 3,594,825건 채움(`0` 은 18건) · `SPONSORSHIP_SK` **전건 채움**.
  * **의미**: 「중단을 후원사업별·캠페인별로 분해」하는 요구는 **지금 답이 비어서 돌아온다.** 이는 결손이 아니라 **의도된 팬아웃 방지 차단**이다 — 동시중단 다중사업의 귀속 규칙이 미확정인 상태에서 배분하면 중단 건수가 사업 수만큼 부풀기 때문이다.
  * 🔴 **정지점**: 착수표 ⑭ `[2026-08-14 O73-C]` = 「**현업 결정 전 배선 금지**」가 살아 있다 ⇒ 이 절이 닫히기 전에는 귀속 규칙을 배선하지 않는다.
  * 🟢 **회신 전에도 답할 수 있는 축**: 획득(개발) 축은 `GOLD.DIM_MEMBER_ACQUISITION`(1,585,949행 · `ACQ_CAMPAIGN_SK` 1,585,945건 채움 · `ACQ_SPONSORSHIP_SK` 전건 채움)과 `FACT_MEMBER_COHORT`·`FACT_MEMBER_SPONSOR_BIZ`·`WIDE_MEMBER_FEE` 의 `ACQ_*` 계열로 **이미 분해 가능**하다.
  * 🟢 **반응 기간 D+5 는 별개로 배선돼 있다**: `GOLD.FACT_SERVICE_EVENT` 및 `WIDE_SERVICE_EVENT` 의 `D5_*` 계열(중단·증액·편지·선물). 🔴 단 **채널별 차등 적용 여부는 미확정**이다(문서17 §1-2).
  * 🔴 **재측정법**(수치를 인용하려면 직접 세라 · 창작 금지):
    `SELECT EVENT_TYPE, COUNT(*), COUNT(CASE WHEN SPONSORSHIP_SK = 0 THEN 1 END) FROM GN_DW.GOLD.FACT_MEMBER_EVENT GROUP BY 1;`
* 🔴 **파생 상태**: 이 절은 **열림** ⇒ 정본 파생 = `17_현업의사결정 요청.md` §1-1(L-1) · §1-2(L-1 부속) · §1-3(L-2).
  🔴 **16 에 닫힌 것으로 실어서는 안 된다** — D+5 기본값 채택과 획득/중단 2-Track 컬럼 제공은 배선됐으나, **귀속 축 확정 자체는 현업 회신 사항**이다.
* **실증 쿼리**:

```sql
-- [1-1. L-1] 중단 회원의 직전 발송 간격 및 당일 발송 상위 제목
-- 원천: BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_DSCNTC (중단) × TD_MS_MSG_AT_SNDNG_DTLS (발송)
WITH stop AS (
    SELECT mber_no, TO_DATE(spnsr_dscntc_de, 'YYYYMMDD') AS stop_date
    FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_DSCNTC
    WHERE spnsr_dscntc_de BETWEEN '20250101' AND '20251231'
), prev_send AS (
    SELECT
        x.mber_no,
        x.stop_date,
        MAX(TO_DATE(s.sndng_dt)) AS last_send_date
    FROM stop x
    JOIN GN_DW.BRONZE_CRM.TD_MS_MSG_AT_SNDNG_DTLS s
        ON s.mber_no = x.mber_no
       AND TO_DATE(s.sndng_dt) <= x.stop_date
    GROUP BY x.mber_no, x.stop_date
)
SELECT
    CASE
        WHEN DATEDIFF(day, last_send_date, stop_date) = 0 THEN '당일(D+0)'
        WHEN DATEDIFF(day, last_send_date, stop_date) BETWEEN 1 AND 5 THEN 'D+1~5'
        WHEN DATEDIFF(day, last_send_date, stop_date) BETWEEN 6 AND 10 THEN 'D+6~10'
        WHEN DATEDIFF(day, last_send_date, stop_date) BETWEEN 11 AND 30 THEN 'D+11~30'
        WHEN DATEDIFF(day, last_send_date, stop_date) BETWEEN 31 AND 90 THEN 'D+31~90'
        ELSE 'D+91 이상'
    END AS "발송_중단_간격",
    COUNT(*) AS "중단건수",
    ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 1) AS "비중_PCT"
FROM prev_send
GROUP BY 1
ORDER BY 2 DESC;

-- [1-2. L-1 부속] 당일 발송(D+0)의 상위 메시지 제목 (행정/통보성 메시지 식별)
SELECT
    m.tit AS "발송제목",
    COUNT(*) AS "당일발송건수"
FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_DSCNTC x
JOIN GN_DW.BRONZE_CRM.TD_MS_MSG_AT_SNDNG_DTLS s
    ON s.mber_no = x.mber_no
   AND TO_CHAR(s.sndng_dt, 'YYYYMMDD') = x.spnsr_dscntc_de
JOIN GN_DW.BRONZE_CRM.TM_MS_MSG_AT_SNDNG m
    ON m.sndng_key = s.sndng_key
WHERE x.spnsr_dscntc_de BETWEEN '20250101' AND '20251231'
GROUP BY 1
ORDER BY 2 DESC
LIMIT 20;

-- [1-3. L-2] 중단보고 후원사업: 끊은 사업(가) vs 최초 유입 사업(나) 대조
WITH acq AS (
    SELECT mber_no,
           MIN_BY(spnsr_bsns_id, occrrnc_de) AS acq_spnsr_bsns_id
    FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_DVLP_AMT
    WHERE spnsr_bsns_id IS NOT NULL
    GROUP BY mber_no
)
SELECT
    bn.spnsr_bsns_nm AS "획득_후원사업_나",
    bs.spnsr_bsns_nm AS "중단_후원사업_가",
    COUNT(*) AS "약정건수"
FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_BSNS b
JOIN GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR s
    ON s.spnsr_no = b.spnsr_no
JOIN acq a
    ON a.mber_no = s.mber_no
LEFT JOIN GN_DW.BRONZE_CRM.TM_CM_SPNSR_BSNS_INFO bn
    ON bn.spnsr_bsns_id = a.acq_spnsr_bsns_id
LEFT JOIN GN_DW.BRONZE_CRM.TM_CM_SPNSR_BSNS_INFO bs
    ON bs.spnsr_bsns_id = b.spnsr_bsns_id
WHERE b.spnsr_dscntc_yn = 'Y'
GROUP BY 1, 2
ORDER BY 3 DESC
LIMIT 30;
```

### [K-2] 인원 vs 횟수 구분 ➔ 🟢 [2026-09-08 O144-D 라이브 배선 확인 — 닫힘]

* **담당 전문 주체**: `[비즈니스 로직]`
* 🟢 **[2026-09-08 O144-D] 배선 실효 확인 — 이 절은 닫혔다.**
  * `GOLD.FACT_EVENT_PARTICIPATION` 에 **인원 계열**(`PARTICIPATE_CNT` 참여인원 · `TOTAL_CNT` 총인원 · `CONFIRM_CNT` 신청확정인원 · `WAIT_CNT`·`CANCEL_CNT`·`ABSENT_CNT`)과 **횟수 계열**(`PARTICIPATION_TIMES` 참여횟수 · `PARTICIPANT_CNT` 참여자수), 그리고 고유 회원 판정키 `MEMBER_DK` 가 **모두 실재**한다.
  * `SERVING.SV_EVENT_PARTICIPATION` 까지 이원화가 올라와 있다 — `DESC SEMANTIC VIEW` 실측:
    * `DISTINCT_PARTICIPANTS` = `COUNT(DISTINCT fep.MEMBER_DK)` (동의어 「고유 참여회원수」) ⇒ **인원(명)**
    * `TOTAL_PARTICIPATE_CNT` = `SUM(fep.PARTICIPATE_CNT)` (동의어 「참여건수」) ⇒ **횟수(건)**
    * `TOTAL_PARTICIPANTS` = `SUM(fep.PARTICIPANT_CNT)` (동의어 「참여자수」·「참가자수」)
  * ⇒ 인원/횟수를 자연어로 물어도 **다른 metric 으로 갈라진다** ⇒ 2.5~3.5배 과대계상 위험이 SV 층에서 차단된다.
* 🔴 **주의 — 정본 원장은 아직 이 절을 🟢 로 표기하지 않았다**: `20_issue/20_현업확인_요청_조각/20_현업확인_요청-004.md:21` (§K-2) 는 여전히 상태 표기가 없다. 그래서 `11_미해결이슈_요약.md` 는 K-2 를 「⚪ 표기 없음」으로 센다. **배선은 닫혔고 원장 표기만 미갱신인 상태**다 — 건수를 인용할 때 이 괴리를 함께 말해야 한다.
* **DB 실측 근거**:
  * **일반행사 참여**(`BRONZE_CRM.TD_MS_EVENT_PRTCPNT_DTL`): 총 983,971건 / 고유 회원수 388,522명 (인원 대비 기록 건수 2.53배).
  * **캠페인행사 참여**(`BRONZE_CRM.TD_MS_CRMN_PRTCPNT`): 총 152,132건 / 고유 회원수 42,535명 (인원 대비 기록 건수 3.58배).
  * **판단 근거**: 동일 회원이 여러 행사에 반복 참여하므로, 중복제거 회원수(인원)와 단순 로그 건수(횟수)를 엄격히 분리 정의하지 않으면 보고서 지표 집계 시 2.5~3.5배의 과대계상이 발생함.
* **실증 쿼리**:

```sql
-- [1-4. K-2] 행사 참여: 인원(고유 회원수) vs 횟수(총 참여기록 건수)
SELECT '일반행사 TD_MS_EVENT_PRTCPNT_DTL' AS "참여원천",
    COUNT(*) AS "총_횟수(기록수)",
    COUNT(DISTINCT mber_no) AS "고유_인원(회원수)",
    ROUND(COUNT(*) * 1.0 / NULLIF(COUNT(DISTINCT mber_no), 0), 2) AS "1인당_평균참여횟수"
FROM GN_DW.BRONZE_CRM.TD_MS_EVENT_PRTCPNT_DTL
UNION ALL
SELECT '캠페인행사 TD_MS_CRMN_PRTCPNT',
    COUNT(*),
    COUNT(DISTINCT mber_no),
    ROUND(COUNT(*) * 1.0 / NULLIF(COUNT(DISTINCT mber_no), 0), 2)
FROM GN_DW.BRONZE_CRM.TD_MS_CRMN_PRTCPNT;
```

    SELECT d.dept_id, d.dept_nm, d.upper_dept_id, d.stats_dept_lvl, 1 AS lvl
    FROM GN_DW.BRONZE_CRM.TM_CM_DEPT_INFO d
    LEFT JOIN GN_DW.BRONZE_CRM.TM_CM_DEPT_INFO p
        ON p.dept_id = d.upper_dept_id
    WHERE p.dept_id IS NULL
    UNION ALL
    SELECT d.dept_id, d.dept_nm, d.upper_dept_id, d.stats_dept_lvl, t.lvl + 1
    FROM GN_DW.BRONZE_CRM.TM_CM_DEPT_INFO d
    JOIN tree t ON d.upper_dept_id = t.dept_id
)
SELECT
    lvl AS "트리레벨",
    COUNT(*) AS "부서수",
    COUNT(CASE WHEN dept_nm LIKE '%본부%' THEN 1 END) AS "본부_명칭포함",
    COUNT(CASE WHEN dept_nm LIKE '%지부%' THEN 1 END) AS "지부_명칭포함",
    COUNT(DISTINCT stats_dept_lvl) AS "STATS_DEPT_LVL_값종류"
FROM tree
GROUP BY lvl
ORDER BY lvl;

-- [4-2. F-2] 후원사업 약어코드 및 후원구분코드 분포
SELECT
    spnsr_bsns_abrv_cd AS "사업약어코드",
    spnsr_div_cd AS "후원구분코드",
    COUNT(*) AS "사업수",
    LISTAGG(spnsr_bsns_id || '=' || spnsr_bsns_nm, ' · ')
        WITHIN GROUP (ORDER BY spnsr_bsns_id) AS "소속사업_목록"
FROM GN_DW.BRONZE_CRM.TM_CM_SPNSR_BSNS_INFO
GROUP BY 1, 2
ORDER BY 1, 2;
