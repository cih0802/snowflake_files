### 2. [K-2] 및 BRONZE 실측 데이터 기반 분석
(1) 왜 "인원(명)"과 "횟수(건)"를 반드시 분리해야 하는가? (BRONZE 실측)
  * 동일 행사 내 중복 신청/참여: TD_MS_CRMN_PRTCPNT에서 동일 (CRMN_CD, MBER_NO) 쌍의 중복 행이 다수 존재합니다. (한 회원이 동일 행사에 2~7회 신청/등록된 사례 확인)
  * 전체 반복 참여:
    * TD_MS_CRMN_PRTCPNT(문화/캠페인): 총 152,127행 / 고유 회원 42,535명 (1인당 평균 3.57회, 최대 842회 참여)
    * TD_MS_EVENT_PRTCPNT_DTL(온라인이벤트): 총 981,999행 / 고유 회원 388,522명 (1인당 최대 18,755건)
  * 판정:
    * 서비스 지표 산식의 (명, 건) 표기 및 보고서 양식에 따라:
      * 인원 = COUNT(DISTINCT MBER_NO)
      * 횟수 / 건수 = COUNT(*)
(2) 행사 참여상태 코드 (MS006 / MS304) 매핑 판정 (근거 1~5번 반영)
제시해주신 근거(문화이벤트, 온라인이벤트, 기업혜택, 특성화회원조직, 해외사업장)를 통해 20_issue §I에서 미결이었던 상태값 의미가 매핑됩니다.

  * 캠페인/문화행사 (TD_MS_CRMN_PRTCPNT / 코드 MS006):
    * 1 (신청): 신청 등록
    * 2 (참여): 실제 행사 참여 완료 → 참여인원 / 참여횟수
    * 3 (불참): 신청 후 불참 → 불참인원 / 불참횟수
    * 4 (대기) / 6 (대기(결제)): 대기 상태 → 대기인원 / 대기횟수
    * 5 (취소): 신청 취소 → 취소인원
    * 신청확정인원: 근거 1)에 따라 [1(신청), 2(참여), 3(불참), 4(대기), 5(취소)] 전체를 아우르는 신청 확정 모수
  * 온라인이벤트 (TD_MS_EVENT_PRTCPNT_DTL / 코드 MS304):
    * 110 (Success): 참여 완료
    * 근거 2) 및 4)에 따라 참여상태가 참여(Success/110)인 건을 참여 기준으로 집계
### 3. 첨부 보고서([회원] 참여콘텐츠분석보고) 기준 지표 정의 확정안
보고서의 레이아웃은 **상단(행사 요약 헤더)**과 **하단(행사별 참여 회원 상세 목록)**의 2-Layer 구조입니다.
① 상단 영역: 행사 기준 집계 지표 (인원 = 고유 회원수)
  * 모집인원: TM_MS_CRMN.RCRIT_PSNNL_CO (행사 마스터 설정값)
  * 총 인원: COUNT(DISTINCT MBER_NO) (해당 행사에 신청/참여한 전체 고유 회원 수)
  * 신청확정인원: COUNT(DISTINCT CASE WHEN PARTCPT_STAT_CD IN ('1','2','3','4','5') THEN MBER_NO END)
  * 참여인원: COUNT(DISTINCT CASE WHEN PARTCPT_STAT_CD = '2' THEN MBER_NO END)
  * 대기인원: COUNT(DISTINCT CASE WHEN PARTCPT_STAT_CD IN ('4','6') THEN MBER_NO END)
  * 불참인원: COUNT(DISTINCT CASE WHEN PARTCPT_STAT_CD = '3' THEN MBER_NO END)
  * 취소인원: COUNT(DISTINCT CASE WHEN PARTCPT_STAT_CD = '5' THEN MBER_NO END)
② 하단 영역: 회원별 상세 목록 지표 (개인 프로필 / 누적 이력 속성)
하단 표의 1개 행은 **[특정 행사 - 특정 회원 1명]**을 나타내며, 우측의 횟수 컬럼은 해당 회원의 개인 누적 활동성 지표입니다.
  * 대기횟수: 해당 회원이 기록한 대기(PARTCPT_STAT_CD IN ('4','6')) 총 건수
  * 불참횟수: 해당 회원이 기록한 불참(PARTCPT_STAT_CD = '3') 총 건수
  * 참여횟수: 해당 회원이 기록한 참여 완료(PARTCPT_STAT_CD = '2') 총 건수
  * 누적 신청 횟수: 해당 회원의 전체 행사 신청 총 건수 (COUNT(*))

### 4. '누적 신청 횟수' 집계 기준 (선택 가이드)
누적 횟수 집계 시점은 다음 2가지 중 업무 목적에 맞게 선택하시면 됩니다:

  * [안 A] 행사 시점 기준 누적 (As-of 기준, 권장)
    * 정의: 해당 행사의 신청일자(RQST_DATE) 이전까지 해당 회원이 신청한 누적 횟수
    * 장점: 일간 보고서 작성 시점의 데이터 상태를 정확히 재현 (과거 시점 분석 및 이탈 예측/ML에 왜곡 없음)
  * [안 B] 회원 생애 전 기간 누적 (현재 기준)
    * 정의: 조회 시점 현재까지 해당 회원이 신청한 통산 누적 건수
    * 장점: CRM 회원 상세 팝업의 현재 통산 지표와 일치
