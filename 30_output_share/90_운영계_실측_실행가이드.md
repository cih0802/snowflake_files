# 90. 운영계 실측 실행 가이드 (30번 산출물)

## 0. 역할 분담

| 어디서 | 누가 | 무엇을 |
|---|---|---|
| 운영계 ZL50263 | 실행 담당 LLM 또는 사람 | §1의 명령 2개를 실행하고 **결과 폴더를 그대로** 돌려준다. 해석·판정·수정은 하지 않는다 |
| 개발계 UM80684 | 문서 작성 담당 | §2 집계를 실행하고 문서에 반영한다 |

- 왜 나누나: 30번 산출물(03·04·05·08·09)의 0행·전건 NULL·전건 0 판정은 `scripts/census_columns.py`가 **접속한 계정에서만** 실측한다. 문서는 개발계에서 쓰고, 운영계에서는 숫자만 가져온다.
- 판정은 **운영계 결과 안에서 닫는다**(85번 R90 원칙). 개발계 값은 `--base`를 줄 때만 참고 열로 붙는다.

## 1. 운영계 실행 — 🔴 실행자 지시 (이 절만 읽고 그대로 따른다)

```text
[실행자 지시]
1. 계정이 ZL50263 인지 먼저 확인한다:  SELECT CURRENT_ACCOUNT();
   - ZL50263 이 아니면 아무것도 실행하지 말고 「계정 불일치: <값>」만 보고하고 멈춘다.
2. dbt "daily" build(06:01 KST)가 끝난 뒤에 실행한다. 진행 중이면 끝날 때까지 기다린다.
3. 아래 명령 2개를 워크스페이스 루트에서 순서대로, 문구 그대로 실행한다. 명령을 고치지 않는다.
4. 파일을 손으로 고치거나 지우지 않는다. SQL 파일을 편집하지 않는다. 다른 SQL 을 실행하지 않는다.
5. 오류가 나도 고치려 하지 않는다. 각 명령의 마지막 출력 줄과 종료코드(rc)만 그대로 적는다.
6. 끝나면 §1-2 의 「돌려줄 것」만 돌려준다. 결과를 요약·해석·판정하지 않는다.
```

### 1-1. 명령

```bash
# ① 운영계 카탈로그 기준으로 SQL 생성 (필수 — 운영계에만 있는 테이블까지 잰다 · 읽기 전용 조회만 한다)
python3 scripts/gen_s30_census_sql.py

# ② 실측 — SELECT/WITH/SHOW/DESC 외 문장이 있으면 실행 전에 rc=1 로 멈춘다
python3 scripts/env_capture.py --id S30 --out-root "30_output_share/_ENV" "30_output_share/_근거쿼리/S30_census.sql"
```

- 정상: ①은 `🟢 30_output_share/_근거쿼리/S30_census.sql · Q01~Qnn`, ②는 `🟢 S30 · account=ZL50263 · … ERROR 0`으로 끝난다. 개발계 리허설은 140문장에 수 분 걸렸다.
- ②가 `🔴 … ERROR n`으로 끝나도 **그대로 돌려준다.** 오류 문장은 manifest에 기록되어 있다.

### 1-2. 돌려줄 것

| 항목 | 내용 |
|---|---|
| 폴더 | `30_output_share/_ENV/ZL50263/` 안의 `S30_*` 파일 전부(`S30_manifest.csv` · `S30_Q01_1.csv` ~). 개수와 이름을 바꾸지 않는다 |
| 파일 | `30_output_share/_근거쿼리/S30_census.sql` (① 생성본) |
| 출력 | ①·②의 마지막 출력 줄 각 1줄 + rc |

- 개발계 워크스페이스의 같은 경로에 넣는다. 덮어써도 되는 이유: 운영계 결과는 `ZL50263` 폴더에만 생기고, 개발계 리허설 결과는 `UM80684` 폴더에 따로 있다.
- 준비: 운영계 워크스페이스에 `scripts/`(최소 `gen_s30_census_sql.py` · `env_capture.py` · `sfconn.py`)가 있어야 한다. 85번 작업 워크스페이스라면 이미 있다. 롤 · WH = ACCOUNTADMIN · GN_DW_ANALYTICS_WH 권장.

## 2. 개발계 집계 (문서 작성 담당)

```bash
python3 scripts/s30_census_to_json.py ZL50263                 # 운영계 단독 판정
python3 scripts/s30_census_to_json.py ZL50263 --base UM80684  # (선택) 개발계 참고 열 추가
```

| 산출물 | 내용 |
|---|---|
| `_ENV/ZL50263/census_S30.json` | `census_columns.py`와 같은 형식 |
| `12_운영계_실측_ZL50263.md` | §1 실행 결과(ERROR 열거) · §2 0행 테이블 · §3 BRONZE 0행 · §4 전건 NULL/0 컬럼 |

- rc=1이면 manifest에 ERROR가 있다는 뜻이다(문서 §1에 🔴로 열거된다). 운영계에 없는 객체인지부터 본다.
- 05·08·09를 운영계 수치로 다시 그리려면 아래처럼 **별도 폴더**로 생성한다. 루트 판본은 개발계 기준이고 골든도 개발계로 고정돼 있으므로 루트에 덮어쓰지 않는다.
  ```bash
  O="30_output_share/_ENV/ZL50263/gen" && mkdir -p "$O" && \
  export GN_DW_OUT="$O" GN_DW_CENSUS="30_output_share/_ENV/ZL50263/census_S30.json" \
         GN_DW_LINEAGE="30_output_share/04_컬럼계보매핑.csv" GN_DW_PREV="30_output_share" && \
  python3 scripts/gen_metric_gold_mapping.py && python3 scripts/gen_section_assembly.py && python3 scripts/gen_silver_gold_retention.py
  ```
  - `GN_DW_LINEAGE`가 없으면 05가 04를 `GN_DW_OUT`에서 찾다가 실패한다. 09는 05를 같은 `GN_DW_OUT`에서 읽는다.
  - 검증(2026-10-27): 개발계 census로 같은 명령을 실행하면 05 csv가 루트 판본과 바이트 단위로 같다.
  - 03은 실행 중에 카탈로그를 직접 조회하므로 이 방식으로는 운영계 판본이 되지 않는다. 운영계 03이 필요하면 별도 작업으로 다룬다(실행 담당 LLM에게 맡기지 않는다).

## 3. 결과 반영

- `12_운영계_실측_ZL50263.md` §2를 85번 `R02_DB_데이터구조.md` 「행 0 테이블」 행과 대조한다. 현재 R02의 근거는 ZL50263 `R00_Q02_1`(2026-10-26)이다.
- 수기 문서(01·10·16·18·19·21)의 「2026-10-27 최신화」 블록 가운데 「개발계 실측」으로 표시된 컬럼 단위 주장을 운영계 값으로 확인한다. 예: `FACT_TARGET_PROJECT` 추경·누계 3컬럼 전건 0, DIGITAL `CRM_DEV_CNT` 전건 NULL.
