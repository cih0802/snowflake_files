> ⇒ 현업 지침(2026-09-10) = **무시하고 파이프라인을 구성**하며, 해당 테스트는 `warn` 을 **영구 유지**합니다.
>
> 🟢 **결정적 증거** = 그 고아 7,658종을 형식별로 분해하니 **전부 정상 형식**이었습니다:
> **정기회원 7자리 7,629종(9,338행) + 일시회원 `S`+8자리 29종(38행) · 형식 이상 0종.**
> ⇒ 즉 이것은 **깨진 쓰레기 값이 아니라 「한때 실재했다가 마스터에서 지워진 정상 번호」**입니다.
> 형식이 깨진 값은 이미 `I-2` 정제 필터가 걸러냈기 때문에 0종인 것입니다.
> 🔴 **그래서 지울 수도(참여 이력이 사실이므로), 실패시킬 수도(구조적으로 상시 발생) 없습니다.**
> 정답은 **사유를 기록하고 관측**하는 것입니다.

## 6. 검증 쿼리 (복붙 실행용)

> 요청을 보내기 전과 회신을 받은 후 **각각 1회씩** 돌려 상태 변화를 대조하십시오.

### 6-1. A유형 — 테이블 미입고 스텁 확인

```sql
-- [19-1] 목표 스텁 테이블 행수 (E-6 · 인입후보 1)
SELECT 'SILVER.CRM_BIZ_TARGET'      AS "대상", COUNT(*) AS "행수"
FROM GN_DW.SILVER.CRM_BIZ_TARGET
UNION ALL
SELECT 'GOLD.FACT_TARGET_PROJECT',  COUNT(*)
FROM GN_DW.GOLD.FACT_TARGET_PROJECT
UNION ALL
SELECT 'SILVER.CRM_DEV_TARGET (대조·정상)', COUNT(*)
FROM GN_DW.SILVER.CRM_DEV_TARGET
UNION ALL
SELECT 'GOLD.FACT_TARGET_MEMBER_DEV (대조·정상)', COUNT(*)
FROM GN_DW.GOLD.FACT_TARGET_MEMBER_DEV;

-- [19-2] 공휴일 캘린더 원천 부재 확인 (HOL-1)
SELECT
    COUNT(*) AS "BRONZE_테이블_총수",
    COUNT(CASE WHEN TABLE_NAME LIKE '%HOLIDAY%' OR TABLE_NAME LIKE '%CALENDAR%'
                 OR TABLE_NAME LIKE '%HLDY%'    OR TABLE_NAME LIKE '%WORKDAY%'
               THEN 1 END) AS "캘린더_키워드_해당"
FROM GN_DW.INFORMATION_SCHEMA.TABLES
WHERE TABLE_SCHEMA LIKE 'BRONZE%';

-- [19-3] DIM_DATE 휴일 플래그 전건 FALSE 확인 (HOL-1 하류 영향)
SELECT
    COUNT(*)                 AS "일자_행수",
    COUNT_IF(IS_HOLIDAY)     AS "휴일_TRUE_행수",
    COUNT_IF(NOT IS_HOLIDAY) AS "휴일_FALSE_행수"
FROM GN_DW.GOLD.DIM_DATE;
```

### 6-2. B유형 — 컬럼 구조적 부재 확인

```sql
-- [19-4] AD-5 : 방송(VIDEO) 개발실적 컬럼 실재 여부
--   🔴 결과가 0행이면 「컬럼이 없다」는 뜻이다(값이 없는 것과 다르다).
SELECT COLUMN_NAME, DATA_TYPE
FROM GN_DW.INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = 'BRONZE_AGENCY'
  AND TABLE_NAME   = 'VIDEO_AD_CMPGN_DTLS'
  AND (COLUMN_NAME ILIKE '%DVLP%' OR COLUMN_NAME ILIKE '%DEV%')
ORDER BY COLUMN_NAME;

-- [19-4-B] 대조군 : 재방송에는 개발 컬럼이 있다
SELECT COLUMN_NAME, DATA_TYPE
FROM GN_DW.INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = 'BRONZE_AGENCY'
  AND TABLE_NAME   = 'REBRDC_AD_CMPGN_DTLS'
  AND (COLUMN_NAME ILIKE '%DVLP%' OR COLUMN_NAME ILIKE '%DEV%')
ORDER BY COLUMN_NAME;

-- [19-5] PST-1 : 우편 발송 상세 전체 컬럼 열거
--   🔴 패턴 검색(ILIKE '%RST%')을 쓰지 마라 — FRST_RGSTR_ID 가 오탐된다.
--      전체를 열거해 결과코드 컬럼이 실제로 없음을 눈으로 확인한다.
SELECT ORDINAL_POSITION, COLUMN_NAME, DATA_TYPE, COMMENT
FROM GN_DW.INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = 'BRONZE_CRM'
  AND TABLE_NAME   = 'TD_MS_PSTMTR_SNDNG_DTL'
ORDER BY ORDINAL_POSITION;

-- [19-5-B] 채널별 집계 테이블의 성공·실패 컬럼 보유 대조
--   🟢 2026-09-10 실측 = 집계(LQY) 테이블은 3종만 실재한다(SND 채널은 집계 테이블 자체가 없다).
--      EMAIL 성공2/실패2 · MSG_AT 성공1/실패1 · PSTMTR 성공0/실패0 ⇒ 우편만 결과 축이 없다.
SELECT TABLE_NAME,
       COUNT_IF(COLUMN_NAME ILIKE '%SUCCES%') AS "성공수_컬럼",
       COUNT_IF(COLUMN_NAME ILIKE '%FAILR%')  AS "실패수_컬럼"
FROM GN_DW.INFORMATION_SCHEMA.COLUMNS
WHERE TABLE_SCHEMA = 'BRONZE_CRM'
  AND TABLE_NAME LIKE '%LQY%'
GROUP BY TABLE_NAME
ORDER BY TABLE_NAME;
```

### 6-5. 🔴 회원 마스터 전량입고 검증 + 잔존 고아 (BLOCKING-1 종결 근거)

```sql
-- [19-9] 마스터 2종 ↔ SILVER ↔ GOLD 3축 대조 (전량입고 확인)
SELECT '1.BRONZE 정기회원 마스터' AS "축", COUNT(*) AS "행수"
FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_INFO
UNION ALL
SELECT '2.BRONZE 일시회원 마스터', COUNT(*)
FROM GN_DW.BRONZE_CRM.TM_MM_ONCE_MBER_INFO
UNION ALL
SELECT '3.SILVER.CRM_MEMBER', COUNT(*)
FROM GN_DW.SILVER.CRM_MEMBER
UNION ALL
SELECT '4.GOLD.DIM_MEMBER', COUNT(*)
FROM GN_DW.GOLD.DIM_MEMBER;
-- 판정 = (1 + 2) = 3 = 4 이어야 한다. 2026-09-10 실측 = 1,587,343 + 175,722 = 1,763,065 전건 일치.

-- [19-10] 전량입고 후에도 남는 고아 회원번호 (무시 대상 · 현업 지침 2026-09-10)
--   🔴 이 수치가 0 이 되지 않는 것이 정상이다. cascade 삭제를 쓰지 않는 운영계의 구조적 잔번이다.
SELECT
    COUNT(DISTINCT p.MBER_NO) AS "고아_회원번호_종수",
    COUNT(*)                  AS "고아_행수",
    (SELECT COUNT(*) FROM GN_DW.SILVER.CRM_EVENT_PARTICIPATION) AS "전체_행수",
    ROUND(COUNT(*) * 100.0
          / NULLIF((SELECT COUNT(*) FROM GN_DW.SILVER.CRM_EVENT_PARTICIPATION), 0), 2)
                              AS "고아율_PCT"
FROM GN_DW.SILVER.CRM_EVENT_PARTICIPATION p
LEFT JOIN GN_DW.SILVER.CRM_MEMBER m
       ON m.MEMBER_DK = p.MBER_NO
WHERE m.MEMBER_DK IS NULL;
-- 2026-09-10 실측 = 7,658종 / 9,376행 / 1,134,022행 = 0.83%.

-- [19-11] 고아 회원번호의 형식별 분해 — 「테스트값」과 「정상 잔번」을 구별한다
SELECT
    CASE
        WHEN REGEXP_LIKE(p.MBER_NO, '^[0-9]{7}$')  THEN '1.정기회원 7자리(정상 형식)'
        WHEN REGEXP_LIKE(p.MBER_NO, '^[0-9]{9}$')  THEN '2.일시회원 9자리(정상 형식)'
        WHEN REGEXP_LIKE(p.MBER_NO, '^S[0-9]{8}$') THEN '3.일시회원 S+8자리(정상 형식)'
        ELSE '9.기타(형식 이상)'
    END                       AS "회원번호_형식",
    COUNT(DISTINCT p.MBER_NO) AS "고아_종수",
    COUNT(*)                  AS "고아_행수"
FROM GN_DW.SILVER.CRM_EVENT_PARTICIPATION p
LEFT JOIN GN_DW.SILVER.CRM_MEMBER m
       ON m.MEMBER_DK = p.MBER_NO
WHERE m.MEMBER_DK IS NULL
GROUP BY 1
ORDER BY 1;
-- 2026-09-10 실측 = 7자리 7,629종(9,338행) + S+8자리 29종(38행) · 「9.기타」 0종.
--   🟢 전부 정상 형식이다 ⇒ 쓰레기 값이 아니라 마스터에서 지워진 정상 번호다(§0-2).
```
