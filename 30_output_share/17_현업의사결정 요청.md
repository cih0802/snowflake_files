## 1. 회원 및 발송 서비스 영역

### 1-1. [L-1] 마케팅·캠페인성 발송 vs 단순 행정통보성 발송 구분 기준 확정

* **확인 및 결정 요청 사항**:
  1. 발송 후 회원 반응(중단·증액 등)을 측정할 때, 모수에서 제외할 **행정/통보성 메시지의 공식 분류 기준** 확정.
  2. 메시지 제목 문자열 패턴 외에 **원천 코드 컬럼(템플릿 유형·목적 코드 등)으로 구분할 수 있는 기준** 존재 여부.
* **데이터 현황 및 실측 근거**:
  * 2025년 중단 회원(115,129명)의 중단 당일(D+0) 발송 비중은 **62.1%(70,231건)**에 달함.
  * 당일 발송 상위 메시지는 `CRM중단-A(경제)`(49.6%), `문의답변`(17.1%), `사복_CRM 중단회원`(7.8%), `미납중단안내`(6.3%) 등 **상위 83% 이상이 사후 통보성 메시지**임.
  * 사후 통보성 메시지를 제외하지 않으면 "중단 처리 완료 안내"가 "발송으로 인한 중단"으로 왜곡 집계됨.
* **실증 쿼리**:

```sql
-- [1-1] 중단 당일(D+0) 상위 발송 메시지 제목 실측
SELECT
    m.tit AS "발송제목",
    COUNT(*) AS "당일발송건수",
    ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 1) AS "비중_PCT"
FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_DSCNTC x
JOIN GN_DW.BRONZE_CRM.TD_MS_MSG_AT_SNDNG_DTLS s
    ON s.mber_no = x.mber_no
   AND TO_CHAR(s.sndng_dt, 'YYYYMMDD') = x.spnsr_dscntc_de
JOIN GN_DW.BRONZE_CRM.TM_MS_MSG_AT_SNDNG m
    ON m.sndng_key = s.sndng_key
WHERE x.spnsr_dscntc_de BETWEEN '20250101' AND '20251231'
GROUP BY 1
ORDER BY 2 DESC
LIMIT 20;

-- [1-1-B] 메시지 제목 패턴별 잠정 분류 비중 집계
WITH d0 AS (
    SELECT m.tit
    FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_DSCNTC x
    JOIN GN_DW.BRONZE_CRM.TD_MS_MSG_AT_SNDNG_DTLS s
        ON s.mber_no = x.mber_no
       AND TO_CHAR(s.sndng_dt, 'YYYYMMDD') = x.spnsr_dscntc_de
    JOIN GN_DW.BRONZE_CRM.TM_MS_MSG_AT_SNDNG m
        ON m.sndng_key = s.sndng_key
    WHERE x.spnsr_dscntc_de BETWEEN '20250101' AND '20251231'
)
SELECT
    CASE
        WHEN tit LIKE '%중단%' OR tit LIKE '%해지%' THEN '1.중단·해지 처리 통보'
        WHEN tit LIKE '%미납%' OR tit LIKE '%납부%' OR tit LIKE '%결과%' THEN '2.미납·납부 결과 통보'
        WHEN tit LIKE '%변경%' OR tit LIKE '%정보%' THEN '3.회원정보 변경 통보'
        WHEN tit LIKE '%문의%' OR tit LIKE '%답변%' THEN '4.문의 응답'
        ELSE '9.마케팅성 후보(그 외)'
    END AS "잠정분류",
    COUNT(*) AS "당일발송건수",
    ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 1) AS "비중_PCT",
    COUNT(DISTINCT tit) AS "제목종수"
FROM d0
GROUP BY 1
ORDER BY 1;
```

### 1-2. [L-1 부속] 채널별 반응 귀속 기간 차등 적용 여부

* **확인 및 결정 요청 사항**:
  1. 발송 후 반응 귀속 기간을 **전 채널 일괄 D+5일**로 적용할지, **채널별로 차등(예: 알림톡 D+5일, 이메일/우편 D+30일 등)** 적용할지 여부.
  2. D+11~30 구간(전체 중단의 12.5%)을 발송 반응으로 인정하여 귀속 기간을 확대할지 여부.
* **데이터 현황 및 실측 근거**:
  * 채널별 반응 도달 속도 차이가 뚜렷함:
    * **알림톡**: D+5 누적 **77.3%**, D+30 누적 95.6%, 평균 반응 간격 **9.8일**
    * **이메일**: D+5 누적 **64.8%**, D+30 누적 78.5%, 평균 반응 간격 **41.5일** (알림톡 대비 4배 이상 김)
  * 일괄 D+5 적용 시 이메일 반응의 약 35%가 모수에서 누락되므로 채널별 차등 적용 검토가 필요함.
* **실증 쿼리**:

```sql
-- [1-2] 발송 후 중단 발생 간격(D+n) 분포 실측
WITH stop AS (
    SELECT mber_no, TO_DATE(spnsr_dscntc_de, 'YYYYMMDD') AS stop_date
    FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_DSCNTC
    WHERE spnsr_dscntc_de BETWEEN '20250101' AND '20251231'
), prev_send AS (
    SELECT
        x.mber_no,
        x.stop_date,
        MAX(TO_DATE(s.sndng_dt)) AS last_send_date
    FROM stop x
    JOIN GN_DW.BRONZE_CRM.TD_MS_MSG_AT_SNDNG_DTLS s
        ON s.mber_no = x.mber_no
       AND TO_DATE(s.sndng_dt) <= x.stop_date
    GROUP BY x.mber_no, x.stop_date
)
SELECT
    CASE
        WHEN DATEDIFF(day, last_send_date, stop_date) = 0 THEN '당일(D+0)'
        WHEN DATEDIFF(day, last_send_date, stop_date) BETWEEN 1 AND 5 THEN 'D+1~5'
        WHEN DATEDIFF(day, last_send_date, stop_date) BETWEEN 6 AND 10 THEN 'D+6~10'
        WHEN DATEDIFF(day, last_send_date, stop_date) BETWEEN 11 AND 30 THEN 'D+11~30'
        WHEN DATEDIFF(day, last_send_date, stop_date) BETWEEN 31 AND 90 THEN 'D+31~90'
        ELSE 'D+91 이상'
    END AS "발송_중단_간격",
    COUNT(*) AS "중단건수",
    ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 1) AS "비중_PCT"
FROM prev_send
GROUP BY 1
ORDER BY 2 DESC;

-- [1-2-B] 채널별(알림톡 vs 이메일) 중단 반응 간격 및 누적 도달률 비교
WITH stop AS (
    SELECT mber_no, TO_DATE(spnsr_dscntc_de, 'YYYYMMDD') AS stop_date
    FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_DSCNTC
    WHERE spnsr_dscntc_de BETWEEN '20250101' AND '20251231'
), sends AS (
    SELECT '1.알림톡' AS ch, mber_no, TO_DATE(sndng_dt) AS send_date
    FROM GN_DW.BRONZE_CRM.TD_MS_MSG_AT_SNDNG_DTLS
    UNION ALL
    SELECT '2.이메일', mber_no, TO_DATE(sndng_de)
    FROM GN_DW.BRONZE_CRM.TD_MS_EMAIL_SNDNG_DTLS
), gap AS (
    SELECT s.ch, x.mber_no, x.stop_date,
           MAX(s.send_date) AS last_send_date
    FROM stop x
    JOIN sends s
        ON s.mber_no = x.mber_no
       AND s.send_date <= x.stop_date
    GROUP BY s.ch, x.mber_no, x.stop_date
)
SELECT
    ch AS "채널",
    COUNT(*) AS "중단건수",
    ROUND(COUNT(CASE WHEN DATEDIFF(day, last_send_date, stop_date) = 0
                     THEN 1 END) * 100.0 / COUNT(*), 1) AS "D0_PCT",
    ROUND(COUNT(CASE WHEN DATEDIFF(day, last_send_date, stop_date) <= 5
                     THEN 1 END) * 100.0 / COUNT(*), 1) AS "D5_누적_PCT",
    ROUND(COUNT(CASE WHEN DATEDIFF(day, last_send_date, stop_date) <= 30
                     THEN 1 END) * 100.0 / COUNT(*), 1) AS "D30_누적_PCT",
    ROUND(AVG(DATEDIFF(day, last_send_date, stop_date)), 1) AS "평균간격_일"
FROM gap
GROUP BY 1
ORDER BY 1;
```

### 1-3. [L-2] 중단 보고서 후원사업 축 귀속 기준

* **확인 및 결정 요청 사항**:
  1. 중단 보고서의 후원사업 집계 축을 **'실제 해지한 사업(가)'**으로 볼지, **'최초 유입(개발) 사업(나)'**으로 볼지 확정.
  2. 한 회원이 **같은 날 2개 이상의 후원사업을 동시 중단**한 경우(전체 중단의 4.39%, 51,859건)의 처리 방식:
     * **(A) 대표 1개 사업 귀속**: 나머지 사업 중단은 보고서에서 제외
     * **(B) 사업 수로 분수 배분**: 사업별 중단 건수가 소수로 표기됨(예: 0.5건)
     * **(C) 사업마다 1건씩 중복 계상**: 사업별 합계가 실제 총 중단 회원수보다 커짐
* **데이터 현황 및 실측 근거**:
  * 중단 약정(1,337,780건) 중 **최초 유입 사업과 해지 사업이 불일치하는 비율은 16.93%(226,544건)**임.
  * 중단 사건의 **95.61%는 1개 사업 단독 중단**이므로, 영향 범위는 동시 중단인 4.39%에 한정됨.
  * 🔴🔴 **[BLOCKING-5 연계] 현재 DW 파이프라인 상태**: 현업 의사결정 전까지 1.56배 팬아웃(과대계상) 방지를 위해 `GOLD.FACT_MEMBER_EVENT`의 `STOP` 행에서 `SPONSORSHIP_SK` 및 `CAMPAIGN_SK`가 **전건 `0` 센티넬로 차단**되어 있음 (회신 완료 시 귀속 규칙 배선).
* **실증 쿼리**:

```sql
-- [1-3] 최초 유입(획득) 사업 vs 실제 중단 사업 불일치 조합 상위 20건
WITH acq AS (
    SELECT mber_no,
           MIN_BY(spnsr_bsns_id, occrrnc_de) AS acq_spnsr_bsns_id
    FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_DVLP_AMT
    WHERE spnsr_bsns_id IS NOT NULL
    GROUP BY mber_no
)
SELECT
    bn.spnsr_bsns_nm AS "획득_후원사업_나",
    bs.spnsr_bsns_nm AS "중단_후원사업_가",
    COUNT(*) AS "약정건수"
FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_BSNS b
JOIN GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR s
    ON s.spnsr_no = b.spnsr_no
JOIN acq a
    ON a.mber_no = s.mber_no
LEFT JOIN GN_DW.BRONZE_CRM.TM_CM_SPNSR_BSNS_INFO bn
    ON bn.spnsr_bsns_id = a.acq_spnsr_bsns_id
LEFT JOIN GN_DW.BRONZE_CRM.TM_CM_SPNSR_BSNS_INFO bs
    ON bs.spnsr_bsns_id = b.spnsr_bsns_id
WHERE b.spnsr_dscntc_yn = 'Y'
GROUP BY 1, 2
ORDER BY 3 DESC
LIMIT 20;

-- [1-3-B] 중단 약정 전체 대비 획득-중단 사업 불일치율 집계
WITH acq AS (
    SELECT mber_no, MIN_BY(spnsr_bsns_id, occrrnc_de) AS acq_id
    FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_DVLP_AMT
    WHERE spnsr_bsns_id IS NOT NULL
    GROUP BY mber_no
)
SELECT
    COUNT(*) AS "중단약정_전체",
    COUNT(CASE WHEN b.spnsr_bsns_id <> a.acq_id THEN 1 END) AS "불일치_건수",
    ROUND(COUNT(CASE WHEN b.spnsr_bsns_id <> a.acq_id THEN 1 END)
          * 100.0 / COUNT(*), 2) AS "불일치율_PCT"
FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_BSNS b
JOIN GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR s ON s.spnsr_no = b.spnsr_no
JOIN acq a ON a.mber_no = s.mber_no
WHERE b.spnsr_dscntc_yn = 'Y';

-- [1-3-C] 같은 날 동시 중단된 사업 수별 중단 사건 분포
WITH x AS (
    SELECT s.mber_no,
           b.spnsr_dscntc_de AS stop_de,
           COUNT(DISTINCT b.spnsr_bsns_id) AS bsns_n
    FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_BSNS b
    JOIN GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR s ON s.spnsr_no = b.spnsr_no
    WHERE b.spnsr_dscntc_yn = 'Y'
      AND b.spnsr_dscntc_de IS NOT NULL
    GROUP BY 1, 2
)
SELECT
    bsns_n AS "같은날_중단사업수",
    COUNT(*) AS "중단사건수",
    ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 2) AS "비중_PCT"
FROM x
GROUP BY 1
ORDER BY 1;
```

## 2. 코드 체계 및 데이터 정제 영역

### 2-1. [I-2] 행사 참여상태 및 이상치 데이터 정제 승인

* **확인 및 결정 요청 사항**:
  1. 웹 보안 스캐너 침투로 유입된 **특수문자 `)` 행(12행 / 회원 3명, 2024-02-14 발생)**의 DW 집계 제외(삭제) 공식 승인.
  2. `S+8자리` 회원번호 중 **일시회원 마스터에도 없는 19종**의 처분 기준 (삭제 vs 비회원 처리).
  3. `S+8자리`는 일시회원 정규 체계로 정상 적재 처리(997종 정상 매칭 확인 완료).
* **데이터 현황 및 실측 근거**:
  * 특수문자 `)` 유입은 2024-02-14 단일 일자에 12행 발생하여 스캐너 유입이 확실함.
  * `S+8자리` 회원번호 1,016종 중 **997종은 일시회원 마스터(`TM_MM_ONCE_MBER_INFO`)에 정상 매칭**되며, 미매칭은 19종에 불과함.
* **실증 쿼리**:

```sql
-- [2-1] 특수문자 ')' 침투 행 실측
SELECT
    TO_CHAR(partcpt_dt, 'YYYY-MM-DD') AS "참여일",
    COUNT(*) AS "이상값행수",
    COUNT(DISTINCT mber_no) AS "관여회원수"
FROM GN_DW.BRONZE_CRM.TD_MS_EVENT_PRTCPNT_DTL
WHERE mber_no = ')' OR partcpt_chnnl_cd = ')' OR partcpt_path_cd = ')'
   OR partcpt_stat_cd = ')' OR rm = ')' OR rm2 = ')'
GROUP BY 1
ORDER BY 1;

-- [2-2] S+8자리 형식 회원번호 예시 조회
SELECT DISTINCT mber_no AS "S형식_회원번호"
FROM GN_DW.BRONZE_CRM.TD_MS_EVENT_PRTCPNT_DTL
WHERE REGEXP_LIKE(mber_no, '^S[0-9]{8}$')
ORDER BY 1
LIMIT 20;

-- [2-2-B] S+8자리 회원의 일시회원 마스터 매칭 여부 검증
SELECT
    COUNT(DISTINCT p.mber_no) AS "S형식_종수",
    COUNT(*) AS "S형식_행수",
    COUNT(DISTINCT CASE WHEN o.once_mber_no IS NOT NULL
                        THEN p.mber_no END) AS "마스터_매칭_종수",
    COUNT(DISTINCT CASE WHEN o.once_mber_no IS NULL
                        THEN p.mber_no END) AS "마스터_미매칭_종수"
FROM GN_DW.BRONZE_CRM.TD_MS_EVENT_PRTCPNT_DTL p
LEFT JOIN GN_DW.BRONZE_CRM.TM_MM_ONCE_MBER_INFO o
       ON o.once_mber_no = p.mber_no
WHERE REGEXP_LIKE(p.mber_no, '^S[0-9]{8}$');
```

### 2-2. [M-2, M-4, M-5, M-6] 발송 서비스 코드 체계 및 발송상태2 원천 컬럼 지정

* **확인 및 결정 요청 사항**:
  1. 공통코드 사전(`MS056~MS059`)에 미등재된 **통신사 전송 실패코드 5종의 한글 표준 명칭** 제공.
     * 상위 2종(`7320`: 291,869건, `7319`: 208,713건)이 미등재 전체의 99.0%를 차지함.
  2. 알림톡의 통신사 실패코드(`TRNSMS_FAILR_CD_ID`)를 요건상의 「발송상태2」로 확정 채택할지 여부.
  3. 🟠 **[O59-P-1] `FACT_SERVICE_EVENT.SEND_STATUS2` 처분 방향 확정**: 통신사 실패코드를 그대로 적재할지, 전 채널 표준 실패 사유로 그룹핑하여 제공할지 처분 확정.
  4. 채널별(이메일, 알림톡)로 `SNDNG_TY_CD` 코드값 체계가 상이한 것이 의도된 설계인지 확인.
* **데이터 현황 및 실측 근거**:
  * 전체 33종 실패코드 중 미등재 코드는 5종(505,541행)이며, 사전에는 146개 코드가 이미 등재되어 있어 5종의 라벨만 추가하면 해소됨.
* **실증 쿼리**:

```sql
-- [2-3] 채널별 발신유형 및 발송결과 코드값 분포
SELECT 'EMAIL TM_MS_EMAIL_SNDNG' AS "채널", sndng_ty_cd AS "발신유형코드", COUNT(*) AS "행수"
FROM GN_DW.BRONZE_CRM.TM_MS_EMAIL_SNDNG GROUP BY 1, 2
```

```sql
-- [2-6] 원천 EVENT_DIV_CD 값을 100% 포함하는 후보 공통코드군 목록 조회
WITH src AS (
    SELECT DISTINCT event_div_cd AS v
    FROM GN_DW.BRONZE_CRM.TM_MS_EVENT
    WHERE event_div_cd IS NOT NULL
), src_n AS (
    SELECT COUNT(*) AS need FROM src
), cand AS (
    SELECT d.cd_id,
           COUNT(DISTINCT s.v) AS covered
    FROM GN_DW.BRONZE_CRM.TC_CMMN_DTL_CD d
    JOIN src s ON s.v = d.dtl_cd_id
    GROUP BY d.cd_id

    cc.cd_nm AS "코드군명",

      WHERE z.cd_id = c.cd_id) AS "코드군_상세코드수",

        WITHIN GROUP (ORDER BY d2.dtl_cd_id) AS "라벨_예시"

JOIN GN_DW.BRONZE_CRM.TC_CMMN_CD cc ON cc.cd_id = c.cd_id
JOIN GN_DW.BRONZE_CRM.TC_CMMN_DTL_CD d2
      ON d2.cd_id = c.cd_id
     AND d2.dtl_cd_id IN (SELECT v FROM src)
WHERE c.covered = (SELECT need FROM src_n)

ORDER BY 5;
```

```sql
-- [3-3-B] 후원사업 약어코드 종수 실측 (6종 확인)
```

```sql
-- [5-3] 방송광고(VIDEO) 성과 지표(전환콜 vs 인바운드콜) 적재 현황
SELECT
```

### 5-2. [J-2] 방송 광고 초수(AD_SEC) 단위 정규화 확인

* **확인 및 결정 요청 사항**:
  1. 방송 광고 초수 중 8자리 숫자(`30000000`, `60000000`, `90000000`)를 **마이크로초로 판단하여 `÷ 1,000,000` (⇒ 30초, 60초, 90초)으로 환산하는 공식 정규화 규칙 승인**.
  2. 시분초 표기(`00:01:00` 등 33,267건)와 8자리 정수 표기(1,932건)가 혼재하는 원인 확인.
* **데이터 현황 및 실측 근거**:
  * 8자리 정수 3종을 1,000,000으로 나눈 결과(30, 60, 90초)가 시분초 표기의 실제 최빈값들과 1:1로 일치함.
* **실증 쿼리**:

```sql
-- [5-4] 방송광고 초수(AD_SEC) 표기 방식별 건수 집계
SELECT
    CASE WHEN ad_sec LIKE '%:%' THEN '시:분:초 표기' ELSE '숫자 표기' END AS "표기방식",
    ad_sec AS "원천값",
    COUNT(*) AS "건수"
FROM GN_DW.BRONZE_AGENCY.VIDEO_AD_CMPGN_DTLS
WHERE ad_sec IS NOT NULL
GROUP BY 1, 2
ORDER BY 1, 3 DESC;

-- [5-4-B] 시분초 표기 및 8자리 정수의 초(Sec) 환산 정규화 결과 검증
SELECT
    ad_sec AS "원천값",
    CASE WHEN ad_sec LIKE '%:%' THEN '시:분:초' ELSE '숫자(µs 가정)' END AS "표기방식",
    COUNT(*) AS "건수",
    CASE
        WHEN ad_sec LIKE '%:%'
            THEN TO_NUMBER(SPLIT_PART(ad_sec, ':', 2)) * 60
                 + TO_NUMBER(SPLIT_PART(ad_sec, ':', 3))
        ELSE TRY_TO_NUMBER(ad_sec) / 1000000
    END AS "환산_초"
FROM GN_DW.BRONZE_AGENCY.VIDEO_AD_CMPGN_DTLS
WHERE ad_sec IS NOT NULL
GROUP BY 1, 2
ORDER BY 4, 3 DESC;
```

### 5-3. [N-9] 캠페인명 시점 동결(Snapshot) 확장 여부

* **확인 및 결정 요청 사항**:
  * 캠페인 마스터의 캠페인명 개칭 시 **과거 코호트 실적의 캠페인명을 소급 변경(현행 유지)할지, 획득 당시 명칭으로 고정(스냅샷 파이프라인 신설)할지** 결정.
    * **(A) 소급 변경(현행 유지)**: 보고서상 항상 최신 명칭으로 조회되나 과거 시점 리포트와 명칭 불일치 발생.
    * **(B) 획득 시점 고정**: 과거 시점 리포트가 그대로 재현되나 별도의 개칭 이력 관리 파이프라인 신설 필요.
* **데이터 현황 및 실측 근거**:
  * 캠페인 마스터(`TM_CM_CMPGN_MNG`, 36,163행)는 변경 이력 테이블이 없으며, 최근 3년간 14,336개 캠페인이 수정되는 등 명칭 변경이 빈번함.
  * 현재 GOLD의 `ACQ_CAMPAIGN_NAME`은 마스터의 최신 명칭과 100% 동일하게 유지되고 있어 실질적인 시점 동결이 이루어지지 않는 상태임.
* **실증 쿼리**:

```sql
-- [5-5] 캠페인별 최종수정일 및 획득 회원수 상위 20건
SELECT
    c.cmpgn_cd AS "캠페인코드",
    c.cmpgn_nm AS "캠페인명_현재값",
    TO_CHAR(c.last_updt_dt, 'YYYY-MM-DD') AS "마스터_최종변경일",
    COUNT(DISTINCT s.mber_no) AS "획득회원수"
FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR s
JOIN GN_DW.BRONZE_CRM.TM_CM_CMPGN_MNG c
    ON c.cmpgn_cd = s.cmpgn_cd
GROUP BY 1, 2, 3
ORDER BY 4 DESC
LIMIT 20;

-- [5-5-B] GOLD 획득 캠페인명 vs 현재 캠페인 마스터명 일치 여부 대조
SELECT
    COUNT(*) AS "대조_행수",
    COUNT(CASE WHEN a.ACQ_CAMPAIGN_NAME <> c.CAMPAIGN_NAME
               THEN 1 END) AS "불일치_행수",
    COUNT(DISTINCT CASE WHEN a.ACQ_CAMPAIGN_NAME <> c.CAMPAIGN_NAME
                        THEN a.ACQ_CAMPAIGN_SK END) AS "불일치_캠페인수",
    COUNT(CASE WHEN a.ACQ_CAMPAIGN_NAME IS NULL THEN 1 END) AS "동결명_NULL_행수"
FROM GN_DW.GOLD.DIM_MEMBER_ACQUISITION a
JOIN GN_DW.GOLD.DIM_CAMPAIGN c
  ON c.CAMPAIGN_SK = a.ACQ_CAMPAIGN_SK;

-- [5-5-C] 연도별 캠페인 마스터 수정 건수 추이
SELECT
    LEFT(TO_CHAR(last_updt_dt, 'YYYYMMDD'), 4) AS "마스터_수정연도",
    COUNT(*) AS "캠페인수",
    ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 1) AS "비중_PCT"
FROM GN_DW.BRONZE_CRM.TM_CM_CMPGN_MNG
GROUP BY 1
ORDER BY 1;
```

### 5-4. [GOLD 마트 후보] 설문 응답 분석 마트(FACT_SURVEY_RESPONSE) 도입 제안 및 중복 3종 기각

* **확인 및 결정 요청 사항**:
  1. 설문 응답 원천 데이터 기반의 **`FACT_SURVEY_RESPONSE`(설문 응답 팩트) 마트 도입 필요성 및 비즈니스 분석 활용 여부** 확인.
  2. 기검토된 3종 모델의 **신설 불필요(기각) 확인**:
     * `FACT_MEMBER_IDENTITY_XREF` ➔ `GOLD.DIM_MEMBER_IDENTITY`로 이미 1회원 1행 차원 완결 배선됨 (신설 불필요).
     * `DIM_PAYMENT_METHOD` ➔ `GOLD.DIM_PAYMENT`로 이미 배포되어 `FACT_MEMBER_FEE` 등에 조인 중 (신설 불필요).
     * `DIM_POSTAL` ➔ `GOLD.FACT_SERVICE_EVENT`의 `CHANNEL='PSTMTR'`로 통합 발송 관리 중 (신설 불필요).
* **데이터 현황 및 실측 근거**:
  * 설문 관련 원천 데이터는 적재되어 있으나 현행 32개 핵심 지표 범위에는 포함되지 않음.
  * YAGNI(과잉 엔지니어링 방지) 원칙에 따라 현업의 명시적 분석 요구 접수 시 `FACT_SURVEY_RESPONSE` 배선 착수 예정.
