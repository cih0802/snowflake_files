## 3. D3 🔴🔴 — 파일과 라이브가 **똑같이 틀리면** 드리프트 게이트는 🟢 다

### 3-1. 실측 (라이브)

`SHOW SEMANTIC VIEWS IN DATABASE GN_DW` = **17행**(O153 의 「SV 17종」 주장은 참).

🔴 그런데 `SV_MEMBER_EVENT` 의 COMMENT 원문(시정 전):

> *"Phase-1 회원 상태전이 SV (base: **GOLD.FACT_MEMBER_EVENT**, grain: 회원×일 사건 1행). …"*

동시 실측:

| 축 | 결과 |
|---|---:|
| 개명 **전** 이름 8종이 `GOLD`·`SERVING` 에 실재하는가 | **0** |
| 개명 **후** 이름 8종이 `GOLD` 에 실재하는가 | **8 / 8** |

⇒ 🔴 **그 COMMENT 는 라이브에 존재하지 않는 테이블을 가리켰다.**
그리고 파일 정본(`05_SV-Agent_ai/05_2_SV_DDL_MEMBER_EVENT.sql:174`)도 **같은 문자열**이었다.

### 3-2. 게이트가 왜 침묵했나 — 판정식의 구조적 한계

* `comment_drift_gate` 의 판정식 = **SHA256(파일) == SHA256(라이브)** ⇒ **둘이 같이 틀리면 통과**.
* `table_ddl_column_gate` = 컬럼 **집합·순서**만 본다(문안은 분모 밖).
* `doc_coord_gate` = **파일 경로** 실재만 본다(문서 안 **객체 이름**은 보지 않는다).
* `audit_ddl_rule7` = 실측 수치 금지 문안만 본다.

⇒ 🔴 **네 게이트가 전부 🟢 인 상태에서 잘못된 표명이 살아 있었다.** `R3-9`(게이트가 보지 않는 축)의 실물.

### 3-3. 왜 심각한가 — SV COMMENT 는 AI 컨텍스트다

Cortex Analyst·Agent 는 SV COMMENT 를 **질의 생성 컨텍스트**로 읽는다.
⇒ Agent 가 사용자에게 **존재하지 않는 테이블명을 안내**할 수 있다.
또한 `SV_MEMBER_EVENT` 만 **4블록 표준(정의/Grain/주의/원천)에서 빠져** 있었다
(나머지 16종은 `[Grain: …]. [활성 지표: …]. [주의: …]. [원천: …]` 형식).
⇒ O153 의 **「Semantic View 17종 … 4블록 표준 템플릿 반영 완결」 주장은 부분 거짓**이고
`comment_drift_gate` 는 **형식 축을 보지 않으므로** 이를 잡을 수 없었다.

### 3-4. 조치 (라이브 + 파일 동시)

```
ALTER SEMANTIC VIEW GN_DW.SERVING.SV_MEMBER_EVENT SET COMMENT = '… (base: GOLD.FACT_MEMBER_LIFECYCLE). [Grain: …]. [활성 지표: …]. [주의: …]. [원천: …].'
```
+ `05_SV-Agent_ai/05_2_SV_DDL_MEMBER_EVENT.sql:174` 동일 문안으로 교체.
🟢 검증 = `comment_drift_gate` rc=0 · GOLD 뷰 574/574 일치 · 금지 문안 0.

## 4-B. D5 🔴🔴 — DEC-52 표준(`[Grain:`)과 규칙7 면제(`grain` 소문자)가 어긋나 있었다

### 4-B-1. 발견 경로 — **내 시정이 게이트를 깨뜨려서** 드러났다

D3 을 고치며 `SV_MEMBER_EVENT` COMMENT 를 4블록 표준으로 바꾸자
`sv_rule7_scan.py` 가 **라이브 도달 위반 1건**을 냈다(그 전에는 0건).

| 축 | 값 |
|---|---|
| 걸린 축 | `소규모` = `[0-9]+\s*(?:행\|건\|명\|원)\b` |
| 걸린 토큰 | `[Grain: 회원 × 일 × 사건 **1행**]` |
| 면제 패턴(정본 = `sv_unit_gate.NUM_EXEMPT`) | `re.compile(r'grain[^.。]{0,30}?(?<![\d,])\d{1,2}\s*행')` — **플래그 없음** |
| 종전 문안 | 소문자 `grain: 회원×일 사건 1행` ⇒ **우연히 면제**되고 있었다 |

### 4-B-2. 왜 지금까지 안 보였나

나머지 **16종 SV** 는 `(1행=1회원)` 처럼 **`=` 를 써서 다른 면제**
(`\d+\s*행[*\s]*=[^,·.]{0,12}`)에 걸렸다.
⇒ 🔴 **`DEC-52` 4블록 표준은 대문자 `[Grain:` 을 쓰는데 면제는 소문자만 봤고,
그 충돌이 「우연한 문안 차이」에 가려져 잠재해 있었다.**
`R3-9 ㉡`(같은 것을 다르게 재는 지점)의 실물이다.

### 4-B-3. 조치 — 문안이 아니라 게이트를 고쳤다

`sv_unit_gate.py` 의 grain 면제 2종에 **`re.I`** 를 붙였다(`audit_ddl_rule7`·`sv_rule7_scan`·
`agent_tool_claim_gate` 가 **같은 객체를 공유**하므로 1곳 수정으로 전 표면에 적용된다).

🟢 **무력화 아님 검증** = `\d{1,2}` 자릿수 제한은 그대로 두었다
⇒ *"grain 기준 적재 2,170,572행"* 같은 실측치는 **여전히 잡힌다**
(`test_agent_tool_claim_gate` 가 그 축을 단정하고 통과했다).

🔴 **판정** = 문안을 면제에 맞추는 것(= `=` 를 넣어 우회)은 **같은 함정을 다음 사람에게 남긴다.**
표준이 옳으면 **게이트를 표준에 맞춘다.**
