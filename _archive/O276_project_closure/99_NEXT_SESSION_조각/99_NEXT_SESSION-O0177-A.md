   나는 `dbt build`/`compile`/`run` 을 **10회 직접 실행**했다(`R4-1`·`R2-1` 확정위반).

   ⇒ 원인은 무지가 아니라 **탐색 생략**이다. 🔴 「이 규칙을 지키면 무엇을 못 하나」를 물으면
   대개 **이미 누군가 그 구멍을 메워 뒀다**.

2. 🔴🔴 **증분화는 「창 밖 불변」을 얻는 대신 「창 밖 검증」을 잃는다 — 내가 없앤 방어를 세라.**
   롤링 윈도우로 바꾸자 **원천이 일자를 잃으면 하류에 영구 고아로 남는** 실패 모드가 새로 생겼다.
   전량 TRUNCATE 시절에는 **구조적으로 불가능**했던 것이다. 내 감시 테스트 초판은 그 반대쪽만 봤다.
   ⇒ 🟢 설계를 바꿀 때 **「이 변경이 없애는 암묵적 보증」**을 목록화하라.

3. 🔴🔴 **「죽어야 알린다」는 적재 경로의 규약이고 감시 경로에서는 정반대다.**
   감시 쿼리에 `TO_DATE` 를 써서 입력 불량 시 **감시기가 예외로 죽게** 만들어 뒀다
   ⇒ `TRY_TO_DATE` + 불량행을 **보이는 행**으로. 같은 프로젝트 안에서 두 규약이 공존한다.

4. 🔴🔴 **오버라이드는 「전달됐다」가 아니라 「렌더된 결과가 바뀌었다」로 확인한다**(`J1` 계열).
   `--vars {k:v}`(콜론 뒤 공백 없음)가 **에러 없이 조용히 무시**돼 멱등성 테스트를 한 번 헛돌렸다.

5. 🟢 **「게이트 전종 통과」는 데이터 범위가 맞다는 증거가 아니다.**
   3일치 절단 상태와 33일치 상태에서 **562노드의 PASS/WARN/ERROR 가 전부 동일**했다.

6. 🟢 **편집 결과는 도구의 context 표시창이 아니라 `grep` 으로 확인한다**(내가 한 번 오판해 오보했다).
