### ▣ O181-A-6 🔴 `--vars` 판별 실험 (사용자 실행 대기 · `R4-1` 정지점)

> 🔴 **에이전트는 dbt 를 실행하지 않는다** — 명령문 작성·결과 해석까지만 담당한다(`R4-1`).
> 🟢 이 실험은 **남은 단 하나의 원인 축**(「전달 실패」)을 두 갈래로 가른다.
> 🔴 **안전** = 둘 다 `--select BIGQUERY_BASIC` 단일 모델이고 `dbt_dt_ranges` 를 **좁은 1일 창**으로
>   주므로 대규모 재적재가 아니다. 🟠 그래도 실행 뒤에는 **[3-3-a] 일자 수 대사**를 반드시 하라
>   (정본 = `10_dbt_pipeline/02_dbt_parse_compile_build.sql` Step 3-3).

**실험 A — 전달 자체를 검증한다(가장 값싸다 · 적재 0)**

```
dbt compile --select BIGQUERY_BASIC --vars '{"bigquery_lookback_days": 999}'
```
· 🟢 **판정식** = 컴파일된 SQL 의 창 하한이 **999일 전**으로 나오면 **전달은 된다**
  ⇒ 그때 원인은 「전달 실패」가 아니라 **관측 오진**이었다(종전 결론을 정정해야 한다).
· 🔴 하한이 기본값 **3일**이면 **전달이 실패**한 것이다 ⇒ 실험 B 로 형태를 바꿔 재시도한다.
· 🟢 `compile` 은 적재를 하지 않으므로 **되돌릴 것이 없다**.

**실험 B — 인용 형태를 바꿔 같은 것을 던진다(따옴표 충돌 가설)**

```
dbt compile --select BIGQUERY_BASIC --vars "{bigquery_lookback_days: 999}"
```
· 🟢 A 는 실패하고 B 는 듣는다면 원인은 **ARGS/셸 단계의 JSON 따옴표 충돌**로 확정된다
  ⇒ 처방 = 런북의 `--vars` 금지 문안을 **「이 형태로 쓰라」로 교체**한다.
· 🔴 **둘 다 실패하면** 원인은 실행 경로(배포본 실행이 런타임 인자를 유실)다
  ⇒ 그때는 현행 처방(`dbt_project.yml` 주석 해제 + 재배포)이 **옳은 유일 경로**이므로
  런북의 금지 문안을 **근거와 함께 확정**하고 이 항목을 닫는다.

🔴 **어느 결과든 문서를 고쳐야 한다** — 지금 런북 2곳이 *"조용히 무시된다"* 로 **원인 없이**
단정하고 있다(`02_dbt_parse_compile_build.sql:110` · `11_일적재pipeline 구성/00_개요_및_실행순서.md:82`).
🟢 판정식 = **「무시된다」는 현상이고 원인이 아니다** — 현상만 적은 금지문은 다음 세션이 못 고친다.
