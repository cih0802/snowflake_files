### 2. 비판적 자기검토 (S8 직후 · 별도 산출물 `_드리프트/자기검토_보고서.md`)

이전 세션과 이번 세션 작업 **전체**(A0~A8 · D01~D14 · N01~N08 · 생성기 6종 · dbt 변경)를 대상으로, 「틀렸을 수 있는 것」을 찾는 관점으로 검토한다. 칭찬·요약 금지. 항목마다 근거(SQL 재실행 결과 또는 파일:행)를 붙인다.

1. **숫자 재현** — 각 산출물에서 숫자 10개를 무작위로 골라 근거 SQL/생성기로 다시 계산해 일치하는지. 근거 쿼리가 없는 숫자(`TBD` 제외)가 있으면 목록화.
2. **단정의 근거** — 「~이다/없다/전부」 형태의 문장 중 실측 없이 쓴 것. 특히 이번 세션에 실제로 나온 유형을 다시 찾는다:
   - 1개 표본을 보고 전체를 단정(예: 「원천 PII 는 BRONZE 로 들어오지 않는다」 → 실제로는 13컬럼 존재)
   - 존재 확인 없이 객체명 사용(예: 없는 WH `GN_DW_ADMIN_WH`)
   - 확인 안 한 테스트·동작을 사실처럼 기재(예: 「dbt relationships 는 warn 이라 통과」, 「Agent 가 128% 를 답한다」)
   - 분류기·도구 결과를 그대로 신뢰(SYSTEM$CLASSIFY 가 한국어 이름·휴대폰을 놓침)
3. **원문 대조** — 95 프롬프트가 지정한 원본을 각 산출물이 실제로 전량 읽었는지 `source_docs` 와 대조. 「미독」·「해시만」 표기가 정당한지 재판정.
4. **ENV 분리** — 계정 의존 값이 md 본문에 하드코딩돼 있지 않은지(규칙 10). 운영계로 가져가 `env_capture` → 생성기만 다시 돌려 갱신되는지.
5. **미실행 SQL 안전성** — A2·A3·N01·N02 미실행 SQL 의 실행 롤·선행 권한·롤백·「붙이면 즉시 위반/실패」 지점이 문서에 있는지. compile 검증 범위(어떤 롤로 했는지) 명시 여부.
6. **결정 반영 일관성** — 사용자 결정(시뮬레이터 GRANT · ANALYST OPS 회수 · 개발계 수동 · DIM_DATE SILVER 삽입 · A8-28 결과)이 드리프트·A8·원천 문서·80번 사본에 모두 같은 내용으로 반영됐는지.
7. **작업 규칙 위반 이력** — 특히 R1-7-2(같은 파일 병렬 edit)는 이번 세션에 **6회** 위반했다. 위반이 남긴 손상이 없는지 해당 파일 전부 재확인하고, 재발 방지책(한 응답에 같은 경로 edit 1개만)을 보고서에 적는다.
8. **결론** — 「운영계로 그대로 가져가도 되는가」를 산출물별 예/아니오/조건부로 판정하고, 조건부는 무엇을 먼저 해야 하는지 적는다.
