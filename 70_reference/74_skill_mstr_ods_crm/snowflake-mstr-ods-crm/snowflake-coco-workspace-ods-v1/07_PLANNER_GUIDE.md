# MSTR_ODS 기반 Streamlit 기획자 가이드

## 이 가이드의 대상

이 문서는 SQL, 데이터베이스의 영문 테이블명·컬럼명·코드값을 모르는 기획자가 Snowflake CoCo에 MSTR_ODS 기반 Streamlit 작업을 요청할 때 사용한다.

기획자는 기술적인 데이터 연결 방식을 정하지 않는다. 화면의 목적과 업무 의미를 설명하고, CoCo가 Reference와 실제 Snowflake 구조를 확인하도록 요청한다.

## 가장 중요한 첫 줄

ODS 기반 작업은 모든 요청의 첫 줄에 다음을 입력한다.

```text
$mstr-ods-crm-schema
```

이 호출이 없으면 ODS 전용 테이블·JOIN·집계·검증 규칙이 적용되지 않을 수 있다.

## 기획자가 작성할 내용

다음 일곱 가지면 충분하다.

1. 화면 또는 업무 이름
2. 화면을 사용하는 목적
3. 보고 싶은 수치
4. 기본 조회기간
5. 필요한 업무 필터
6. 수와 건의 업무적 차이
7. 비교할 기존 화면·엑셀·기준값

모르는 내용은 추측하지 말고 `모름`이라고 작성한다.

## 기획자가 작성하지 않아도 되는 내용

- 영문 테이블명
- 영문 컬럼명
- 내부 코드값
- JOIN 키
- SQL 문법
- 중복 제거 함수
- Snowflake 데이터 타입

CoCo가 이 내용을 기획자에게 다시 선택하라고 요구하면 업무용어로 질문하도록 요청한다.

## 안전한 작업 순서

### 1단계: 분석

```text
바로 구현하지 말고 사용할 업무 데이터, 각 수치의 의미, 날짜 기준,
중복 위험, 확정된 내용과 미확정 내용을 먼저 설명해주세요.
제가 결정할 질문은 한국어 선택지로 최대 3개만 제시해주세요.
```

### 2단계: 업무기준 확정

CoCo가 제시한 질문에 업무 기준으로 답한다.

```text
- 회원 수는 같은 회원을 한 명으로 계산합니다.
- 참여 건은 같은 회원의 여러 참여를 각각 계산합니다.
- 후속 행동은 발송 후 30일까지 인정합니다.
```

### 3단계: 구현

```text
앞서 확정한 기준으로 구현해주세요.
데이터 계산을 먼저 만들고 검증한 뒤 Streamlit에 연결해주세요.
KPI, 표, 차트, 다운로드가 동일한 계산 결과를 사용해야 합니다.
```

### 4단계: 검증

```text
서로 다른 대표 기간 2개를 검증해주세요.
원천 행 수, 고유 회원 수, 고유 건수, 미매칭, JOIN 후 증가,
표·KPI·다운로드 총계를 비교해주세요.
```

## 요청 유형별 주의사항

| 요청 | 반드시 명시할 내용 |
|---|---|
| 신규 화면 | 화면 목적, 지표, 기간, 필터, 사용자 |
| 기존 화면 UI 변경 | 데이터 계산을 유지할지 여부 |
| 지표 변경 | 기존 정의와 새 정의, 영향 범위 분석 요청 |
| 수치 검증 | 조회조건, 기준값, 현재값, 비교자료 |
| 오류 진단 | 코드 수정 금지 여부, 처음 차이가 나는 단계 요청 |

## 답변을 승인하면 안 되는 경우

- 근거 없이 테이블이나 컬럼을 추정함
- 컬럼 이름이 같다는 이유로 데이터를 연결함
- `DISTINCT`만 추가해 중복을 숨김
- 기존 숫자에 맞추려고 특정 데이터를 임의 제외함
- 현재 상태를 과거 상태라고 표시함
- 메일 링크 클릭을 확인 없이 GA 클릭이라고 표시함
- 대표 기간 검증 없이 완료라고 보고함
