# 비개발 기획자를 위한 CoCo 자연어 요청 가이드

## 요청문에 꼭 포함할 다섯 가지

### 1. 화면의 목적

좋은 예:

```text
발송구분별로 실제 발송 결과와 이후 참여 행동을 비교하고 싶습니다.
```

피해야 할 예:

```text
대시보드 만들어줘.
```

### 2. 화면에서 볼 수치

수치 이름만 나열하지 말고 의미를 함께 적습니다.

```text
회원 수는 같은 회원이 여러 건을 가지고 있어도 한 명으로 보고 싶습니다.
중단 건은 회원 수가 아니라 실제 중단된 후원 건수를 보고 싶습니다.
```

### 3. 조회기간과 필터

```text
기본기간은 최근 3개월입니다.
기간, 법인, 부서, 발송구분으로 조회하고 싶습니다.
```

날짜 기준을 모르면 `모름`이라고 적어도 됩니다. CoCo가 후보 날짜의 업무 의미를 확인해야 합니다.

### 4. 화면 변경 범위

```text
이번 요청은 화면 배치와 색상만 변경하는 것입니다.
기존 지표 계산과 데이터 SQL은 변경하지 마세요.
```

또는:

```text
이번 요청은 발송 성공 수의 계산 기준도 변경하는 작업입니다.
영향받는 KPI, 표, 다운로드를 함께 찾아주세요.
```

### 5. 검증 기준

```text
2026년 8월 전체 법인의 기존 엑셀 합계는 발송 성공 수 000건입니다.
이 값을 비교 기준으로 사용하되 숫자를 강제로 맞추지는 마세요.
```

## 모르는 내용을 표현하는 방법

기획자가 모르는 기술 정보를 추측해서 작성하지 않습니다.

```text
- 발송일 기준: 모름
- 성공으로 인정할 상태: 모름
- 클릭률 분모: 모름
- 관련 데이터 위치: 모름
```

CoCo는 `모름`을 임의 계산 허용으로 해석하면 안 됩니다. Reference와 실제 데이터에서 확인하고, 확인할 수 없으면 쉬운 업무 질문을 해야 합니다.

## 기획자가 답하기 좋은 질문 형태

CoCo가 다음처럼 질문하도록 요청합니다.

- 발송 수는 `발송 대상 회원 수`와 `실제 발송을 시도한 건수` 중 어느 쪽인가요?
- 클릭률은 `클릭한 고유 회원 ÷ 성공한 고유 회원`과 `클릭 건수 ÷ 성공 건수` 중 어느 쪽인가요?
- 발송 후 행동은 `7일`, `30일`, `다음 발송 전` 중 어디까지 인정하나요?

다음과 같은 질문은 기획자에게 하지 않도록 합니다.

- `SND_YN='Y'`를 사용할까요?
- `R_NUM`으로 JOIN할까요?
- `SPNSR_BSNS_ID` 기준으로 DISTINCT할까요?

## 추천 진행 순서

1. 분석 요청
2. 업무 질문 답변
3. 확정된 지표 정의표 확인
4. 구현 요청
5. 대표 기간 검증
6. 화면 확인
7. 다운로드 결과 확인

분석과 구현을 한 문장에 모두 맡기지 않는 편이 안전합니다.
