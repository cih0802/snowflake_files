# 검증 체크리스트

## A. 변환 전

- [ ] 한글 리포트명과 화면 경로를 식별했다.
- [ ] 기준월/기간, 법인, 조직 등 조회조건을 기록했다.
- [ ] 기존 SQL이 처음부터 끝까지 포함되었다.
- [ ] SQL 밖의 MSTR 뷰 필터·부분합·동적 집계를 확인했다.
- [ ] 결과 1행의 업무 Grain과 전체합계 Grain을 구분했다.

## B. 매핑

- [ ] 모든 DW 팩트·차원·함수·프로시저를 목록화했다.
- [ ] 각 항목을 `확인/파생/미확인`으로 표시했다.
- [ ] 실제 Snowflake FQN과 컬럼을 `INFORMATION_SCHEMA` 또는 승인된 매핑 자료로 확인했다.
- [ ] 미확인 이름과 코드 의미를 추정하지 않았다.
- [ ] MSTR_DW 오브젝트를 배포 SQL에서 직접 참조하지 않는다.

## C. 로직 동등성

- [ ] JOIN 종류·키·NULL 처리가 동일하다.
- [ ] 원천 및 결과 Grain이 동일하다.
- [ ] 필터 적용 순서가 동일하다.
- [ ] Window의 파티션·정렬·동률 처리가 동일하다.
- [ ] DISTINCT 회원의 범위와 누계 기간이 동일하다.
- [ ] 공통코드의 그룹과 상세코드를 함께 확인했다.
- [ ] 금액 환산 건수와 소수 정밀도를 확인했다.
- [ ] 전체합계를 하위 행 단순합계로 만들지 않았다.

## D. 수치 대사

각 조건에서 다음 단계를 비교한다.

| 순서 | 비교 항목 | 확인할 값 |
|---:|---|---|
| 1 | 조회조건 | 파라미터, 시작일, 종료일, 포함 경계 |
| 2 | 대상범위 | 원천 행 수, 최소/최대 일자, 주요 코드 |
| 3 | 조인 | 조인 전후 행 수, 미매칭 키, 1:N 증폭 |
| 4 | 분류 | 코드별 행 수·회원 수·금액 |
| 5 | 중복 | 업무 키 중복, 회원 중복, 대표 키 |
| 6 | 집계 | 지표별 총계, 고유회원, 소수 정밀도 |
| 7 | 화면 | KPI·표·차트·다운로드 값의 일치 |

- [ ] 대표 조건 1개를 기준값과 대사했다.
- [ ] 다른 월·법인·조직 등 변형 조건 1개 이상을 대사했다.
- [ ] 차이가 있으면 최초 차이 단계와 대표 키를 기록했다.
- [ ] 스냅샷 차이와 계산 오류를 구분했다.
- [ ] 기준값을 맞추기 위한 하드코딩이나 임의 보정을 하지 않았다.

## E. APP/Streamlit

- [ ] 데이터 검증을 통과한 뒤 UI를 적용했다.
- [ ] Streamlit은 검증된 APP View만 조회한다.
- [ ] KPI·표·차트·다운로드가 같은 결과 집합을 재사용한다.
- [ ] 사용자 입력은 바인딩 또는 허용값 검증을 거친다.
- [ ] 개인정보와 무제한 회원 상세가 노출되지 않는다.
- [ ] 적용 조건과 스냅샷/현재재계산 구분을 화면에서 확인할 수 있다.

## 판정 문구

- `완료`: 매핑과 수치 검증을 모두 통과함
- `검증 필요`: 변환은 되었으나 기준 결과 또는 변형 조건 대사가 남음
- `자료 필요`: 로직에 영향을 주는 정의나 기준값을 확인할 수 없음
- `적용 중단`: 검증 실패 또는 개인정보/권한 위험 때문에 APP 적용 불가
