# 공통 업무·집계 규칙

## 수·건·금액 구분

- 회원 수: 최종 조회 범위에서 고유 회원을 다시 계산한다.
- 후원 건: 승인된 전체 후원 업무키를 기준으로 계산한다.
- 관계 건: 고유 결연관계 키를 계산한다.
- 납입 건: 상태 필터 후 고유 납입 키를 계산한다.
- 선물금 참여 수: 승인된 선물금 건에 참여한 고유 회원 수다.
- 선물금 참여 건: 승인된 전체 선물금 업무키의 고유 건수다.
- 서신 참여 수: 승인된 상태의 서신에 참여한 고유 회원 수다.
- 금액은 원천 거래 Grain으로 중복을 제거한 뒤 합산한다.

그룹별 고유 회원 수를 더해 전체 고유 회원 수를 만들지 않는다.

## 날짜

- 조회기간에는 어떤 업무 이벤트 날짜를 사용했는지 화면과 완료보고에 표시한다.
- 등록일·수정일은 업무 발생일이 아니다. 업무 정의가 확인된 경우에만 사용한다.
- 종료일은 사용자가 날짜로 입력하면 해당 날짜 전체를 포함하도록 반개구간 조건을 우선한다.
- 시간대는 Snowflake 세션과 원천 시간대 차이를 확인한다.

## 상태

- 요청·처리중·성공·완료·실패·취소·환불을 섞지 않는다.
- 재시도 이력이 있으면 최종 상태 선택 기준과 동률 처리 기준을 먼저 정의한다.
- 현재 상태 테이블과 이력 테이블을 구분한다.

## 비율

- 분자와 분모의 Grain이 같아야 한다.
- 전체 비율은 전체 분자 ÷ 전체 분모로 계산한다.
- 행별 백분율의 평균을 전체 비율로 사용하지 않는다.
- 분모가 0이면 0으로 임의 치환하지 말고 화면 표시 정책을 따른다.

## 성능

- 큰 상세 테이블은 조회기간과 마스터키를 먼저 제한한다.
- 화면에서 필요한 컬럼만 조회한다.
- 원시 1:N 테이블은 JOIN 전에 목표 Grain으로 집계한다.
- Streamlit에서 동일 대형 SQL을 KPI·표·다운로드마다 반복하지 않는다.
