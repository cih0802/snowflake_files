# 기획자용 CoCo 요청 템플릿

영문 컬럼명·테이블명·코드값을 알 필요가 없다. 화면에서 확인 가능한 한글명과 조건만 입력하고, MSTR SQL은 수정하지 않은 전체 원문을 첨부한다.

## 1. 신규 MSTR 리포트 전체 변환

````text
$snowflake-mstr-dw-to-ods
모드: 신규 리포트 변환
리포트명: [화면의 한글 리포트명]
화면 경로: [상위 메뉴 > 하위 메뉴]
조회조건: [예: 2026년 6월, 사단법인, 전체 부서]
필요 화면: [KPI/표/차트/다운로드]
기준 결과: [MSTR 총계 또는 결과 엑셀, 없으면 없음]
과거월 기준: [월마감 그대로 / 현재 ODS 현황값 / 모름]
요청: MSTR_DW SQL을 업무 명세로 분석한 뒤 실제 GN_DW.BRONZE_CRM 원천으로 재구성해줘. 미확인 값은 추정하지 말고 쉬운 질문을 최대 3개만 해줘. 검증 전에는 Streamlit을 수정하지 마.
MSTR SQL:
```sql
[MSTR에서 복사한 SQL 전체]
```
````

## 2. 기존 리포트 UI 변경

```text
$snowflake-mstr-dw-to-ods
모드: 화면 변경
리포트: [한글 리포트명]
조회조건: [기간/법인/조직]
화면 요청: [바꿀 필터·표·차트·다운로드]
유지할 내용: 기존 검증된 계산식과 총계
요청: Manifest에서 REPORT_ID를 찾고 해당 Source of Truth와 Validation Gate만 읽어줘. 다른 리포트 계산은 수정하지 마.
```

## 3. 수치 차이 진단

```text
$snowflake-mstr-dw-to-ods
모드: 데이터 검증
리포트: [한글 리포트명]
비교 조건: [기준월/기간, 법인, 조직]
MSTR 기준값: [한글 지표명=값]
Snowflake 값: [한글 지표명=값]
요청: 조회조건→대상범위→조인→분류→중복→집계→화면표시 순서로 최초 차이 지점을 찾아줘. Snapshot 차이는 계산 오류와 분리하고 임의 보정하지 마.
첨부: [MSTR SQL, Snowflake SQL, 결과 파일]
```

## 토큰 절감 규칙

- 공통 Reference 내용은 프롬프트에 복사하지 않는다.
- 한 번에 한 리포트와 한 가지 결과만 요청한다.
- `리포트·조건·목표·기준값·SQL`만 전달한다.
- 이미 Workspace에 있는 파일은 파일명만 지정한다.
- SQL은 일부가 아니라 전체를 한 번만 붙인다.
- 설명이 필요 없으면 `변경 파일, 검증 결과, 미해결 항목만 반환`이라고 적는다.
