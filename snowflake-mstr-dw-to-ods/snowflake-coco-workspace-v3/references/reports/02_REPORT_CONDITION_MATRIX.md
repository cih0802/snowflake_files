# 회원통계보고서 — REPORT_ID별 조건 차이

이 문서는 서로 비슷한 용어를 사용하는 보고서의 조건을 섞지 않기 위한 기준이다. CoCo는 작업 전에 반드시 REPORT_ID를 확정한다.

`2025 허수회원 옵션`, `2026-04 수동보정`은 모두 `LEGACY_UI_EXCEPTION`이다. Fact 계산에 포함하거나 다른 REPORT_ID·기간으로 전파하지 않으며, 기존 화면 재현이 명시적으로 요구될 때만 적용한다.

## 1-1 / 1-2 회원개발
원천은 `TM_MM_FDRM_MBER_DVLP_AMT`.

개발구분:
- 1 신규
- 4 재후원
- 2 증액

증액은 단순 `DVLP_DIV_CD=2` 행 합이 아니라 회원 월 순액, 감액, 누적 증액을 사용한 RAMT 배분 로직이다.

부서는 개발 이벤트 `ACMSLT_DEPT_CD`를 현재 Streamlit의 부서분류 규칙으로 분류한다.

현재 Streamlit 고유 예외(`LEGACY_UI_EXCEPTION`):
- 2025 `허수회원 제외` 토글이 켜지면 지정된 `(MBER_NO, STRD_MT)` 6건 그룹을 1번 탭 데이터에서 제외.
- 2026-04 1-1/1-2 시도본부: 신규 -1, 재후원 +1.
- 이 보정은 Fact 자체가 아니라 화면 Pivot에서 적용.

따라서 보정 전 Fact 합과 화면 합은 다를 수 있다. 이 차이를 일반 ODS 계산 규칙으로 만들지 않는다.

## 1-3 / 1-4 회원구분별 개발
이 화면의 신규/기존은 ACT_2_1과 다르다.

현재 코드:
```text
회원의 전체 DVLP_DIV_CD='1' 중 MIN(OCCRRNC_DE) >= 선택연도 1월 1일
→ 신규회원
그 외 → 기존회원
```

즉 "당해연도 최초 신규개발 회원" 분류다.

2026-04 화면 보정:
- 신규회원 본부 신규 +1
- 신규회원 시도본부 신규 -1
- 기존회원 신규 -1, 재후원 +1
- 누계는 4월 이후 계속 반영

## 1-5 캠페인 TOP10
개발 Base는 1-1 계열과 동일하다.
- `CMPGN_CD` 캠페인
- `UPPER_CMPGN_CD` 상위캠페인
- 캠페인별 개발건 합
- 캠페인별 `MBER_NO.nunique()`

한 회원이 여러 캠페인에 있을 수 있으므로 캠페인별 개발명수 합은 전체 DISTINCT 회원수가 아니다.
현재 2026-04 수동보정은 1-5에 적용되지 않는다.

## 2-1 활동회원(회원구분별)
개발 보고서와 다른 Base다.

활동회원 자격:
1. 기준월까지 최근 중단일
2. 최근 재후원일
3. 실제 활동종료일
4. 기준월말 유효 후원 존재
5. 회원 최초등록일~활동종료일 범위

현재 후원잔액:
`SPNSR_NO + SPNSR_BSNS_NO`별 기준월까지 `SUM(SPNSR_AMT)`.

활동 후원:
`최종 이벤트 속성행 AND SUM_AMT > 0`.

신규/기존:
```text
회원 FRST_REGIST_DT 연도 = 기준연도
AND 후원 TM_MM_FDRM_MBER_SPNSR.FRST_REGIST_DT 연도 = 기준연도
→ 신규
그 외 기존
```

부서:
`TM_MM_FDRM_MBER_SPNSR.ACMSLT_DEPT_CD` → DEPT4.

법인:
회원+법인별 결제 현재/이력 최신 정보를 반영.

지표:
- 활동명 = COUNT(DISTINCT MBER_NO)
- 활동건 = SUM(현재 후원잔액/10000)
- 정상회원 납입금액
- 별도 중단 Branch의 중단건

## 2-2 활동회원(후원사업별)
활동 Base는 반드시 ACT_2_1과 동일하게 공유한다. 차이는 최종 차원에 `SPNSR_BSNS_ID/SPNSR_BSNS_NM`이 추가되는 것뿐이다.

현재 Streamlit의 사업명 `contains` 분류는 사업명 변경/신규사업 추가 시 누락 위험이 있다. 향후 `SPNSR_BSNS_ID → 표시사업` 명시 Mapping을 사용한다.

검증:
- 미매핑 사업 ID/활동건 확인
- 표시 대상 전체 활동건 합 = 동일 Scope ACTIVE_FACT 활동건
- 전체 활동회원명은 사업별 회원명 SUM이 아니라 raw ACTIVE_FACT DISTINCT

## 3-1 중단회원
현재 3-1은 ACT_2_1 내부 중단 Branch와 같은 정의가 아니다.

회원수 Base:
- `TM_MM_FDRM_MBER_SPNSR_DSCNTC` 선택월 중단 이력
- 현재 `TM_MM_FDRM_MBER_INFO.MBER_STAT_CD='12'`
- 회원별 선택월 최신 중단 이력

중단금액 Base:
- `TM_MM_FDRM_MBER_SPNSR_BSNS`
- `SPNSR_DSCNTC_YN='Y'`
- 중단일 선택월
- `SPNSR_DSCNTC_RSN_CD='7'`

즉 회원수 Base와 금액 Base도 완전히 동일하지 않다. ACT_2_1의 `WJXBFS4`와 직접 동일해야 한다고 가정하지 않는다.

## 보고서 간 직접 비교 금지
'신규':
- DEV_1_1: 개발 이벤트 유형
- DEV_1_3: 당해연도 최초 신규개발 회원
- ACT_2_1: 회원등록연도 + 후원등록연도
- STOP_3_1: 별도 로직

'건':
- 개발건 = 개발금액/10000
- 활동건 = 현재 누적 후원잔액/10000
- 중단건 = 보고서별 중단 금액 정의
- 물리 Row Count 아님

'회원수':
차원별 DISTINCT 회원수를 합해 전체 DISTINCT로 사용하지 않는다.
