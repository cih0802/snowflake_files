# 기획자용 요청 템플릿

아는 내용만 채운다. 영문 테이블명·컬럼명·코드값은 적지 않아도 된다. 기존 SQL은 수정하지 말고 전체를 그대로 붙인다.

## 가장 짧은 요청

````text
$snowflake-mstr-dw-to-ods
모드: 전체
리포트: [화면의 한글 리포트명]
조건: [예: 2026년 6월, 전체 법인]
목표: 아래 MSTR_DW SQL을 같은 업무기준의 Snowflake MSTR_ODS SQL로 변환하고 검증해줘.
기준값: [알면 입력, 모르면 없음]
기존 SQL:
```sql
[MSTR에서 복사한 SQL 전체]
```
````

## 신규 리포트 변환 요청

````text
$snowflake-mstr-dw-to-ods
모드: 변환
리포트명: [한글명]
화면 경로: [메뉴 > 하위 메뉴]
조회조건: [기간/법인/조직/상태 등 화면에서 선택한 값]
필요 결과: [표시할 KPI, 표, 차트, 다운로드]
행 기준: [표의 한 행이 의미하는 것. 모르겠으면 모름]
기준 결과: [MSTR 화면의 총계 또는 엑셀 값. 없으면 없음]
요청: DW 문법만 바꾸지 말고 실제 Snowflake ODS 원천을 확인해 업무 로직을 재구성해줘. 미확인 항목은 추정하지 말고 최대 3개만 쉬운 말로 질문해줘.
첨부: [기존 SQL / 화면 캡처 / 결과 엑셀 / 함수·프로시저 정의]
기존 SQL:
```sql
[전체 SQL]
```
````

## 차이 검증 요청

```text
$snowflake-mstr-dw-to-ods
모드: 검증
리포트: [한글명]
비교 조건: [기준월/기간, 법인, 조직 등]
MSTR 기준값: [지표명=값]
Snowflake 값: [지표명=값]
요청: 조회조건→대상범위→조인→분류→중복→집계→화면표시 순으로 최초 차이 지점을 찾아줘. 월마감 스냅샷과 현재 ODS 재계산 차이는 별도로 표시하고 임의 보정하지 마.
첨부: [MSTR SQL, Snowflake SQL, 결과 파일]
```

## Streamlit 적용 요청

```text
$snowflake-mstr-dw-to-ods
모드: 앱 적용
리포트: [한글명]
검증 완료 근거: [검증 SQL/결과 파일 또는 승인된 APP View]
화면 요청: [필터, KPI, 표, 차트, 다운로드]
요청: 검증된 APP View 하나를 기준으로 모든 화면 수치를 만들고 개인정보를 노출하지 마. 데이터 검증이 끝나지 않았으면 UI를 먼저 만들지 말고 중단 사유를 알려줘.
```

## 토큰을 줄이는 작성법

- 앞선 대화 전체를 복사하지 말고 `리포트·조건·목표·기준값·SQL`만 보낸다.
- 한 요청에는 한 리포트와 한 결과만 적는다.
- “알아서”, “비슷하게” 대신 화면의 한글명과 조회조건을 적는다.
- 이미 첨부한 참조 파일은 본문에 다시 붙이지 않고 파일명만 쓴다.
- SQL은 일부가 아니라 전체를 한 번만 붙인다.
- 설명이 필요 없으면 마지막에 `결과는 변경 파일, 검증 결과, 미해결 항목만`이라고 적는다.
