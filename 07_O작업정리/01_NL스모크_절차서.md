## §2. 실행 절차 (선행 조건 충족 후)

1. CoWork UI 에서 `AGENT_MEMBER` 를 연다.
2. 아래 §3 질의를 **한 번에 하나씩** 넣고, 답변 전문을 그대로 복사해 둔다.
3. 각 질의마다 §3 의 「합격 조건」과 「불합격 신호」를 대조해 O/X 를 적는다.
4. `AGENT_OVERALL`·`AGENT_MARKETING` 도 같은 방식으로 해당 질의만 반복한다.
5. 결과를 **이 문서 §4 표에 기록**하고 세션 이력에 링크한다.

## §3. 질의 세트와 판정 기준

### Q1 — 배분규칙필요 (🔴 가장 중요한 축)

> 질의: **"발송 건별로 납입방식과 개발(명)을 같은 표로 뽑아줘"**

* 🟢 **합격**: 배분(귀속) 규칙이 필요한 **업무 판단 사안**이라고 답하고 **SQL 을 만들지 않는다.**
* 🔴 **불합격 신호**: SQL 을 생성한다 · 도구를 억지로 골라 숫자를 낸다 ·
  「데이터가 없다」로 답한다(판정의 뜻이 그것이 아니다).

### Q2 — 집계필요

> 질의: **"이번 달 중단 회원 수를 알려줘"**

* 🟢 **합격**: 고유회원수(`COUNT(DISTINCT MEMBER_DK)`) 기준으로 답하고
  「명 ≠ 플래그 합」임을 밝힌다.
* 🔴 **불합격 신호**: `SUM(STOP_MEMBERS)` 를 「명」으로 답한다(과대) ·
  주차별 「명」을 월로 합산한다.

### Q3 — 형제팩트중복

> 질의: **"납입방식별 납입액과 월 회원수를 한 표로 보여줘"**

* 🟢 **합격**: 두 팩트를 **한 표에 합치지 않는다**고 밝히고 표를 분리하거나
  「납입(원)」을 `analyst_member_fee` 앵커로 답한다.
* 🔴 **불합격 신호**: 한 표에 합쳐 이중계상한다.

### Q4 — 앵커_경합

> 질의: **"개발실적보고 주간 섹션을 만들어줘"**

* 🟢 **합격**: 3개 도구를 **각각 호출해 연·월 축에서 병기**하고 표마다 grain 을 밝힌다 ·
  주간 목표를 **만들지 않는다**.
* 🔴 **불합격 신호**: 하나의 팩트를 골라 섹션 전체를 답한다(**조용한 오답**) ·
  주간 목표 수치를 창작한다.

### Q5 — 역방향 오탐 가드 (🟢 정상 답변이 나와야 한다)

> 질의: **"개발(건)을 월별로 보여줘"** (자기 grain 질의)

* 🟢 **합격**: 정상적으로 답한다.
* 🔴 **불합격 신호**: 「배분규칙필요」라고 거부한다 ⇒ 라우팅이 **과잉 차단**이다.
  🔴 **Q1 만 보면 이 결함을 못 잡는다** — 거부만 잘하는 Agent 는 쓸 수 없다.
