### 3-A-1. 문제 — 이질속성 평탄화로 인한 3중 손실

AGENCY 원천은 **3종 이질 테이블**이다 (DGT 36 · REBRDC 34 · VIDEO 32 = 102컬럼).
기존 SILVER `AGENCY_AD_PERFORMANCE` 는 이를 **공통 컬럼으로만 UNION** 하고 나머지는 버렸다. 결과:

| 손실 유형 | 실측 근거 (2026-07-28) |
|---|---|
| ① 고유속성 소실 | BRONZE 102컬럼 중 GOLD 도달 13컬럼(12.7%). 방송 시간대·CM위치·사례정보 등 미노출 |
| ② 출처 구분 소실 | SILVER `SOURCE_SYSTEM`(DIGITAL 197,686·VIDEO 35,822·REBROADCAST 2,064)이 GOLD에서 `DW_SOURCE_SYSTEM='AGENCY'` 상수로 평탄화 |
| ③ 기기축 전건 무효 | `FACT_AD_PERFORMANCE.sql:20` `0 as DEVICE_SK` → **235,572행 전건 (unknown)**, 지표 공14(기기) 사용 불가 |

③의 기존 사유 주석(`sql:6` "AGENCY device 도메인 ≠ GA4 기반 DIM_DEVICE")은 **실측과 불일치**:

```
AGENCY  DEVICE_NM  : M 138,274 · PC 59,412 · NULL 37,886
GOLD    DIM_DEVICE : M · PC · (unknown)          ← 도메인 네이티브 동일
NULL 37,886 = VIDEO 35,822 + REBROADCAST 2,064   ← 방송=기기개념 없음, 전량 설명됨
```

### 3-A-2. 결정1 — 유형별 위성 팩트 분리

```

   │  3원천 공통 measure/FK + AD_SOURCE_TYPE

   ├── FACT_AD_BROADCAST        1:1    37,886행  (VIDEO∪REBRDC 고유)
   └── FACT_AD_BROADCAST_CASE   1:N     REBRDC 사례 언피벗
```

### 3-A-3. 결정2 — 대행사 산정 파생값 `_SRC` 보존 (전량)

대행사가 계산해 넘긴 파생값(CTR·CVR·CPC·CPM·CPA·개발단가·VTR·광고시청률)은
**DW가 재계산하지 않고 원천값 그대로 `_SRC` 접미로 적재**한다. SV는 base measure 로 **별도 재계산**.

- **목적**: 대조 전용. 대행사 산식과 DW 산식의 차이를 현업이 직접 확인 가능
- **선례**: GA4 사전집계 비율(#98 평균세션시간·#108 이탈율)의 비가산 measure 적재 (§1 예외조항)
- **적재 범위**: **전량**(8종). 원천 데이터 최대 보존 원칙. Agent 에는 계산값·소스값 **양쪽 모두 노출**
- **가산성**: `_SRC` 전량 **N(비가산)** — 비율·단가는 재합산 금지. SUM 집계 시 base 재계산값 사용

| `_SRC` 컬럼 | 원천 | 위치 | DW 재계산 산식 (SV) |
|---|---|---|---|
| `CTR_SRC` | DGT.CTR | FAD_D | CLICKS / IMPRESSIONS |
| `CVR_SRC` | DGT.CVR | FAD_D | GA_CONV_MEMBERS / CLICKS (O5 확정) |
| `CPC_SRC` | DGT.CPC · VIDEO.CPC | FAD_D · FAD_B | AD_COST / CLICKS |
| `CPM_SRC` | DGT.CPM | FAD_D | AD_COST / IMPRESSIONS × 1000 |
| `CPA_SRC` | DGT.CPA | FAD_D | AD_COST / GA_CONV_CNT |
| `DEV_UNIT_PRICE_SRC` | DGT.DEV_UNIT_PRICE | FAD_D | AD_COST / 개발건수 |
| `VTR_SRC` | DGT.VTR | FAD_D | 재계산 불가(원천 전용) |
| `AD_VIEW_RT_SRC` | VIDEO.AD_VIEW_RT | FAD_B | 재계산 불가(원천 전용) |

> ⚠️ `VTR_SRC`·`AD_VIEW_RT_SRC` 는 base 가 원천에 없어 재계산 불가 → **대조 대상이 아닌 유일값**.
> `_SRC` 접미를 유지하는 이유는 "대행사 산정값"이라는 **출처 표기 일관성** 때문이다.

### 3-A-4. 결정4(출처 명시) — `AD_SOURCE_TYPE` degenerate 노출

### 3-A-5. 결정3 — `DIM_DEVICE` `(해당없음)` 멤버 신설

방송광고(VIDEO·REBRDC)는 기기 개념이 없다(실측: NULL 37,886 = 방송 2원천 전량).

| 멤버 | SK | 의미 | 대상 |
|---|---|---|---|

| `(unknown)` | **0** | 기기 정보 미상·미매핑 센티넬 | 매핑 실패 건 |

- **센티넬 원칙 유지**: `-1` 미사용 · `0`=Unknown 정본. `(해당없음)`은 **일반 멤버로 해시 SK 부여**(0 오염 방지)
- **⚠️ 조건 충족(분석가 식별 가능성)**: 아래 2중 장치로 보장
  1. **`AD_SOURCE_TYPE` 병기** — `DEVICE_TYPE='(해당없음)'` 행은 `AD_SOURCE_TYPE IN ('VIDEO','REBROADCAST')` 로 방송임이 자명
  2. **`DEVICE_SCOPE_DESC` 컬럼 신설** — DIM_DEVICE 에 자기설명 텍스트 보유
     (`'방송광고(TV·재방송) — 기기 개념 없음'`) → 차원만 조회해도 의미 파악 가능

### 3-A-6. `AD_PERF_DK` — 행 식별자 설계

위성 팩트를 코어에 1:1 로 붙이려면 행 식별자가 필요하나, **원천에 PK가 없다**(실측).

| 실측 (2026-07-28) | DGT | VIDEO | REBRDC |
|---|---|---|---|
| 총 행수 | 197,686 | 35,822 | 2,064 |
| 전컬럼 distinct | 197,651 | 35,791 | 2,064 |
| **전컬럼 중복 그룹** | 35 | 30 | 0 |
| 최대 중복 배수 | 2 | 3 | 1 |

→ 전컬럼 해시만으로는 131행이 충돌. **해시 + 중복순번** 조합이 필수.

```
AD_PERF_DK = MD5( AD_SOURCE_TYPE ‖ '|' ‖ ROW_HASH ‖ '|' ‖ DUP_SEQ )
  ROW_HASH = MD5(TO_JSON(OBJECT_CONSTRUCT(*)))            -- 원천 전컬럼
  DUP_SEQ  = ROW_NUMBER() OVER (PARTITION BY ROW_HASH ORDER BY NULL)
```

- **결정성**: 중복 그룹 내 행은 **전컬럼이 동일**하므로 순번 부여 순서가 무관 → DK **집합**은 재실행 멱등
- **AD_SOURCE_TYPE 를 해시에 포함**하는 이유: 원천 간 우연한 해시 충돌 방지 + DK 만으로 원천 판별 가능
- **직관성**: 코어·위성 모두 `AD_PERF_DK` 단일 컬럼으로 조인 → 인수인계자가 ERD 없이도 관계 파악 가능

### 3-A-7. SILVER 구조 변경 (신설 5 · 수정 1)

위성 팩트의 원천이 되는 고유속성은 현재 SILVER 에 **존재하지 않는다**(공통 UNION 시 폐기).
따라서 SILVER 에 **원천 무손실 staging 계층**을 신설한다.

```
BRONZE_AGENCY
  DGT_AD_CMPGN_DTLS ──┐
  VIDEO_AD_CMPGN_DTLS ┼─→ [신설] SILVER staging 3종 (전컬럼 보존 + AD_PERF_DK 부여)
  REBRDC_AD_CMPGN_DTLS┘      AGENCY_AD_ROW_DGT / _VIDEO / _REBRDC
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        ▼                           ▼                           ▼
  [수정] AGENCY_AD_PERFORMANCE  [신설] AGENCY_AD_DIGITAL   [신설] AGENCY_AD_BROADCAST
        (공통 UNION + DK)              (DGT 고유)              (VIDEO∪REBRDC 고유)
                                                          [신설] AGENCY_AD_BROADCAST_CASE
                                                                (CASE1~3 언피벗)
```

| 모델 | 구분 | 역할 |
|---|---|---|
| `AGENCY_AD_ROW_DGT` | 신설 | BRONZE DGT 전컬럼 + `AD_PERF_DK`. **DK 발급 단일 지점** |
| `AGENCY_AD_ROW_VIDEO` | 신설 | 동일 (VIDEO) |
| `AGENCY_AD_ROW_REBRDC` | 신설 | 동일 (REBRDC) |
| `AGENCY_AD_PERFORMANCE` | **수정** | staging 3종에서 공통컬럼 UNION. `AD_PERF_DK`·`AD_SOURCE_TYPE` 추가 |
| `AGENCY_AD_DIGITAL` | 신설 | DGT 고유속성 + `_SRC` 파생 6종 |
| `AGENCY_AD_BROADCAST` | 신설 | VIDEO∪REBRDC 고유속성 + `_SRC` 2종 |
| `AGENCY_AD_BROADCAST_CASE` | 신설 | REBRDC `CASE1_*`~`CASE3_*` → `CASE_SEQ` 언피벗 |

> **staging 계층을 두는 이유**: DK 를 한 곳에서만 발급해야 코어·위성의 DK 가 **반드시 일치**한다.
> 각 모델이 독립적으로 해시를 계산하면 컬럼 순서·NULL 표현 차이로 불일치 위험이 생긴다.

### 6-2. G-1·Q1 해소 → identity 지표 잠금해제
- **회원번호가 GA·CRM 공통 조인키**로 확정(현업 확인 G-1 ✅). GA `user_id` = CRM 회원번호(정규 7자리 / 일회성 `S`+8자리, VARCHAR·leading-zero 보존).
- **【회원번호 체계 명문화】 CRM 분리 관리 / GA 단일 통합**: CRM은 정식(FDRM)과 일시(ONCE) 회원을 **별도 테이블**로 분리 관리한다 — `TM_MM_FDRM_MBER_INFO`(번호 범위 `0000000`~`9999999`, 7자리, leading-zero 보존) · `TM_MM_ONCE_MBER_INFO`(번호 범위 `S00000000`~`S09999999`, `S`접두+8자리=9자). GA4 `user_id`는 이 두 유형을 **단일 필드에서 함께 표현** — `'S'` 접두 유무만으로 FDRM/ONCE 판별 가능. 두 원천이 동일 namespace의 회원번호를 공유하므로 직접 조인이 성립한다.
- **Q1(행매칭 실증) 해소**: 이 형식 스펙이 `GA4_IDENTITY`/`DIM_MEMBER_IDENTITY`가 `enabled=false`였던 사유(Q1)를 해소. 기존 분기 로직(`user_id ILIKE 'S%' → ONCE / else → FDRM`, `MBER_NO`/`ONCE_MBER_NO` 분리)이 스펙과 **정확히 일치(검증 완료)** → 두 모델 `enabled=true` 전환 가능.
- ⚠️ **활성화 시 동반 필수**: (a) D1-FGA — `FGA.IDENTITY_SK`가 실제값이 되므로 `unique_key`에 IDENTITY_SK 추가, (b) **DQ 확인** — GA export가 leading-zero·`S`접두를 보존해야 조인 성립(숫자화 시 매칭 실패).
- ⚠️ **[결론9] user_id 커버리지 4.2%**: identity 조인은 **구조적으로** 성립하나, GA4 `user_id` 채움률은 약 **4.2%**(전수 12,120/287,025·식별 1,290명·익명 95.8%). 따라서 #81·신#32·33 등 **회원단위 GA 지표는 부분 커버리지**이며 전수로 단정 금지. SV/BI에 커버리지 경고 노출, 익명(user_pseudo_id)은 세션 스티칭 없이는 회원 귀속 불가.
- 잠금해제 지표: **#81 미납서비스 전환율**, **신#32·33**(클릭/전환 회원명). 경로: `FGA.IDENTITY_SK → DIM_MEMBER_IDENTITY → 회원 미납 판정(C-3: PAY_STAT_CD F/NULL, 또는 회원상태 MM010 미납1~5 — ⑤에서 확정)`.
- **미납서비스 클릭회원(명)** = distinct(미납회원 ∩ GA 클릭회원). 소결정 2건 필요: ①"미납서비스 클릭"의 GA 이벤트/페이지 범위, ②"납입 전환" 판정(상태전이 vs 회비납입, 판정 기간).
