## 3-B. ◐ 집계필요 전량 — **불가가 아니다** (사전집계 후 조인)

> 대상 팩트가 앵커보다 **잘다**(fine→coarse). 앵커 grain 으로 **먼저 집계한 뒤** 조인하면 팬아웃이 0 이다.
> 실측 증명: `FMM ⋈ (FSE→회원·월 사전집계)` 행 **40,054,883 불변** · 청구액 **891,959,790,888 불변**.
> 🔴 사전집계 **없이** 그냥 조인할 때만 이중계상이 난다 — 종전 판본의 「37.3배 복제」가 바로 그 경우다.
> ⇒ 해소 주체는 **쿼리 패턴**이며 테이블 신설도 업무 규칙도 필요하지 않다(O47·P95).

|---|---|---|---|---|---|
| 회원 | 2-2. [회원] 월간 중단보고 | 중단(명) | `FACT_MEMBER_MONTHLY` | `FACT_MEMBER_EVENT.STOP_MEMBERS` | 시간축 상이 — `FACT_MEMBER_MONTHLY`=월 vs `FACT_MEMBER_EVENT`=일. 🟢 **불가가 아니다** — `FACT_MEMBER_EVENT` 를 앵커 grain 으로 **먼저 집계한 뒤** 조인하면 팬아웃이 0 이다. 🔴 naive 조인(사전집계 없이)만 이중계상을 만든다. 실측 증명: `FMM ⋈ (FSE→회원·월 사전집계)` 행 40,054,883 **불변** · 청구액 891,959,790,888 **불변**(2026-08-07 O47). ▸ BRONZE 근거: `FACT_MEMBER_EVENT` 는 **사건(일) grain**, `FACT_MEMBER_MONTHLY` 는 **월 grain** 이다. ## 3-C. 🆕 검증된 처방 쿼리 (실행 근거 첨부 · 2026-08-10 O56)

> 🔴 **여기 실린 쿼리는 전부 실제로 실행한 것이고, 표에 적힌 값이 그 실행 결과다.**
> 종전 판본은 처방을 **산문으로만** 적었고 실행 근거가 없었다 — 그 결과 처방 4건이 틀린 채
> 통과했다(O49 적발). 처방은 쿼리로 적고 값으로 증명한다(P139).

### ㉮ 2-1 앵커 교체 — 월 팩트로는 주차를 낼 수 없다

`FACT_MEMBER_MONTHLY` 에는 `DATE_SK` 가 없다. 앵커를 `FACT_MEMBER_EVENT` 로 바꿔도 **손실이 0** 인지 먼저 증명한다.

```sql
-- ① 앵커 교체 손실 검증: FME 월 롤업 = FMM (466개월 전건)
with fme as (
  select floor(DATE_SK/100) M, sum(STOP_CNT) S, sum(DEV_CNT) D
  from GN_DW.GOLD.FACT_MEMBER_EVENT group by 1),
fmm as (
  select MONTH_KEY M, sum(STOP_CNT) S, sum(DEV_CNT) D
  from GN_DW.GOLD.FACT_MEMBER_MONTHLY group by 1)
select count(*) MONTHS_COMPARED,
       count_if(coalesce(a.S,0) <> coalesce(b.S,0)) STOP_MISMATCH,
       count_if(coalesce(a.D,0) <> coalesce(b.D,0)) DEV_MISMATCH
from fme a full outer join fmm b on a.M = b.M;
-- 실행 결과: MONTHS_COMPARED=466 · STOP_MISMATCH=0 · DEV_MISMATCH=0

-- ② 교체 후 주차 축이 실제로 나오는지 + 총계 보존
with wk as (
  select date_trunc('week', to_date(to_varchar(DATE_SK),'YYYYMMDD')) WK,
         sum(STOP_CNT) STOP_CNT
  from GN_DW.GOLD.FACT_MEMBER_EVENT where DATE_SK > 0 group by 1)
select count(*) WEEK_ROWS, sum(STOP_CNT) STOP_SUM from wk;
-- 실행 결과: WEEK_ROWS=1,795 (1991-01-07 ~ 2026-07-06) · STOP_SUM=1,038,262 = FME·FMM 총계와 동일
```

### ㉯ 「중단(명)」·「개발(명)」은 비가산 — SUM 처방이 틀렸다

```sql
-- ① STOP_MEMBERS 는 「명」이 아니라 사건행당 1 인 플래그다
select sum(STOP_MEMBERS) SUM_MEMBERS, sum(STOP_CNT) SUM_CNT, count_if(STOP_CNT > 0) ROWS_STOP
from GN_DW.GOLD.FACT_MEMBER_EVENT;
-- 실행 결과: 1,038,262 / 1,038,262 / 1,038,262  (셋이 동일 = 건수다)

-- ② 주차로 쪼개 더하면 과대계상된다
with w as (
  select date_trunc('week', to_date(to_varchar(DATE_SK),'YYYYMMDD')) WK,
         count(distinct case when STOP_CNT > 0 then MEMBER_DK end) D
  from GN_DW.GOLD.FACT_MEMBER_EVENT where DATE_SK > 0 group by 1)
select sum(D) WEEKLY_SUM_DISTINCT,
       (select count(distinct case when STOP_CNT > 0 then MEMBER_DK end)
          from GN_DW.GOLD.FACT_MEMBER_EVENT where DATE_SK > 0) TRUE_DISTINCT
from w;
-- 실행 결과: 972,925 vs 903,064 = 69,861 과대 (7.74%)

-- ③ 🟢 BRONZE 원천 독립 대조 — 「명」의 정답은 원천 distinct 다
select count(*) BRONZE_ROWS, count(distinct MBER_NO) U_MBER
from GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_SPNSR_DSCNTC;
-- 실행 결과: 1,038,262 / 903,064  → GOLD 와 정확히 일치(행수=건수 · distinct=명)

-- ④ 🔴 [O56 신규] 개발(명)도 비가산이다 — O49 는 이 필드를 검사하지 않았다
select sum(DEV_MEMBERS) FMM_SUM, sum(DEV_CNT) FMM_CNT,
       (select count(distinct MEMBER_DK) from GN_DW.GOLD.FACT_MEMBER_EVENT
          where EVENT_TYPE = 'DEV' and DEV_CNT > 0) TRUE_DISTINCT
from GN_DW.GOLD.FACT_MEMBER_MONTHLY;
-- 실행 결과: 1,996,977 / 2,291,878 / 1,585,923  → SUM(DEV_MEMBERS) 가 25.9% 과대
```
