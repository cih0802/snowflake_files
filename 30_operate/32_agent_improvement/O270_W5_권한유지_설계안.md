# O270 W5 — 권한 유지 설계안(㉢ = dbt grants + DDL 파일 GRANT 줄)

> 🟢 사용자 결정(2026-10-29) = ㉢ · 계획서 = `12_agent개선과제/O270_원천별_접근통제_작업계획.md` C6 · W5
> 🔴 이 문서는 **설계**다 — dbt 파일·SV DDL 파일은 아직 고치지 않았다(라이브 변경 0).
> 🔴 수치는 W1 분류표(`output/O270_source_class.csv`)에서 나온다 — 여기 적힌 객체 목록은 생성 시점 사본이다.

## 1. 경로별 방식

| 경로 | 객체 | 재생성 방식 | 유지 수단 |
|---|---|---|---|
| dbt | SILVER·GOLD 모델 | incremental 은 유지 · view(WIDE_*)는 CREATE OR REPLACE | `dbt_project.yml` `+grants` |
| SV DDL | SV 45 | CREATE OR REPLACE SEMANTIC VIEW | 파일 끝 GRANT 줄(접근 역할) |
| SERVING 뷰 DDL | ML_*·MSTR_* 21 | CREATE OR REPLACE VIEW | 파일 끝 GRANT 줄(접근 역할) |
| 48번 SQL | 위 전부의 현재 상태 | 1회 적용 | 재빌드 뒤 W7 게이트로 대조 |

- FUTURE GRANT 는 쓰지 않는다 — GOLD·SERVING 에 원천이 섞여 있어 스키마 단위로 가를 수 없다.

## 2. dbt `+grants` 배선안

- 폴더 기본값 = 공통.
  예외 모델만 모델 단위로 덮는다(폴더가 원천별로 나뉘지 않은 GOLD 때문).
- SILVER 는 기능 역할에 주지 않는다(접근 역할 GRANT 대상 아님) — 구 역할 전환기 목록만 유지한다.

```yaml
models:
  gn_dw_silver:
    silver:
      +grants:
        select: ['GN_DW_ANALYST']            # 전환기 구 역할(W8 후 제거)
    gold:
      +grants:
        select: ['GN_DW_AR_SRC_COMMON', 'GN_DW_ANALYST', 'GN_DW_VIEWER', 'GN_DW_SERVICE']
```

- GOLD 예외(모델 `config(grants=...)` 또는 `_gold_ready_schema.yml` 의 models 항목):

| 분류 | 접근 역할 | 모델 |
|---|---|---|
| AGENCY | GN_DW_AR_SRC_AGENCY | DIM_AD_CREATIVE · FACT_AD_BROADCAST · FACT_AD_BROADCAST_CASE · FACT_AD_DIGITAL · FACT_AD_INFLOW_ALLOC · FACT_AD_PERFORMANCE · WIDE_AD_BROADCAST · WIDE_AD_BROADCAST_CASE · WIDE_AD_COMBINED · WIDE_AD_DIGITAL · WIDE_AD_PERFORMANCE |
| ERP | GN_DW_AR_SRC_ERP | DIM_BUDGET_ITEM · FACT_BUDGET · FACT_BUDGET_YEARLY · FACT_EXPENSE_RESOLUTION · WIDE_BUDGET |
| AGENCY+ERP | GN_DW_AR_SRC_AGENCY_ERP | FACT_MKTG_CAMPAIGN_MONTHLY_COST |

- 예외 모델의 select 목록 = 그 접근 역할 1개 + 전환기 구 역할 3개(공통 접근 역할은 **넣지 않는다**).

## 3. 🔴 전환기 위험(검증 필요)

- dbt `grants` 는 설정에 없는 권한을 **회수**하는 동작이 있다고 알려져 있다
  (같은 privilege 종류 한정 · 이 세션에서 문서 재확인 실패 ⇒ **미검증**).
- 그렇다면 구 역할(GN_DW_ANALYST·VIEWER·SERVICE)을 목록에서 빼는 순간 다음 build 가 회수를 집행한다
  ⇒ **W8 전에 구 역할을 목록에서 빼지 마라**(계획서 §4 「운영계 실측 전 회수 금지」와 같은 축).
- W6 에서 모델 1개(예: GOLD.DIM_DATE)로 실증 = 목록에 없는 역할의 SELECT 가 build 후 남는지 `SHOW GRANTS ON`.

## 4. SV·SERVING 뷰 DDL 파일

- SV 45 의 GRANT 줄(현재 = 구 3역할)에 **접근 역할 1줄을 추가**한다(구 역할 줄은 W8 까지 유지).
  형식 = `GRANT SELECT, REFERENCES ON SEMANTIC VIEW GN_DW.SERVING.<SV> TO ROLE <접근 역할>;`
- 대상 접근 역할 = 분류표 `source_class` 그대로 — 손으로 고르지 말고 W7 게이트가 파일 ↔ 분류표를 대조한다.
- 대안(보류) = DDL 을 `CREATE OR REPLACE ... COPY GRANTS` 로 바꾸기 — 파일에 GRANT 가 없어도 유지되지만
  「파일이 정본」 원칙(재현성)이 약해지므로 GRANT 줄 방식을 기본으로 둔다.
- SERVING 뷰 DDL 4파일도 같은 방식(ML_REALTIME_SIMULATOR_V = AGENCY · 나머지 = COMMON).

## 5. 집행 순서(각 단계 승인)

1. 48번 [1]~[3] 개발계 적용(W6) → 역할별 검증.
2. dbt `+grants` 추가(구 역할 포함) → 👤 사용자 build → GRANT 유지 실측.
3. SV·SERVING 뷰 DDL GRANT 줄 추가 → 재배포 → W7 게이트.
4. W8 운영계 실측 → 구 역할 제거(dbt 목록 · DDL 줄 · 48번 [6]).

## 6. 🆕 집행 결과 · 정정(O270-F · 2026-10-29 · 개발계 ZS83821)

- 🔴 정정 ①: §2 의 「SILVER·GOLD 모델에 `+grants`」는 **불필요했다** —
  SILVER·GOLD **테이블은 GN_DW_ADMIN 소유**이고 incremental·`full_refresh: false` 라 재생성되지 않는다
  ⇒ 48번 GRANT 이 그대로 유지된다. 재생성 대상은 **dbt 소유 WIDE 뷰 19개뿐**이다(INFORMATION_SCHEMA 실측).
- 🔴 정정 ②: WIDE 뷰 materialization `gn_view_commented` 는 `apply_grants` 를 **호출하지 않았다**
  ⇒ `+grants` 만 넣으면 효과 0 이었다. 처방 = 매크로에 `copy grants` + `apply_grants(should_revoke=False)`.
  ⇒ §3 의 회수 위험은 `should_revoke=False` 로 구조적으로 제거했다(구 역할은 GOLD FUTURE VIEWS GRANT 로 받는다).
- 🔴 정정 ③: GOLD 에는 FUTURE VIEWS GRANT(구 4역할)가 **있다**(계획서 §1 의 「FUTURE GRANT 0」은 SERVING 한정).
- 반영 = `dbt_project.yml` wide 블록 `+copy_grants`·`+grants`(공통 기본 · WIDE_AD_* 5 = AGENCY · WIDE_BUDGET = ERP).
- DDL GRANT 줄 = 40파일 76줄(SV 45 · SERVING 뷰 21 전건) · 생성기 = `output/O270_add_ddl_grants.py`(재실행 0건).
- 게이트 = `scripts/rbac_source_gate.py`(A1 배선 · A2 DDL · A3 `--live`) · 음성 테스트 = `scripts/test_rbac_source_gate.py`.
- 👤 남은 확인 = 사용자 dbt build 후 `python3 scripts/rbac_source_gate.py --live` 재실행(WIDE 뷰 GRANT 유지).
