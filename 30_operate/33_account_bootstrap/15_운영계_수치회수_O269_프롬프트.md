# 운영계 수치 회수 O269 — 저가형 LLM 실행 프롬프트

> 실행 = 운영계(ZL50263) 워크스페이스 · 실행자 = 저가형 LLM(사용자 감독) · 작성 = 개발계 O269-C (2026-10-29)
> 목적 = 개발계 세션이 운영계 수치를 **파일로 읽고** 다음 작업을 판정하게 한다.
> 🔴 **읽기 전용이다.** DDL·DML·GRANT·COMMENT 수정·SV 재배포·dbt 실행을 하지 않는다.
> 선행 = 이 문서와 `85_실제 인수인계 문서/30_현업요청대응/_근거쿼리/R95_O269_운영계_수치회수.sql` 을 운영계 워크스페이스 같은 경로에 둔다.

## 0. LLM 에게 붙여 넣을 프롬프트

```text
너는 Snowflake 운영계(ZL50263)에서 조회만 하는 보조자다. 결과는 파일로 남기고, 해석은 하지 않는다.

규칙
1. 실행할 것은 아래 「단계」에 적힌 명령뿐이다. 다른 SQL·DDL·DML·dbt·GRANT 는 실행하지 않는다.
2. 파일을 고치거나 지우지 않는다. 새로 생기는 것은 _ENV/ZL50263/ 아래 csv·out 파일뿐이다.
3. 명령이 실패하면 고치려 하지 말고 오류 원문을 그대로 적고 다음 단계로 간다.
4. 결과를 요약·반올림하지 않는다. 숫자는 파일에 있는 그대로 둔다.
5. 끝나면 「보고 형식」대로만 답한다.

단계
1) SELECT CURRENT_ACCOUNT(); 를 실행한다. ZL50263 이 아니면 즉시 멈추고 그 값을 보고한다.
2) 운영계 워크스페이스 루트에서 아래 명령을 차례로 실행한다(각 명령은 한 줄이다).
   python3 scripts/env_capture.py --id R95 "85_실제 인수인계 문서/30_현업요청대응/_근거쿼리/R95_O269_운영계_수치회수.sql"
   python3 scripts/env_capture.py --id R10 "85_실제 인수인계 문서/30_현업요청대응/_근거쿼리/R10_데이터검증_근거.sql"
   python3 scripts/env_capture.py --id R06 "85_실제 인수인계 문서/30_현업요청대응/_근거쿼리/R06_Agent검증_기대값.sql"
3) 아래 명령으로 게이트 출력을 파일로 남긴다(조각 8개 · 각각 한 줄).
   mkdir -p "85_실제 인수인계 문서/_ENV/ZL50263/R95_gate"
   for k in 0 1 2 3 4 5 6 7; do timeout 900 python3 scripts/sv_code_label_gate.py --shard $k/8 </dev/null >"85_실제 인수인계 문서/_ENV/ZL50263/R95_gate/sv_code_label_$k.out" 2>&1; echo "shard $k rc=$?"; done
4) 각 manifest 파일(R95_manifest.csv · R10_manifest.csv · R06_manifest.csv)을 열어
   문장 수 · OK 수 · ERROR 수를 센다. ERROR 행은 오류 원문을 그대로 옮긴다.

보고 형식
[계정] CURRENT_ACCOUNT 결과
[R95] 문장 n · OK n · ERROR n · ERROR 원문(있으면)
[R10] 문장 n · OK n · ERROR n · ERROR 원문(있으면)
[R06] 문장 n · OK n · ERROR n · ERROR 원문(있으면)
[게이트] shard 0~7 rc 8개
[파일] 생성된 파일 목록(경로만)
```

## 1. 사람이 할 일 (LLM 실행 후)

1. `85_실제 인수인계 문서/_ENV/ZL50263/` 아래 **새로 생긴 파일**(`R95_*` · `R10_*` · `R06_*` · `R95_gate/`)을
   개발계 워크스페이스 같은 경로로 옮긴다(덮어쓰기 = 같은 이름의 이전 측정분 교체 · 기존 이력은 `_archive` 에 있다).
2. 개발계 세션에 「R95 회수 완료」라고 알린다. 개발계가 아래 §2 표대로 판정한다.
