## 1. 장애 대응 흐름 (A6 요약)

1. **증거 먼저**: `python3 scripts/env_capture.py --id A6 "85_실제 인수인계 문서/10_실무자_인수인계/A6_일배치_장애대응_런북.sql"`.
2. **증상 분류**: A6 §3 표(F1~F9)에서 증상 → 확인 SQL → 원인 후보 → 처치.
3. **에스컬레이션**: L1 ENGINEER(15분 · dbt·모델) → L2 ADMIN(30분 · 권한·DDL·WH·보안) → L3 ACCOUNTADMIN + Snowflake Support(1시간) · BRONZE 원천 = 외부 LOADER 팀(RUNBOOK §9 · 연락처 = §4 표에 사용자 기입).
4. **재처리**: 멱등 경로만(R05 §5) · 끝나면 A6 Q03(실패 저장 0행) · Q04(일자 수 일치) 재확인.

## 2. 복구 수단 · 보존 설정 · 한계 [신규 · UM80684 실측 2026-10-25]

| 수단 | 대상 | 현재 설정 | 복구 가능 범위 | 한계 |

| Fail-safe | permanent 테이블(BRONZE·SILVER·GOLD·ML·MSTR·SERVING) | Time Travel 종료 후 7일(Snowflake 고정) | Snowflake Support 요청으로만 | 사용자가 직접 쓸 수 없음 · 소요 시간 보장 없음 · **OPS 는 transient**(dbt 실패 저장 12) ⇒ Fail-safe 없음(재생성 가능 데이터라 무해) |

```sql

```

## 3. 원천 재확보 조건 [신규]

BRONZE 는 원천 사본이다. BRONZE 가 손상되고 Time Travel(1일)이 지났으면 원천에서 다시 받아야 한다.

| 원천 | BRONZE | 재확보 방법 | 조건 · 담당 |
|---|---|---|---|
| CRM | BRONZE_CRM 53 | 외부팀 LOADER 재적재 요청 | 원천 시스템 보존 범위 안 · 🔴 `_STDR_YM`(기준년월) 단위 재적재 가능 여부 LOADER 팀 확인 |
| ERP 예산·지출결의 | BRONZE_ERP 3 | 연도 단위 재적재 프로시저 `SP_LOAD_BUDGET_BY_YEAR` · `SP_LOAD_EXPENSE_RESOLUTION_BY_YEAR`(ZL50263) | 원천 ERP 접근 가능 시 |
| 대행사 광고 | BRONZE_AGENCY 4 | `SP_LOAD_DGT_AD_FROM_GSHEET` · `SP_LOAD_VIDEO_AD_FROM_GSHEET/GDRIVE` · `SP_LOAD_REBRDC_FROM_SHAREPOINT` | 원본 시트·파일이 남아 있어야 함 |
| GA4 · GSC | BRONZE_BIGQUERY · _GA4 · _GSC | `SP_LOAD_BIGQUERY` · `SP_LOAD_GA_USER_DEMOGRAPHIC` · `SP_LOAD_GOOGLE_SEARCH` | BigQuery export·API 보존 기간 안(🔴 GA 원천은 더 늘지 않는다 · SV_GA_BEHAVIOR) |
| 수기 업로드(부서 자체 집계) | SILVER `ANNUAL_*` · `MM_SPNSR_CLS_AGGR_DATA` | 부서 원본 파일 재업로드 + `SP_INSERT_*` | 원본 파일 보관 필수 |
| 수기 매핑 | dbt seeds 5 | 소스 csv(`10_dbt_pipeline/seeds/`) 재실행 | 소스 사본 |

- 상세 연동 경로·자격은 현업 D03(다른 담당) 문서와 맞춘다.

## 5. 인수자 확인 절차 (현업 확인 기준: 「시험 환경에서 대표 장애의 진단·재처리·복구 수행 · 복구 가능 기간과 불가 범위·대응책 설명」)

시험 계정 또는 시험 스키마에서만 수행한다.

```sql
USE ROLE GN_DW_ADMIN;
CREATE SCHEMA IF NOT EXISTS GN_DW.ZZ_RECOVERY_TEST;
CREATE TABLE GN_DW.ZZ_RECOVERY_TEST.T CLONE GN_DW.GOLD.DIM_SPONSORSHIP;   -- 대표 테이블 사본
DELETE FROM GN_DW.ZZ_RECOVERY_TEST.T;                                       -- 장애 재현
SELECT COUNT(*) FROM GN_DW.ZZ_RECOVERY_TEST.T AT (OFFSET => -60);           -- 1분 전 상태 확인
CREATE TABLE GN_DW.ZZ_RECOVERY_TEST.T_RESTORE CLONE GN_DW.ZZ_RECOVERY_TEST.T AT (OFFSET => -60);
DROP TABLE GN_DW.ZZ_RECOVERY_TEST.T;  UNDROP TABLE GN_DW.ZZ_RECOVERY_TEST.T;  -- UNDROP 시험
DROP SCHEMA GN_DW.ZZ_RECOVERY_TEST;                                          -- 정리
```
1. 위 시험으로 Time Travel·UNDROP 을 직접 수행한다.
2. dbt 실패 → `retry` 재처리를 R05 §6-2 로 수행한다.
3. 인수자가 §2 「한계」 열(24시간 · Fail-safe 는 Support 경유 · OPS transient · BRONZE 원천 재확보)을 설명할 수 있는지 확인한다.
