## 4. 업체 접근 회수 절차 [보완]

1. **식별**: 업체 인원 사용자 목록 확정(인수자 · 업체 공동). `SHOW USERS;` + `A1_Q02_1.csv` 로 각자의 롤 확인.
2. **업체 개인 계정 의존 제거** — 회수 전에 아래가 사람 계정 소유가 아닌지 확인한다:
```sql
SHOW TASKS IN DATABASE GN_DW;                    -- owner 가 롤(GN_DW_DBT·GN_DW_ADMIN)인지
SHOW STREAMLITS IN ACCOUNT;                       -- USER$<업체인원> 개인 워크스페이스 앱 → 이관 대상
SHOW DBT PROJECTS IN DATABASE GN_DW;              -- default_version_source_location_uri 가 개인 워크스페이스(USER$.PUBLIC."snowflake_files")
SHOW SECRETS IN ACCOUNT;                          -- 개인 PAT(§3 Git)
SELECT * FROM GN_DW.OPS.ALERT_RECIPIENT_CONFIG;   -- 업체 메일 수신자
```
   - 🔴 확인된 의존: dbt 프로젝트 원천 경로 = 배포 담당자의 개인 워크스페이스(`USER$.PUBLIC."snowflake_files"` · A4 §4) · Git PAT = 개인 계정 · Streamlit 2 = 개인(`USER$CHOIH`). ⇒ R11 §1 이관을 **회수 전에** 끝낸다.
3. **회수**(🔴 미실행 템플릿 · A1 §2-3): 롤 REVOKE → `ALTER USER … SET DISABLED = TRUE`(DROP 은 감사 이력 보존 기간 후) → 알림 수신자 동기화 `CALL GN_DW.OPS.USP_SYNC_ALERT_RECIPIENTS();`.
4. **검증**: 회수 다음 날 정기 Task·Alert 정상 실행(A6 Q05) · 업체 사용자 `LAST_SUCCESS_LOGIN` 갱신 없음.

## 5. 인수자 확인 절차 (현업 확인 기준: 「내부 운영 계정의 조회·실행·관리 권한과 제한 대상 접근 확인 · 업체 개인 계정 의존 작업 없음 확인」)

1. 내부 사용자에게 GN_DW_ADMIN · GN_DW_DBT 를 부여한 뒤 각 롤로: GOLD 조회 · `EXECUTE DBT PROJECT … ARGS='parse'` · `SHOW GRANTS ON SCHEMA GN_DW.GOLD` 가 되는지 확인.
2. 제한 확인(🔴 `USE SECONDARY ROLES NONE` 먼저 · A6 §7): GN_DW_VIEWER 로 `SELECT * FROM GN_DW.BRONZE_CRM.TM_MM_FDRM_MBER_INFO LIMIT 1` → 권한 오류여야 한다 · GN_DW_ANALYST 로 같은 쿼리 → 마스킹 적용 후에는 이름·휴대폰이 가려져야 한다.
3. §4-2 의 의존 점검 결과가 모두 「롤 소유 · 내부 경로」인지 확인.
