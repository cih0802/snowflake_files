## 1. 아키텍처 요약 (`85:D02` 발췌)

```
원천(CRM·ERP·대행사·GA4·GSC)
  → BRONZE_* (원천 6 스키마 · 외부 LOADER 적재)      ← D03 외부 연동 범위
  → SILVER (정제 · dbt incremental append)
  → GOLD   (dim · fact · wide view · dbt)
  → SERVING (Semantic View 44~45 · Agent 3 · Cortex Search 1)  → Snowflake Intelligence
보조: ML(예측 결과) · MSTR(MSTR 이관 리포트) · OPS(dbt 프로젝트·감사·알림) · SECURITY(태그·정책)
```

## 3. 개발 · 검증 · 운영 구분

GN_DW 는 **계정을 나눠** 개발과 운영을 구분하고, 같은 계정 안에서는 **dbt target 과 사본 스키마**로 시험한다.

| 구분 | 실체 | 쓰는 곳 | 근거 |
|---|---|---|---|
| 운영(Production) | 계정 ZL50263 · DB `GN_DW` 주 스키마 16 | 현업 Snowflake Intelligence · 정기 Task | A0 §1·§3 · `_ENV/운영계_반영_체크리스트.md` |
| 개발·재구축 검증 | 개발 계정(85번 `_archive/` 캡처) · 재구축 계정 UM80684 | 배포 SQL 사전 검증 · 문서실행순서 재현 | `_라이브대조.md` |
| 계정 내 시험 | dbt target `dev2` → `BRONZE_CRM_2` 원천 · `_2` 사본 스키마 | 모델 변경 시험(운영 스키마 미영향) | A4 §1 · ZL 의 `*_2`·`*_OLD` 백업 사본 6 |
| dbt target | `dev`(기본 · SILVER/GOLD) · `dev2`(시험) · `prod` | `10_dbt_pipeline/profiles.yml` | A4 §1 |

- 배포 순서 정본 = `80/01_실행순서_배포SQL/문서실행순서.md`(신규 구축 1~51 · 기존 환경 갱신 목록). 운영 반영 = `85:D14` §2.

## 4. Warehouse

| WH | 용도(COMMENT) | 운영계 `[ENV]` ZL50263: 크기 · auto_suspend · auto_resume | UM80684 라이브 | 사용 롤 |
|---|---|---|---|---|
| GN_DW_ETL_WH | ETL · 적재 · 프로시저 · 태스크 · dbt | X-Small · 60s · 켜짐 | Small · 60s · true | ADMIN · ENGINEER · LOADER · DBT |
| GN_DW_DEV_WH | 개발 · 테스트 | X-Small · 60s | X-Small · 60s · true | ADMIN · ENGINEER |
| GN_DW_ANALYTICS_WH | 분석 · SV/Agent 소비 · Cortex Search | X-Small · 60s | **Medium** · **300s** · true | ADMIN · ANALYST · VIEWER · SERVICE |
| GN_DW_ML_WH | ML 학습·예측 프로시저(실행 중 크기 조정) | Large · 60s | Small · 60s · true | LOADER(USAGE+OPERATE+MODIFY) |
| COMPUTE_WH · SYSTEM$STREAMLIT_NOTEBOOK_WH | 계정 기본 · 시스템 | X-Small · 300s / X-Small(max 10) · 60s | 같음 | — |

- 공통: 전부 Gen2(STANDARD_GEN_2) · 단일 클러스터(min=max=1) · 리소스 모니터 0(ZL50263) · auto_resume 켜짐.
- 소유: ZL50263 = ACCOUNTADMIN · UM80684 = SYSADMIN(계정 차이 · `_라이브대조.md` §3-2).
- 크기·중지 설정 변경 절차 = `85:D11` §3·§4 · 비용 영향 = `85:N06` §2-2.

## 5. 인수자 확인 절차 (현업 확인 기준: 「내부 계정으로 접속하고 대상 환경과 Warehouse 를 식별 · 문서와 일치 확인」)

1. 내부 운영 계정 사용자로 Snowsight 로그인 → 계정 로케이터·리전이 §2 운영계 열과 같은지 확인.
2. 아래 SQL 을 실행하고 결과를 §4 운영계 열과 대조한다(차이는 `특이사항`에 기록).

```sql
SELECT CURRENT_ACCOUNT(), CURRENT_REGION(), CURRENT_ORGANIZATION_NAME();
SHOW WAREHOUSES LIKE 'GN_DW%';          -- size · auto_suspend · auto_resume · owner
SHOW SCHEMAS IN DATABASE GN_DW;          -- 주 스키마 16 + 백업 사본(R02 §4)
```
3. 문서와 다르면 문서가 아니라 **계정 캡처**를 갱신한다: `python3 scripts/env_capture.py --id A0 "85_실제 인수인계 문서/10_실무자_인수인계/A0_환경실사_baseline.sql"`.
