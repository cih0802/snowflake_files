# 현업요청 인수인계목록 대응 작업계획서

## 0. 이력
1. 80번 폴더 = 전달용 원본, 85번 폴더 = 인수인계용 문서(A0~A8, D01~D14, N01~N08) 작성 완료.
2. 현업이 인수인계목록(xlsx, 자료 ID D01~D12)을 요청.
3. 목록을 `98_현업요청인수인계/현업요청인수인계목록.md` 로 정리.
4. **(현재)** 목록 §3(항목별 상세)에 맞게 기존 문서를 매핑하고, 빠진 부분은 현재 구성을 근거로 새로 작성.

## 1. 범위와 결정 사항 (2026-10-25 사용자 확정)
- 대상: 목록 §3 의 **D01, D02, D04~D11**. 
- 제외: §1·§2·§4·§5 표(사용자 작성) · **D03 외부 데이터 연동(다른 담당자)** · **D12 교육·지원의 일정·지원기간(사용자 작성)**. D12 는 기존 문서 매핑만 한다.
- ID 충돌 주의: 현업 자료 ID `D01~D12` ≠ 85번 정식산출물 `D01~D14`. 이 폴더의 문서는 **`R<현업ID>`** 로 부르고, 85번 문서는 `85:D04` 처럼 접두를 붙여 적는다.
- 기준 계정: `[공통]` 값(GN_DW 객체·구조) = 현재 세션 계정에서 라이브로 다시 확인한다. `[ENV]` 값(사용자·롤 할당·WH·모니터·Task 상태 등) = `85_실제 인수인계 문서/_ENV/ZL50263/` 캡처를 그대로 인용한다.
- 원본 보존: 80번·85번 기존 파일은 수정하지 않는다. 예외 = `현업요청인수인계목록.md` §3 의 「실제 파일명 및 버전」「저장위치 및 해당 장·절」 칸.
- 읽기 전용: DDL/DML/GRANT 는 실행하지 않는다. 근거 SQL 은 SELECT/SHOW/DESCRIBE 만 쓴다.
