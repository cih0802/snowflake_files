# 90. 운영계 점검·기록 실행 가이드

## 0. 추천 방식과 이유

**「SQL 파일 → env_capture → 운영계 csv 증거 → 스크립트 점검 → 사람 판정 · 기록」** 방식을 쓴다. 🔴 **다른 계정(개발계 등) 결과와 비교하지 않는다** — 판정 기준은 운영계 결과 안에서 닫힌다(§3).

| 원칙 | 이유 |
|---|---|
| 손으로 결과를 옮겨 적지 않는다 | `env_capture.py` 가 결과를 `_ENV/ZL50263/<ID>_<Qnn>_<k>.csv` 로 남긴다. 실행 시각·계정이 각 파일 첫 줄에 찍혀 그대로 감사 증거가 된다 |
| 운영계 안에서 판정한다 | 기준은 계정 밖 값이 아니라 운영계 자체의 정합성이다: 「원천↔목적지 차이 0 또는 사유 확인」「Task·Alert 정상」「NULL·중복 0」「객체 존재」 |
| 값은 기록한다 | 에디션·보존기간·버전·Agent 정답지처럼 기준이 없는 값은 판정하지 않고 §4 에 그대로 적어 R 문서에 반영한다 |
| 읽기 전용 | `env_capture` 는 SELECT/SHOW/DESC 가 아닌 문장이 있으면 **실행 전에** 멈춘다 |
| 사람은 🔴 만 본다 | `r_env_check.py` 가 자동으로 🟢/🟠/🔴 를 매기므로 사람은 🔴 원인과 값 기록 항목만 판정표(§4)에 적는다 |

## 2. 실행 (복사해서 순서대로)

워크스페이스 터미널(또는 CoCo)에서 워크스페이스 루트 기준:

```bash
# ① 구조 · 객체 (R00 · 1~2분)
python3 scripts/env_capture.py --id R00 "85_실제 인수인계 문서/30_현업요청대응/_근거쿼리/R00_라이브대조.sql"
# ② 복구 수단 (R09 · 수 초)
python3 scripts/env_capture.py --id R09 "85_실제 인수인계 문서/30_현업요청대응/_근거쿼리/R09_복구수단_근거.sql"
# ③ TBD 해소 (R90 · 수 초)
python3 scripts/env_capture.py --id R90 "85_실제 인수인계 문서/30_현업요청대응/_근거쿼리/R90_운영계_추가확인.sql"
# ④ Agent 기대값 (R06 · 1분 내외)
python3 scripts/env_capture.py --id R06 "85_실제 인수인계 문서/30_현업요청대응/_근거쿼리/R06_Agent검증_기대값.sql"
# ⑤ 원천↔목적지 대사 (R10 · 수 분 · build 직후)
python3 scripts/env_capture.py --id R10 "85_실제 인수인계 문서/30_현업요청대응/_근거쿼리/R10_데이터검증_근거.sql"
# ⑥ 자동 점검 → 91_운영계_점검결과.md (운영계 결과만 사용)
python3 "85_실제 인수인계 문서/30_현업요청대응/_도구/r_env_check.py" --account ZL50263
```

- 각 줄 끝의 `🟢/🔴 … OK n · ERROR m` 을 확인한다. ERROR 가 있으면 `_ENV/ZL50263/<ID>_manifest.csv` 의 NOTE 열에 오류 메시지가 있다.
- 선택(권장): 사용자·롤·실행 이력 최신화 = `--id A1 …/10_실무자_인수인계/A1_운영자가이드_근거.sql` · `--id A6 …/A6_일배치_장애대응_런북.sql`(기존 85 근거 SQL · 덮어쓰기).

### 2-1. 터미널을 쓸 수 없을 때 (워크시트 수동 방식)
1. 각 SQL 파일을 워크시트에 열고 `-- Qnn` 블록 단위로 실행한다.
2. 결과를 csv 로 내려받아 `85_실제 인수인계 문서/_ENV/ZL50263/<ID>_<Qnn>_<k>.csv` 이름으로 올린다(k = 블록 안 문장 순번 · 보통 1 · R90 Q07 은 1~3).
3. 이 방식은 manifest 가 없어 ⑥ 스크립트가 돌지 않는다 ⇒ §3 표의 기준으로 직접 판정해 §4 에 기록한다.
