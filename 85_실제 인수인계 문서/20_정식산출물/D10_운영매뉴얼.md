## 1. [공통] 운영 체계

| 작업 | 실행 롤 | 비고 |
|---|---|---|
| dbt build · retry · 백필 | `GN_DW_DBT` | 🔴 dbt 를 다른 롤로 돌리면 뷰 소유가 섞여 다음 build 가 실패한다(A6 F9) |
| dbt 재배포 · SV 재배포 · Agent 버전업 · MSTR 적재 · Alert 관리 · 마스킹 정책 | `GN_DW_ADMIN` | 객체 소유 롤 |
| 원천 적재 · 월마감 SP | `GN_DW_LOADER`(외부팀) | 월마감 SP 와 dbt build 를 동시에 돌리지 않는다 |
| 계정 권한(`EXECUTE ALERT`·`EXECUTE TASK`·`APPLY MASKING POLICY`) · 알림 통합 | `ACCOUNTADMIN` | 1회성 |

- 🔴 RUNBOOK(2026-07-22)은 dbt 실행 롤을 `GN_DW_ENGINEER` 로 적었다. 현행은 `GN_DW_DBT` 다(DR-19 · `profiles.yml`).
- dbt 명령은 사람이 실행한다. 에이전트(CoCo)에게 맡기지 않는다(작업 지침 `R4-1`).

## 3. [공통] 일상 운영

1. **아침** — 원천 신선도(A6 Q09) → dbt build 결과(A6 Q01 · ERROR 0 · SKIP 0) → 실패 저장 테이블(A6 Q03 · 0행). 목표 시각은 N04 §3.
2. **주간** — A7 주간 항목(크레딧 추세 · 실패 Task · 권한 변경 감사).
3. **월간** — A7 월간 항목 + 월마감 SP 실행 일정 확인(dbt build 와 겹치지 않게).
4. 🔴 **SKIP 은 무해하지 않다** — 상류 1건 실패가 모델 9개와 테스트 59개를 건너뛰게 만든 이력이 있다(RUNBOOK :775).

## 4. [공통] 장애 대응

증상별 처치는 A6 §3 의 F1~F9 를 따른다. 공통 원칙만 적는다.

1. **증거 먼저** — `python3 scripts/env_capture.py --id A6 <A6 SQL>` 로 상태를 남긴 뒤 손댄다.
2. **멱등 경로만** — SILVER·GOLD 는 build 재실행이 안전하다 · MSTR 는 해당 월만 다시 부른다 · `--full-refresh` 는 쓰지 않는다.
3. **Agent 이상** — 직전 버전으로 되돌린다: `ALTER AGENT GN_DW.SERVING.<AGENT> SET DEFAULT_VERSION = 'VERSION$<n>';`
4. 처치 후 A6 Q03(0행) · Q04(일자 수 일치)를 다시 본다.

## 6. [공통] 보안 · 권한 점검

- 🔴 롤별 권한을 점검할 때는 `USE SECONDARY ROLES NONE` 을 먼저 실행한다. 안 하면 보유 롤 전부의 권한이 합쳐져 차단돼야 할 것이 통과한다(RUNBOOK §6.2 · 실제 오탐).
- 로그인 실패 · GRANT/REVOKE 감사 · 대량 추출 쿼리는 RUNBOOK §8.2~§8.4 쿼리를 그대로 쓴다.
- BRONZE 개인정보(이름·휴대폰·연락처 12 컬럼)는 마스킹 적용 후 GN_DW_ADMIN 이상만 원문으로 본다. 적용 전에는 ANALYST·ENGINEER·DBT 가 원문을 볼 수 있다(N02 §2-B).
- Agent 답변 품질 점검(NL 스모크)은 Agent 버전업·SV 문안 변경 때 `60_repeat_어카운트시작/10_NL스모크_재실행_절차.md` 로 한다(CoWork 화면 · 사람만).
