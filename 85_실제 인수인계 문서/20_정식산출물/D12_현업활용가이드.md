# D12. 현업 활용 가이드

CRM·마케팅·재무 담당자가 GN_DW 로 **어떤 질문에 답할 수 있는지**와 **그 숫자를 믿어도 되는지**를 정리했다.
지표 하나하나의 정의는 D01, 컬럼 출처는 N03(통합 데이터 사전)에 있다.

## 1. [ENV] 지금 쓸 수 있는 것

| 수단 | 운영계(ZL50263) | 누가 쓰나 | 근거 |
|---|---|---|---|
| Cortex Agent(자연어 질의 · CoWork 화면) | **3** (계정 내 전체 6 — MSTR·OVERALL·ASDF 포함) | 현업 전원(VIEWER·ANALYST·SERVICE) | D12 Q05 · D09 |
| Semantic View(SV) | **45** (실적 28 · ML 예측 16 · MSTR 1) | 분석가(ANALYST) · Agent 가 내부에서 사용 | D12 Q05 · D08 |
| Streamlit 앱 | **9** (LAB 스키마) | 분석가·업무담당자 | D12 Q05 · D10 Q07 |

| Agent | 이럴 때 묻는다 |
|---|---|
| `AGENT_MEMBER` | 회원 월실적 · 상태 변화 · 발송 · 행사 참여 · 결연 활동 · 획득 코호트 · 개발 목표 달성 · 회비 분해 · 이탈 위험 예측 |
| `AGENT_MARKETING` | 사업 목표 · 광고 효율 · 개발 목표 달성 · 예산 집행 · 전환 회원 · 캠페인 회비 · 웹 행동(GA) |
| `AGENT_EXECUTIVE` | 전사 요약 · 경영/재무 · 사업 목표 · 예산 편성/집행 · 광고 실적 · AI 미래 예측 |

- Agent 이름과 담당 범위는 Agent 설명문(COMMENT) 기준이다. 실제로 연결된 SV 는 D09 표가 정본이다(설명문의 「소관 SV 수」는 낡았다 · DR-03).
- 🔴 ML 예측 SV(`SV_ML_*`)의 값은 **추정치**다. Agent 답변에 「추정」 표기가 붙는다. 실적과 한 표에서 더하지 않는다.

## 2. [공통] 업무 질문 → 어디서 보나

| 납입방식·후원사업·회비구분별 회비 | `SV_MEMBER_FEE`(MEMBER) | 🔴 월 회비 표와 **한 표에 섞지 않는다**(§3 #6) |

| 광고비·개발단가(마케팅캠페인별) | `SV_AD`(MARKETING·EXECUTIVE) | 개발캠페인 단위로 내리면 광고비가 복제된다 |
| 예산 편성·집행 | `SV_BUDGET` · `SV_BUDGET_YEARLY`(MARKETING·EXECUTIVE) | 🔴 2024년은 편성 0 · 집행율 128.74% 가 나온다(§4 · DR-29) |
| 웹/앱 방문·세션(GA) | `SV_GA_*`(MARKETING) | 운영계 적재 범위를 먼저 확인한다(DR-14) |
| 이탈 위험 · 회비 · 개발 예측 | `SV_ML_*`(MEMBER·EXECUTIVE) | 추정치 |
| MSTR 기준 후원 개발 | `SV_MSTR_SPNSR_DVLP` | 🔴 GN_DW 실적과 한 표에서 합산하지 않는다 |

## 3. 조용히 틀리는 지표 6종 (재측정)

에러 없이 그럴싸한 값이 나오는 지표다. 종전 가이드(2026-08-11)의 규칙은 그대로 맞고, 수치를 계정 실측값으로 제시한다.

**운영계 (ZL50263 · 2026-10-27 캡처)**
| # | 질문 | 틀린 방법 → 값 | 맞는 방법 → 값 | 근거 |
|---|---|---|---|---|
| 1 | 개발(명) | `SUM(DEV_MEMBERS)` → 사건 팩트 1,992,068 · 월 팩트 1,888,929 | 고유 회원 `COUNT(DISTINCT 회원)` → **1,584,428** | Q01 — 사건 팩트 25.7% · 월 팩트 19.2% 과대 |
| 2 | 발송 회원수 | 발송 행 수 → 44,646,949 | 고유 회원 → **1,067,787** | Q02 — 41.8배 차이 |
| 3 | 납부율 | 총수납액(기부금 포함) ÷ 회비 청구 | 회비 납입 ÷ 회비 청구 → **84.77%** | Q03 (815,480,150,782 ÷ 961,981,566,649) |
| 4 | 총미납금액 | 청구 − 납입(기부금이 상쇄) | 실패·미결 **청구액 합** → **145,928,980,451원** | Q03 |
| 5 | 목표 달성률 | 실적 ÷ 목표 직접 나눗셈 | SV 지표 `ACHIEVEMENT_RATE`(목표 편성분만) | 종전 가이드 §0 #5 |
| 6 | 회비를 후원사업별로 보면서 월 합계도 | 월 팩트 × 회비 상세 팩트 조인 | **표를 나눠 따로 조회** — 따로 세면 청구 총계 961,981,566,649원으로 같다 | Q04 (월팩트 42,983,646행 · 회비상세 43,389,462행) |

- 🔴 **#1 「개발(건)」 `DEV_CNT` 의 뜻이 바뀌었다** — 종전 「사건 건수」에서 「인정금액 ÷ 10,000」(MSTR 기준)으로 바뀌었다(DR-28). 합계가 소수(4,059,502.2214)인 이유다. 「몇 건」을 물을 때는 Agent 에 「건수」라고 명시한다.
- 🔴 `0` 을 실적으로 읽지 않는다 — GOLD 에는 자리만 있고 값이 아직 없는 컬럼이 있다(활동회원 수 · 발송 성공/실패/오픈 · 연 편성예산 등 · 종전 가이드 §2-2). 목록은 N03 에서 `WAIT` 로 표시된다.

## 5. [공통] 질문 요령

1. **기간을 넣는다** — 「2026년 7월」 「최근 12개월」. 기간이 없으면 전 기간 합계가 나온다(납부율 왜곡).
2. **「건」과 「명」을 구분해 묻는다** — 「발송 건수」 「발송받은 회원 수」.
3. **축을 하나씩** — 회비를 후원사업별로 볼 때는 회비 상세만, 월 추이는 월 팩트만.
4. **추정치는 추정치로** — 예측 답변의 「추정」 표기를 지우지 않고 보고서에 옮긴다.
5. 답이 이상하면 질문·시각·Agent 이름을 DW 관리자에게 보낸다(D10 §7 L1).
