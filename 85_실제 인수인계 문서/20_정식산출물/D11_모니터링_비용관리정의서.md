# D11. 모니터링 · 비용관리 정의서

비용 수치·월 추정은 N06 이 정본이다. 이 문서는 **무엇을 어떤 수단으로 감시·통제하는지**를 정한다.

## 1. [공통] 감시 대상과 수단

| 대상 | 수단 | 차단 가능 | 지연 | 정본 쿼리 |
|---|---|---|---|---|
| 웨어하우스 크레딧 | Resource Monitor | ⭕ SUSPEND(사용자 구분 없음) | — | N06 Q03 · `06_…` §11 |
| 개별 쿼리 시간 | `STATEMENT_TIMEOUT_IN_SECONDS`(WH 레벨) | ⭕ 쿼리 취소 | — | `06_…` §3 |
| AI(CoCo · CoWork · Agent · AI 함수) | Per-user quota(Preview-Open) | ⭕ 사용자별 내장 Block | 차단 수 분 · 알림 약 6시간 | `05_…` §9 |
| Cortex Analyst | 관찰만(quota 도메인 아님 — `Operation not supported`) | ❌ ⇒ RBAC 로 | — | `05_…` §3 |
| 팀 합산 예산 | Budget + custom action | ⚠️ 프로시저 자작 | 최대 8시간 | `03_…` §2 |
| 접근 자체 | RBAC(`SNOWFLAKE.CORTEX_USER`) | ⭕ | — | `05_…` §10 |
| 파이프라인 실패 · 데이터 품질 | dbt 실패 저장 테이블 + Alert + 메일 | — | Alert 주기 | A6 Q03·Q05 · `09_…` |

- 🔴 Resource Monitor 는 서버리스·AI 를 막지 못한다. AI 하드 차단은 per-user quota 의 Block 뿐이다(`01_…` §3).
- 🔴 AI 사용량은 **도메인마다 정본 뷰 1개만** 쓴다. CoCo 는 `SNOWFLAKE_COCO_USAGE_HISTORY` — 인터페이스별 `CORTEX_CODE_*` 뷰와 더하면 2배가 된다(`02_…` §3).

## 3. [공통] 비용 가드 스크립트 — 배포 전 주의

| 스크립트 | 만드는 것 | 🔴 실행 전 고칠 것 |
|---|---|---|
| `05_AI비용가드_구축.sql` | 태그 `SECURITY.AI_COST_SCOPE` · quota `OPS.AI_USER_QUOTA`(AI 4도메인) · 관찰 뷰 `OPS.V_AI_SPEND_BY_USER` | ① :151 `SET_PER_USER_LIMIT(30)` · :162 `(5,'DAILY')` · :184 `SET_BLOCK_ENFORCEMENT_ENABLED(TRUE)` 가 **주석이 아니다** — 주석(:132 「현재 미적용」·:171 「현재 비활성」)과 반대로, 파일을 통째로 돌리면 월 30·일 5 크레딧 차단이 켜진다(DR-32). 실측 사용량(1인 하루 5~6 · 월 150~180 · :144~145)보다 낮아 **월중 차단**된다 ② :65 `ALTER USER choih` = 다른 계정 사용자 ③ :81 `CREATE … QUOTA` 는 `IF NOT EXISTS` 미지원 — 재실행 시 실패 |
| `06_웨어하우스비용가드_구축.sql` | RM `ML_WH_MONITOR`(월 100) · WH `ML_WH`(Large) · quota `OPS.ML_WH_USER_QUOTA` · 프로시저·감사 로그·관찰 뷰 | ① 대상 WH `ML_WH`(Large)는 이 계정에 없다 — 실재 ML WH 는 `GN_DW_ML_WH`(Small) ② :66 `NOTIFY_USERS = (TRIALADMIN)` · :24 `COMPUTE_WH` 는 계정 의존 ③ custom action 은 위반자 1명 때문에 **WH 전체를 정지**한다(:273) |

- 두 스크립트 모두 ACCOUNTADMIN 실행 · 이 계정 미배포(A8-11 「비용 가드를 언제 켤 것인가」 미결).
- 🔴 웨어하우스 quota 에 `SET_BLOCK_ENFORCEMENT_ENABLED(TRUE)` 를 호출해도 오류 없이 "enabled" 를 돌려준다 — 웨어하우스 차단은 Resource Monitor 로만 된다(`06_…` :44~47).
- 🔴 quota 알림 임계값은 한도의 % 다. 한도가 NULL 이면 알림을 등록해도 영원히 울리지 않는다(`05_…` :194~197).

## 4. [공통] 권장 운영 단계 (🟡 제안 — A8-11 결정 전)

1. **관찰(즉시)** — N06 Q01~Q05 를 주 1회 캡처(A7 주간). 가드 객체 없이 가능하다.
2. **경고(운영 4주 후)** — Resource Monitor 를 NOTIFY 만으로 붙인다(50·80%) · 한도는 4주 실측 × 1.5 를 출발점으로 둔다.
3. **차단(합의 후)** — `05_…` 를 §3 수정 후 실행 · 한도는 1인 실측(월 150~180)보다 높게 · `GET_USERS()` 로 관리자 제외 확인 후 Block 활성.
- `50_handoff/예산 안.md` 의 WH 4종(`WH_PIPELINE_LIGHT` 등)·월 1,000 크레딧은 **일반 예시**다 — GN_DW WH 이름과 다르고 실측 근거가 없다. 비율(파이프라인 50~60% · 분석 25~30% · AI 15~20%)도 GN_DW 실측(N06 §2 · AI 85.7%)과 맞지 않는다.
