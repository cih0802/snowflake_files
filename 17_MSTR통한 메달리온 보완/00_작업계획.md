# 00. MSTR 통한 메달리온 보완 — 작업계획 (A안 · B안 확장 전제)

## 0. 계기 · 목표

- 계기 = 같은 질문(2026-07 매체운영팀 회원개발)에 두 기준의 답이 크게 달랐다.
  - 메달리온 답 = 60명 / 72건(「사단법인 캠페인 기준」 · 재현 쿼리 미확인).
  - MSTR 답 = 5,989명 / 11,956.21건 / 119,562,055원(`F_MM_SPNSR_DVLP_SUM` 재현 일치).
  - GOLD `FACT_MEMBER_EVENT` 를 `ORG_SK`(매체운영팀) + 개발구분 1·2·4 로 집계 = 6,448명 / 7,383건 / 128,694,055원.
- 원인(O202 실측) = 정의 축 3개가 어긋난다.
  - ㉠ 법인 = MSTR `CPR_DIV_CD`(사단·사복) ↔ GOLD `DIM_ORG.CORP` NULL.
  - ㉡ 팀 귀속 = MSTR 실적부서(`ACMSLT_DEPT_CD`) ↔ 답변 경로는 캠페인 축으로 우회.
  - ㉢ 개발(건) = MSTR `SPNSR_AMT_CNT`(금액 가중 · 소수) ↔ GOLD `DEV_CNT`(개발구분 필터와 무관하게 7,383 — 정의 확인 필요).
- 목표(A안) = **GOLD 구조를 유지한 채** MSTR 업무 규칙과 정의가 어긋나는 지점을 찾아 맞춘다.
- 비목표 = MSTR 객체 전량 이관(C안) · GOLD 에 없는 영역 신설(B안 — 이 계획은 B 착수에 필요한 그릇만 만든다).

## 2. A/B 경계 — B안을 위해 지금 정해 두는 것

- 🟢 **매핑표 1장을 A·B 공용으로 쓴다**(`02_MSTR_GOLD_매핑표.md`).
  - 행 = MSTR 객체(SP 기준 · 대상 테이블 포함) · 열 = 대응 GOLD 객체 · 판정 · 근거 좌표 · 처리안(A/B/제외).
  - 판정 코드 = `일치` · `정의차`(A 대상) · `GOLD미보유`(B 대상) · `MSTR전용`(제외 · 운영 보조) · `변형본`(제외).
- 🟢 A안은 `정의차` 만 처리한다 ⇒ `GOLD미보유` 행이 그대로 **B안 백로그**가 된다.
- 🟢 인벤토리는 도구로 재생성한다(`tools/sp_inventory.py` → `01_MSTR_SP_인벤토리.md`) — B 에서 재사용.
- 🟢 규칙 추출 결과는 **「규칙 카드」** 형식으로 남긴다(`03_규칙카드/`): 규칙 · 원본 좌표 · GOLD 현행 · 차이 · 처방.
  - B 에서 새 팩트를 설계할 때 같은 카드를 설계 입력으로 쓴다.
- 🔴 변형본(`_202004` · `_210429` · `_TEST` · `_INIT_UP0n`)은 정본 SP 와 대조만 하고 별도 행을 만들지 않는다.
