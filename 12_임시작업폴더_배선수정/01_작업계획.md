**판정 및 처분(사용자 결정):**
* 스냅샷 11종은 **껍데기로 유지**한다(삭제하지 않는다 — 지우면 그 시점부터 이력이 다시 0 이 되고 재구축 불가).
* dbt 소비처는 **전부 0 으로 되돌린다**. 배선은 **허가가 떨어진 뒤에** 추가한다.
* 근거 = **선(先)이력 · 후(後)배선**. 이력은 시간이 만들고 배선은 나중에 공짜로 붙는다.
  이력 없는 배선은 실효가 0 이며(실측 ③), 동시에 **거짓 보장을 표명해 더 위험하다**(§1-3).

### 1-3. 왜 컬럼까지 제거하는가 — AI 가 거짓 보장을 학습한다

두 컬럼의 **라이브 COMMENT** 가 이렇게 표명하고 있다:

* `ACQ_CAMPAIGN_NAME_AT_ACQ` = `'회원 획득 당시 캠페인명 (Snapshot 기반 시점 동결).'`
* `ACQ_DEPARTMENT_AT_ACQ` = `'회원 획득 당시 부서명 (Snapshot 기반 시점 동결).'`

실제로는 현재명과 100% 동일한데 「시점 동결」을 **표명**한다. 이 COMMENT 는 Cortex Analyst·Agent 의
컨텍스트로 들어가므로 **AI 가 시점 정합이 보장된다고 답한다.** O155 가 `rename_stale_gate` 를
신설한 사유(SV COMMENT 가 라이브에 없는 이름을 가리켰고 드리프트 게이트는 0 을 냈다)와 **동일 축**이다.

⇒ 컬럼을 남기고 COMMENT 만 고치는 것보다 **제거가 안전하다**.
⇒ 부수 효과: `ACQ_DEPARTMENT_AT_ACQ`(부서 동결)는 **승인 근거가 문서에 없다**
   (현업 승인 요건 `N-9` 는 **캠페인명만** 승인했다) ⇒ 이 초과분도 함께 정리된다.

## §3. 작업 B — 게이트 방향 반전 (필수 · 빠뜨리면 FAIL 한다)

### 3-1. 왜 필수인가

`scripts/rename_stale_gate.py:56` 이 현재 이렇게 등재돼 있다:

```python
'FACT_MEMBER_EVENT': 'FACT_MEMBER_LIFECYCLE',
```

즉 이 게이트는 **`FACT_MEMBER_EVENT` 를 「옛 이름 위반」으로 잡는다**.
원복하면 복원된 이름 전건이 축1 위반으로 계상되어 기준선(축1 **536건 / 115파일**) 대비
**증가 ⇒ exit 1 FAIL** 한다.

### 3-2. 처방 = 항목 반전 (제거가 아니다)

```python
'FACT_MEMBER_LIFECYCLE': 'FACT_MEMBER_EVENT',
```

* 🟢 **반전을 택하는 이유**: 이제 `FACT_MEMBER_LIFECYCLE` 이 옛 이름이 되므로
  **원복 누락을 게이트가 blocking 으로 잡는다**. 항목을 **제거**하면 잔존 표기를 아무도 감시하지 않는다.
